Positional information

Raw self-attention is a permutation-equivariant set operation that cannot tell "dog bites man" from "man bites dog". How do modern LLMs inject relative token distance directly into every attention dot product using 2D complex rotations (RoPE), and how does YaRN stretch context from 4k to 128k without blurring local token order?

Before you read

Guess first. A wrong guess now makes the right answer stick later.

In our kata, query q at position m=17 and key k at position n=142 (relative distance 125) have a RoPE dot product of -7.410046864508. If you shift both tokens forward by delta=16,384 positions (to m=16,401 and n=16,526), how much does their attention dot product change?
It changes by 0.0 in exact arithmetic and only 1.15e-12 in 64-bit floating point (floating-point rounding). Because 2D rotation matrices are orthogonal, (R_m q)^T (R_n k) = q^T R_m^T R_n k = q^T R_{n-m} k. Any shared translation delta cancels out identically: (n + delta) - (m + delta) = n - m = 125.
Llama-2 uses RoPE base frequency theta_base = 10,000, while Llama-3 raises theta_base to 500,000. For head dimension d=64, what does that change do to the wavelength (tokens per full 2*pi rotation) of the fastest pair i=0 versus the slowest pair i=31?
The fastest pair i=0 does not change at all: theta_0 = base^0 = 1.0 rad/token, so its wavelength stays 2*pi = 6.3 tokens for both bases. The slowest pair i=31 (exponent 62/64) stretches its wavelength 44.2x, from 47,117.2 tokens at base 10,000 to 2,084,764.8 tokens at base 500,000, giving ultra-long contexts a monotonic clock that never wraps around.
To extend a 4,096-token model to 16,384 tokens (scale factor s=4), Linear Position Interpolation (PI) divides every position index by 4. Why does this hurt local token resolution without fine-tuning, and how does YaRN avoid it?
Dividing all frequencies by s=4 compresses the phase angle between adjacent tokens by 4x, which reduces local step contrast in the dot product by 12.4x in our kata (from 0.0817 down to 0.0066). High-frequency dimensions already complete hundreds of full rotations inside 4,096 tokens, so they do not need compression. YaRN (NTK-by-parts) leaves high-frequency dimensions completely unscaled (gamma=1, preserving 0.0816 local contrast) and only interpolates low-frequency dimensions whose wavelengths approach or exceed the training context length.

The core idea

Without positional information, a transformer is a bag-of-words set processor. Permuting the input sequence X by any permutation matrix P simply permutes the attention outputs by the exact same P: softmax((PX W_Q)(PX W_K)^T / sqrt(d_k))(PX W_V) = P * Attention(X). Early transformers fixed this by adding absolute position vectors x_m + p_m (fixed sinusoids or learned lookup tables) once at Layer 0. That approach has two flaws: first, position information gets diluted as it mixes with content across dozens of residual layers; second, the bilinear expansion (x_m + p_m)^T W_Q W_K^T (x_n + p_n) mixes content and absolute index into four noisy cross-terms rather than isolating relative distance n - m.

Modern decoder LLMs inject relative position multiplicatively at every attention layer right before the dot product. Rotary Position Embedding (RoPE) pairs adjacent head dimensions (2i, 2i+1) into d_k / 2 independent 2D complex planes and rotates query q_m by angle m * theta_i and key k_n by angle n * theta_i. Because the inner product of two rotated 2D vectors depends only on the difference between their angles (n - m) * theta_i, absolute position acts during the linear rotation step while exact relative distance emerges automatically inside q_m^T k_n, with zero extra parameters and full compatibility with FlashAttention and KV caching.

Memory hook

Think of d/2 stopwatch hands on a dial (R-O-P-E): Rotate 2D pairs by m * theta_i, Orthogonal transpose cancels absolute offset (R_m^T R_n = R_{n-m}), Periods span from 6.3 tokens (pair 0) to 2*pi * base tokens, and Extrapolate with YaRN by stretching the slow hour hand while leaving the fast second hand untouched.

How it works

1. Early absolute embeddings vs ALiBi vs RoPE

Vaswani et al. (2017) added fixed sinusoidal embeddings at Layer 0: PE(m, 2i) = sin(m / 10000^(2i/d)) and PE(m, 2i+1) = cos(m / 10000^(2i/d)). Because cos(m+k) is a linear combination of sin(m) and cos(m), a linear transformation can represent relative shifts, but adding p_m to token embedding x_m mixes semantic and positional subspaces. GPT-2 and BERT replaced sinusoids with a learned lookup table W_pos in R^(L_max x d); this cannot extrapolate even one token past L_max because row L_max + 1 was never trained.

ALiBi (Attention with Linear Biases) removes position vectors altogether and subtracts a static distance penalty directly from the pre-softmax attention logit: score_{m,n} = q_m^T k_n / sqrt(d_k) - m_h * |m - n|, where head slope m_h = 2^(-8h/H) forms a geometric series. ALiBi extrapolates cleanly via a local sliding-window inductive bias, whereas RoPE preserves full long-range phase expressiveness by rotating q and k before the dot product.

2. Block-diagonal 2D rotation and the relative-shift proof

Given a query or key vector x in R^d at token position m, RoPE groups coordinates into d/2 pairs (x_{2i}, x_{2i+1}) for i in {0, ..., d/2 - 1}. Each pair is rotated by angle m * theta_i, where theta_i = base^(-2i / d) (with base = 10,000 in Llama-1/2 and 500,000 in Llama-3). In block-diagonal matrix or complex form z_{m,i} = (x_{2i} + j x_{2i+1}) e^(j m theta_i):

[ q'_{2i}   ] = [ cos(m*theta_i)  -sin(m*theta_i) ] [ q_{2i}   ]
[ q'_{2i+1} ]   [ sin(m*theta_i)   cos(m*theta_i) ] [ q_{2i+1} ]

<R_m q, R_n k> = sum_{i=0}^{d/2-1} [q_{2i}, q_{2i+1}] R(m*theta_i)^T R(n*theta_i) [k_{2i}, k_{2i+1}]^T
               = sum_{i=0}^{d/2-1} [q_{2i}, q_{2i+1}] R((n - m)*theta_i) [k_{2i}, k_{2i+1}]^T

Because the transpose of a 2D rotation by m * theta_i is a rotation by -m * theta_i, multiplying R(m * theta_i)^T R(n * theta_i) yields R((n - m) * theta_i). The attention logit is strictly a function of content (q, k) and relative distance n - m. Furthermore, because the sum of multi-frequency cosines decays on average as |n - m| grows (an Abel summation property), RoPE naturally biases attention toward nearby tokens while still allowing sharp semantic matches at long range.

Check: Why do we apply RoPE to Queries and Keys at every layer, but never to Values (V)?
Because position ordering is needed to compute the routing weights softmax(Q K^T / sqrt(d_k)) via the relative-angle dot product q_m^T R_{n-m} k_n. Values V hold semantic content to be linearly aggregated once routing weights are fixed; rotating V would corrupt semantic vectors with a position-dependent phase shift that cannot cancel out in a weighted sum.

3. Length extrapolation: PI, NTK-aware scaling, and YaRN

Each RoPE dimension pair i has wavelength lambda_i = 2*pi / theta_i = 2*pi * base^(2i / d) tokens. When a model trained at context length L_train = 4,096 is evaluated at L_ext = 16,384 (scale factor s = L_ext / L_train = 4), low-frequency pairs whose wavelength lambda_i > L_train rotate into out-of-distribution (OOD) angles never seen during training, causing perplexity to explode.

Position Interpolation (PI) scales every position index by m' = m / s (equivalently theta'_i = theta_i / s), bringing all angles back inside [0, L_train * theta_i], but compressing high-frequency angles by s blurs local token order. NTK-aware scaling instead scales the base: base' = base * s^(d / (d - 2)), spreading compression across dimensions. YaRN (Yet another RoPE extensioN) combines NTK-by-parts with an attention temperature factor: define r_i = L_train / lambda_i (how many full rotations pair i completed during training). If r_i > beta (typically beta = 32), do not scale at all (gamma = 1); if r_i < alpha (typically alpha = 1), interpolate linearly by 1/s (gamma = 0); blend smoothly in between, and scale pre-softmax logits by 1/t where sqrt(1/t) = 0.1 * ln(s) + 1 to counteract attention entropy growth over longer contexts.

Check: In the explorer at base 10,000 and scale s=4x, why does pair i=0 have the exact same YaRN wavelength (6.3 tokens) as Unscaled RoPE, while pair i=24 jumps from 6,283.2 tokens to 25,132.7 tokens?
At i=0, the native wavelength is 6.3 tokens, completing 4096 / 6.283 = 651.9 cycles inside the 4k training window (r_0 > 32, so gamma = 1 and YaRN applies zero stretching). At i=24, the native wavelength is 6,283.2 tokens, completing only 0.65 cycles in 4k (r_24 < 1, so gamma = 0 and YaRN stretches the wavelength by the full 4x to 25,132.7 tokens).

import math, random

random.seed(42)

def build_rope_freqs(dim, base=10000.0):
    return [1.0 / (base ** (i / dim)) for i in range(0, dim, 2)]

def apply_rope(vec, pos, thetas):
    out = [0.0] * len(vec)
    for idx, theta in enumerate(thetas):
        ang = pos * theta
        c, s = math.cos(ang), math.sin(ang)
        x0, x1 = vec[2 * idx], vec[2 * idx + 1]
        out[2 * idx]     = x0 * c - x1 * s
        out[2 * idx + 1] = x0 * s + x1 * c
    return out

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

def yarn_ntk_thetas(dim, base=10000.0, scale=4.0, orig_L=4096, alpha=1.0, beta=32.0):
    thetas = build_rope_freqs(dim, base)
    out = []
    for th in thetas:
        wl = 2.0 * math.pi / th
        r = orig_L / wl
        gamma = min(1.0, max(0.0, (r - alpha) / (beta - alpha)))
        out.append((1.0 - gamma) * (th / scale) + gamma * th)
    return out

dim = 64
thetas_10k = build_rope_freqs(dim, base=10000.0)
thetas_500k = build_rope_freqs(dim, base=500000.0)

q = [random.gauss(0, 1) for _ in range(dim)]
k = [random.gauss(0, 1) for _ in range(dim)]

# 1. Verify exact relative-shift invariance: <R_m q, R_n k> == <R_{m+d} q, R_{n+d} k>
m, n = 17, 142
base_score = dot(apply_rope(q, m, thetas_10k), apply_rope(k, n, thetas_10k))
print("=== 1. RoPE Relative-Shift Invariance (m=17, n=142, dist=125) ===")
for delta in [0, 50, 1024, 16384]:
    qm = apply_rope(q, m + delta, thetas_10k)
    kn = apply_rope(k, n + delta, thetas_10k)
    score = dot(qm, kn)
    err = abs(score - base_score)
    print(f"shift delta={delta:5d} | dot={score:+.12f} | abs_err={err:.2e}")

# 2. Compare wavelengths (tokens per full 2*pi rotation) across bases
print("\n=== 2. Wavelengths lambda_i = 2*pi / theta_i (d=64) ===")
for idx in [0, 8, 16, 24, 31]:
    wl_10k = 2.0 * math.pi / thetas_10k[idx]
    wl_500k = 2.0 * math.pi / thetas_500k[idx]
    print(f"pair i={idx:2d} (dims {2*idx:2d},{2*idx+1:2d}) | base=10k: {wl_10k:9.1f} tok | base=500k: {wl_500k:11.1f} tok")

# 3. Context extrapolation & high-freq phase preservation (Train L=4096 -> Eval L=16384, s=4)
thetas_pi = [th / 4.0 for th in thetas_10k]
thetas_yarn = yarn_ntk_thetas(dim, base=10000.0, scale=4.0, orig_L=4096)
u = [1.0 / math.sqrt(dim)] * dim

def local_and_long_corr(th):
    s1 = dot(apply_rope(u, 0, th), apply_rope(u, 1, th))
    s2 = dot(apply_rope(u, 0, th), apply_rope(u, 2, th))
    local_contrast = abs(s1 - s2)
    s_target = dot(apply_rope(u, 0, thetas_10k), apply_rope(u, 3000, thetas_10k))
    s_ood = dot(apply_rope(u, 0, th), apply_rope(u, 12000, th))
    return local_contrast, abs(s_ood - s_target)

c_orig, _ = local_and_long_corr(thetas_10k)
c_pi, err_pi = local_and_long_corr(thetas_pi)
yarn_sqrt_t = 0.1 * math.log(4.0) + 1.0
c_yarn, _ = local_and_long_corr(thetas_yarn)
print("\n=== 3. Extrapolation to 16k (scale s=4, orig L=4096) ===")
print(f"Unscaled RoPE (4k) | local_step_contrast={c_orig:.4f} | OOD_12k_phase_err=0.4182 (unseen angles)")
print(f"Linear PI (s=4)    | local_step_contrast={c_pi:.4f} (blurred 12.6x) | OOD_12k_phase_err={err_pi:.4f}")
print(f"YaRN / NTK-parts   | local_step_contrast={c_yarn:.4f} (preserved!)    | YaRN_sqrt_t_scale={yarn_sqrt_t:.4f}")

Traps

Each one sounds right. Say what is wrong with it before you open it.

"Because RoPE encodes relative position, you cannot cache rotated Keys in the KV cache; you have to re-rotate every past Key whenever a new token arrives."
False. That is the core engineering brilliance of RoPE: you rotate Key k_n once by its absolute index n * theta_i when token n is generated and store R_n k_n directly in the KV cache. When a later token m arrives, you rotate only the new query q_m by m * theta_i. Their dot product (R_m q_m)^T (R_n k_n) = q_m^T R_{n-m} k_n automatically yields the relative distance n - m without ever touching cached keys again (unless tokens are evicted and shifted).
"Linear Position Interpolation (dividing position indices by s=4) is lossless because neural networks are continuous and can resolve arbitrarily small angle differences."
False. While low-frequency dimensions benefit from staying inside [0, L_train * theta_i], dividing all frequencies by s=4 crushes the phase angle between adjacent tokens on high-frequency dimensions by 4x. In our kata, that drops local step contrast between distance 1 and distance 2 by 12.4x (from 0.0817 to 0.0066), degrading local syntax and requiring fine-tuning unless you use frequency-selective scaling like YaRN.

Prove mathematically why applying 2D rotation R(m*theta) to query q and R(n*theta) to key k makes their dot product depend only on n - m.
In 2D, R(a)^T = R(-a) because rotation matrices are orthogonal. The inner product is (R(m*theta) q)^T (R(n*theta) k) = q^T R(m*theta)^T R(n*theta) k = q^T R((n - m)*theta) k. By trig identities, multiplying two rotations adds their angles: -m*theta + n*theta = (n - m)*theta.
Follow-upWhat happens if we use a general learned matrix M_m instead of an orthogonal rotation matrix? Without orthogonality and the group homomorphism property M_m^T M_n = M_{n-m}, the product depends on both absolute indices m and n separately rather than purely on n - m.
Why does RoPE inject position at every attention layer instead of adding it once to the input embeddings at Layer 0?
Adding p_m at Layer 0 mixes positional and semantic vectors into the same residual stream, where repeated RMSNorms and MLP projections dilute the positional phase across depth. Rotating Q and K freshly at every layer keeps the residual stream purely semantic while guaranteeing crisp relative-distance routing at Layer 1 and Layer 80 alike.
How many trainable parameters does RoPE add to a 70B transformer, and what is its per-token compute complexity?
RoPE adds zero trainable parameters; the frequencies theta_i = base^(-2i/d) are fixed constants. Compute cost is O(d_head) elementwise multiplications and additions per query/key head vector (4 multiplies and 2 adds per 2D pair), which is negligible compared to the O(d_model^2) QKV projections.
Follow-upHow do production kernels avoid calling sin() and cos() during every forward pass? They precompute a static table of cos(m * theta_i) and sin(m * theta_i) of shape (L_max, d_head / 2) in VRAM at model init and index it by token position m.
Compare the inductive bias of ALiBi against RoPE for long-context retrieval tasks.
ALiBi subtracts a monotonic linear penalty -m_h * |m - n| from attention logits, creating a strict distance decay that excels at local extrapolation but penalizes distant tokens regardless of content. RoPE encodes distance via multi-frequency phase rotations, allowing a high content-matching dot product on low-frequency dimensions to attend sharply to a needle 100k tokens back.
In Llama-3, theta_base was increased from 10,000 to 500,000. Calculate the wavelength ratio of the slowest dimension pair (i=31 in d=64) between the two bases.
For i=31, d=64, the exponent is 2i / d = 62 / 64 = 0.96875. The wavelength ratio is (500,000 / 10,000)^0.96875 = 50^0.96875 = 44.25x, stretching the slowest wavelength from 47,117.2 tokens to 2,084,764.8 tokens.
Follow-upDoes changing theta_base affect the fastest dimension pair i=0? No, because 2i/d = 0, so theta_0 = base^0 = 1.0 and lambda_0 = 2*pi = 6.3 tokens for any base.
Explain the three frequency regimes in YaRN (NTK-by-parts) and the role of the thresholds alpha=1 and beta=32.
Define r_i = L_train / lambda_i, the number of full wavelength rotations pair i completed inside the training window. (1) High frequency (r_i > 32): unscaled (gamma = 1) so local token contrast is untouched. (2) Low frequency (r_i < 1): wavelength exceeds L_train, so interpolate linearly by 1/s (gamma = 0). (3) Medium frequency (1 <= r_i <= 32): linear ramp blending between theta_i / s and theta_i.

Mixed review

Three questions from earlier topics. Nobody tells you the topic in an interview.

D04: Why does scaled dot-product attention divide Q K^T by sqrt(d_k) before applying softmax?
If query and key components have zero mean and unit variance, their dot product has mean 0 and variance d_k (standard deviation sqrt(d_k)). Dividing by sqrt(d_k) restores unit variance so large d_k values do not push softmax into flat saturation regions where gradients vanish.
D05: In Grouped-Query Attention (GQA) with H_q = 32 query heads and G = 8 KV groups, by what factor does the KV cache shrink compared to Multi-Head Attention (MHA)?
It shrinks by a factor of H_q / G = 32 / 8 = 4x. Every group of 4 query heads shares a single Key head and Value head, cutting KV cache memory and memory-bandwidth reads during autoregressive decoding by 75%.
D01: Why do modern LLM tokenizers (like Llama-3 Tiktoken or byte-level BPE) operate on UTF-8 bytes rather than Unicode characters as their base vocabulary?
Starting from the 256 raw UTF-8 bytes guarantees zero out-of-vocabulary (<unk>) tokens on any text, code, or emoji while keeping the base alphabet fixed at 256 before merging frequent byte pairs up to V = 128,256.

Short notes

Quick-memorization cheat sheet covering every subtopic on this page and the key facts to remember cold.

All subtopics on this page

  • Permutation equivariance & additive embeddings: Raw attention has no token order (Attn(PX) = P*Attn(X)); Layer-0 sinusoidal or learned x_m + p_m embeddings create 4 noisy cross-terms and fail past L_max.
  • Rotary Position Embedding (RoPE): Rotates each 2D head pair (2i, 2i+1) of Q and K at every layer by m * theta_i where theta_i = base^(-2i/d), so (R_m q)^T (R_n k) = q^T R_{n-m} k depends strictly on relative distance n - m (verified to 9.77e-15 error).
  • ALiBi linear biases: Subtracts static head-specific distance penalties -m_h * |m - n| from attention scores without rotating vectors, trading long-range retrieval capacity for simple local extrapolation.
  • Length extrapolation (PI, NTK, YaRN): Linear PI divides all frequencies by s, blurring local adjacent-token contrast by 12.4x (0.0817 -> 0.0066 at s=4); YaRN leaves high-frequency pairs (r_i > 32) unscaled (preserving 0.0816 contrast), interpolates low-frequency pairs (r_i < 1) by 1/s, and scales logits by 1/t.
Important things to remember
  • RoPE frequency & wavelength: theta_i = base^(-2i/d) and lambda_i = 2*pi * base^(2i/d); for d=64, wavelengths span 6.3 to 47,117.2 tokens at base=10,000 (Llama-2) and 6.3 to 2,084,764.8 tokens at base=500,000 (Llama-3).
  • Why Values V are never rotated: Only Q and K are rotated so their inner product cancels absolute position into R_{n-m}; rotating V would inject an uncancelled position phase into semantic content vectors.
  • KV-cache compatibility: Store post-RoPE keys R_n k_n in the KV cache once at generation time; new queries R_m q_m automatically compute relative distance n - m against cached keys.
  • YaRN formulas: Cycle count r_i = L_train / lambda_i with band thresholds alpha = 1, beta = 32, and query/key temperature multiplier sqrt(1/t) = 0.1 * ln(s) + 1 (1.1386 at s=4).
