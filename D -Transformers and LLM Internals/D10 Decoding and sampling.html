Decoding and sampling

Once the unembedding matrix produces a raw logit vector over the vocabulary, how does the inference engine turn those scores into one concrete next token without collapsing into repetitive loops or sampling incoherent tail garbage?

At a SQL-generation step, the top token SELECT already has probability 0.884 and the second token WITH has 0.059. If you use nucleus sampling with top_p = 0.90 (at T = 1.0), how many tokens survive in the candidate pool?
Two tokens survive (SELECT and WITH), not one. Nucleus sampling sorts tokens descending and keeps the smallest prefix whose cumulative probability reaches or exceeds top_p. Because 0.884 < 0.90, the sampler must include WITH (bringing cumulative mass to 0.943 ≥ 0.90), giving WITH a 6.3% renormalized chance of being picked even when the model is nearly certain of SELECT.
Suppose an already-generated error token zz_err has a negative logit of -0.5. To penalize repetition with multiplicative factor alpha = 2.0, you compute z_i = z_i / alpha. Did you make zz_err less likely or more likely?
More likely. Dividing -0.5 by 2.0 moves the logit up to -0.25 (closer to zero), which raises its softmax probability from 0.0018 to 0.0038 in our kata. Multiplicative repetition penalty requires a sign check: divide positive logits by alpha, but multiply negative logits by alpha so they become more negative (-1.00).
Does applying temperature T = 0.3 before top_p = 0.90 produce the exact same candidate pool as applying top_p = 0.90 before T = 0.3?
No. Temperature nonlinearly changes the softmax probabilities that top_p sums over. In our kata's flat distribution, cooling with T = 0.3 first concentrates mass into the top 3 tokens (k = 3, entropy 1.46 bits) so the 4th token falls outside the 0.90 nucleus. Running top_p = 0.90 first locks in 4 tokens at T = 1.0, and cooling afterward keeps all 4 alive (k = 4, entropy 1.76 bits).

The core idea

A transformer's forward pass ends at the unembedding projection (see D03), which outputs a vector of raw, unnormalized real numbers called logits, z in R^V, one per vocabulary token. The model's job is finished the instant z is computed; it never picks a token by itself. Choosing the next token is the job of the decoding and sampling pipeline, a deterministic or stochastic post-processor that reshapes z, converts it into a probability distribution p, prunes low-probability tail tokens, renormalizes the survivors so they sum to 1.0, and draws one token ID to append to the sequence.

Every production inference engine (vLLM, TensorRT-LLM, llama.cpp, SGLang) executes this pipeline in a strict order. If you change the order of operations or misconfigure the thresholds, a well-trained model will either lock into deterministic repetition loops (when decoding is too greedy) or hallucinate nonsensical tokens from the long tail of 128,000 vocabulary entries (when temperature and truncation let tail mass leak through). Mastering D10 means knowing the exact six-stage pipeline, why each filter exists, and how modern adaptive truncation (min_p) fixes the classic failure mode of top_p.

Memory hook

Remember the pipeline order with the acronym P-T-S-F-R-D (Penalty, Temperature, Softmax, Filter, Renormalize, Draw): "Penalize The Score, Filter Remaining Draws." If you filter before temperature, you freeze the guest list before checking the weather.

How it works

1. Repetition, frequency, and presence penalties

Before converting logits to probabilities, the sampler adjusts scores for tokens that have already appeared in the prompt or generated output. There are two standard families. In the HuggingFace / Keskar multiplicative repetition penalty (parameter alpha ≥ 1.0, where 1.0 means no penalty), any token i in the seen set has its logit rescaled according to its sign: if z_i > 0, set z_i = z_i / alpha; if z_i < 0, set z_i = z_i * alpha. In the OpenAI additive penalties, the adjustment is subtractive and sign-independent, splitting into a frequency penalty (proportional to how many times token i has appeared, count(i)) and a presence penalty (a flat one-time nudge if count(i) > 0):

# Multiplicative (HuggingFace / llama.cpp repetition_penalty alpha >= 1.0)
z_i = (z_i / alpha) if z_i > 0 else (z_i * alpha)   # for i in seen_tokens

# Additive (OpenAI / vLLM frequency_penalty in [-2, 2], presence_penalty in [-2, 2])
z_i = z_i - mu_freq * count(i) - mu_pres * (1 if count(i) > 0 else 0)

Use presence penalty to encourage topic diversity (nudging the model away from reusing any word once), and frequency penalty to break verbatim multi-token loops (where penalty grows linearly each time a token repeats).

2. Temperature scaling and numerical softmax

Next, logits are divided by temperature T > 0: z'_i = z_i / T, followed by the softmax function. Because exponentiating a float16 logit above 11.09 overflows to inf (exp(11.1) > 65504), every production softmax uses the log-sum-exp shift, subtracting M = max(z') from every entry before calling exp:

M = max(z / T)
p_i = exp((z_i / T) - M) / sum_j exp((z_j / T) - M)

Mathematically, multiplying numerator and denominator by exp(-M) changes nothing, but numerically the largest exponent is guaranteed to be exp(0) = 1.0, making overflow impossible; underflow smoothly flushes tiny tail tokens to 0.0. Temperature controls Shannon entropy H(p) = -sum p_i log2(p_i): as T -> 0, the gap between the top logit and all others scales to infinity, collapsing p to a one-hot vector on argmax(z) (greedy decoding, H = 0 bits). At T = 1.0, the model's raw training distribution is preserved. As T -> infinity, z_i / T -> 0 for all tokens, flattening p toward a uniform distribution 1 / V with maximum entropy log2(V).

Check: Why does pure temperature sampling at T = 0.8 without truncation still produce occasional gibberish tokens on a 128k-token vocabulary?
Because softmax assigns strictly positive probability to every token in the vocabulary. Even if 120,000 nonsensical tail tokens each have probability 0.0000005, their combined tail mass is 6%. Over a 500-token response, drawing from the full vocabulary virtually guarantees hitting that tail at least once, which then corrupts the autoregressive context for all subsequent steps.

3. Truncation filters: Top-k, Top-p (nucleus), and Min-p

To prevent tail draws, truncation filters set low-probability tokens to zero before renormalizing. Top-k keeps only the k highest-probability tokens (e.g., k = 50). Its flaw is rigidity: on a peaked SQL keyword step where 1 token is right, keeping 50 tokens admits 49 bad choices; on a flat creative step where 100 adjectives fit, keeping 50 chops off half the good options.

Top-p (nucleus sampling, Holtzman et al. 2020) sorts probabilities descending (p_(1) ≥ p_(2) ≥ ...) and keeps the smallest prefix whose cumulative sum reaches or exceeds p (e.g., top_p = 0.90):

# Top-p: keep smallest prefix m where cumulative mass >= p
keep_top_p = { (1), ..., (m) }  where m = min { j : sum_{r=1..j} p_(r) >= top_p }

# Min-p (Nguyen et al. 2024): scale threshold relative to the top token p_max
keep_min_p = { i : p_i >= min_p * max_j(p_j) }

Top-p adapts better than top-k, but still fails when confidence is high but just below top_p, or when you raise temperature T > 1.0 for creative writing. If the best token has p_max = 0.884 and top_p = 0.90, top-p is forced to include the runner-up token to cross the 0.90 cumulative line. Worse, at T = 1.8 with top_p = 0.95, our kata shows SELECT drops to 0.598 raw probability, so top-p keeps adding tokens until even banana enters the nucleus! Min-p solves this with a single relative rule: keep token i only if p_i ≥ min_p * p_max (typically min_p = 0.05 to 0.10). When p_max = 0.884 and min_p = 0.10, any token below 0.0884 is cut immediately (leaving only SELECT). When the distribution is flat (p_max = 0.303), the threshold drops to 0.0303, letting all 4 close contenders through while still blocking banana (0.025).

4. Renormalization, categorical draw, and beam search

After zeroing out filtered tokens, the surviving probabilities p_filt no longer sum to 1.0. Stage 6 divides each survivor by sum(p_filt) to form the final distribution p_final, builds its cumulative distribution function (CDF), draws a uniform random float u ~ Uniform(0, 1), and returns the first token index where CDF[i] ≥ u. Equivalently, engines sometimes use the Gumbel-Max trick: adding independent Gumbel(0, 1) noise directly to the log-probabilities and taking argmax, which samples from the categorical distribution in a single parallel GPU reduction without building a sequential CDF scan.

What if instead of sampling one token per step, you want the single highest-probability multi-token sequence? Greedy decoding picks argmax at step 1, which can walk into a dead-end at step 2. Beam search keeps the top B partial sequences (beams) alive at every step, expands each beam by all V possible next tokens, scores the B * V candidates by their cumulative log-probability (often divided by a length-normalization factor L^alpha so beam search does not unfairly favor shorter sequences that multiply fewer probabilities), and prunes back to the top B. In our kata, token 0 wins step 1 (0.52 vs 0.43) but hits a flat dead-end at step 2 (joint logprob -1.776), whereas Beam Search (B = 2) keeps token 1 alive and discovers path [1, 0] with joint logprob -0.899. Despite this advantage in machine translation and speech recognition, beam search is rarely used in open-ended LLM chat: maximizing sequence likelihood over open-ended text causes generic, repetitive loops (Holtzman et al.), and maintaining B parallel beams multiplies KV-cache memory and memory-bandwidth cost by B.

Check: In the playground above, when you select the Peaked distribution at T = 1.8, top_p = 0.95, min_p = 0.00, what is the renormalized probability of sampling banana, and what drops it to 0.0%?

kata.py

import numpy as np

TOKENS = ["SELECT", "WITH", "EXPLAIN", "VALUES", "banana", "zz_err"]
# Peaked step (SQL start: 1 clear winner) vs Flat step (4 close options + 2 tail junk tokens)
LOGITS_PEAK = np.array([5.2, 2.5, 1.9, 1.2, 0.1, -0.5])
LOGITS_FLAT = np.array([2.2, 2.0, 1.9, 1.7, -0.3, -0.8])

def softmax(z):
    s = z - np.max(z)  # log-sum-exp shift prevents exp overflow
    e = np.exp(s)
    return e / np.sum(e)

def entropy_bits(p):
    p_nz = p[p > 0]
    return float(abs(-np.sum(p_nz * np.log2(p_nz))))

def apply_rep_penalty(z, seen_ids, alpha=1.2, correct_sign=True):
    out = z.copy()
    for idx in set(seen_ids):
        if correct_sign:
            out[idx] = out[idx] / alpha if out[idx] > 0 else out[idx] * alpha
        else:
            out[idx] = out[idx] / alpha  # BUG: dividing negative logit raises it toward 0!
    return out

def sample_pipeline(z, T=1.0, top_k=0, top_p=1.0, min_p=0.0):
    if T == 0.0:
        p = np.zeros_like(z); p[np.argmax(z)] = 1.0
        return p
    p = softmax(z / T)
    keep = np.ones(len(p), dtype=bool)
    if top_k > 0:
        order = np.argsort(p)[::-1]
        keep[order[top_k:]] = False
    if top_p < 1.0:
        order = np.argsort(p)[::-1]
        csum = np.cumsum(p[order])
        cutoff = np.searchsorted(csum, top_p, side="left")
        keep[order[cutoff + 1:]] = False
    if min_p > 0.0:
        keep &= (p >= min_p * np.max(p))
    p_filt = np.where(keep, p, 0.0)
    return p_filt / np.sum(p_filt)

def fmt_dist(p):
    parts = [f"{TOKENS[i]}:{p[i]:.3f}" for i in range(len(p)) if p[i] > 0]
    return f"k={len(parts)} H={entropy_bits(p):.2f}b | " + " ".join(parts)

print("=== 1. SAME LOGITS THROUGH 6 SAMPLING STRATEGIES ===")
strategies = [
    ("Base (T=1.0)",      dict(T=1.0)),
    ("Greedy (T=0.0)",    dict(T=0.0)),
    ("Temp Cool (T=0.7)", dict(T=0.7)),
    ("Temp Hot (T=1.5)",  dict(T=1.5)),
    ("Top-k (k=3)",       dict(T=1.0, top_k=3)),
    ("Top-p (p=0.90)",    dict(T=1.0, top_p=0.90)),
    ("Min-p (m=0.10)",    dict(T=1.0, min_p=0.10)),
]
for label, z in [("PEAKED (SQL start)", LOGITS_PEAK), ("FLAT (4 close options)", LOGITS_FLAT)]:
    print(f"\n--- {label}: logits={np.round(z, 1).tolist()} ---")
    for name, kw in strategies:
        p = sample_pipeline(z, **kw)
        print(f"  {name:18s} -> {fmt_dist(p)}")

print("\n=== 2. REPETITION PENALTY & BEAM SEARCH (2-step decode) ===")
z_pen = apply_rep_penalty(LOGITS_PEAK, seen_ids=[0, 5], alpha=1.5, correct_sign=True)
print("Rep penalty (alpha=1.5 on seen=[SELECT, zz_err]):")
print(f"  Before: {fmt_dist(softmax(LOGITS_PEAK))}")
print(f"  After : {fmt_dist(softmax(z_pen))}")

step1_lp = np.log(softmax(np.array([2.0, 1.8, 0.1])))  # tok0=0.52, tok1=0.43
step2_cond = {0: np.log(softmax(np.array([0.1, 0.1, 0.1]))),   # tok0 leads to flat dead-end
              1: np.log(softmax(np.array([4.5, 0.0, 0.0])))}   # tok1 leads to high-certainty phrase
beams = [(step1_lp[i], [i]) for i in [0, 1]]
cand = [(lp + step2_cond[seq[-1]][j], seq + [j]) for lp, seq in beams for j in range(3)]
cand.sort(key=lambda x: x[0], reverse=True)
print(f"Beam B=2 best path: {cand[0][1]} (logprob={cand[0][0]:.3f}) vs Greedy path: [0, 0] (logprob={step1_lp[0]+step2_cond[0][0]:.3f})")

print("\n=== 3. BREAK-IT EXPERIMENTS ===")
# Break 1: Hot T=1.8 + Top-p=0.95 on Peaked logits leaks 'banana' into the nucleus; Min-p=0.10 blocks it
p_leak = sample_pipeline(LOGITS_PEAK, T=1.8, top_p=0.95)
p_safe = sample_pipeline(LOGITS_PEAK, T=1.8, min_p=0.10)
print(f"Break 1 (T=1.8 + Top-p=0.95 leak): {fmt_dist(p_leak)}")
print(f"Break 1 (T=1.8 + Min-p=0.10 safe): {fmt_dist(p_safe)}")

# Break 2: Pipeline order (T=0.3 BEFORE Top-p=0.90 vs Top-p=0.90 BEFORE T=0.3 on Flat logits)
p_right = sample_pipeline(LOGITS_FLAT, T=0.3, top_p=0.90)
p_trunc_first = sample_pipeline(LOGITS_FLAT, T=1.0, top_p=0.90)
p_wrong = softmax(np.where(p_trunc_first > 0, LOGITS_FLAT / 0.3, -1e9))
print(f"Break 2 (Right: T=0.3 then Top-p=0.90): {fmt_dist(p_right)}")
print(f"Break 2 (Wrong: Top-p=0.90 then T=0.3): {fmt_dist(p_wrong)}")

# Break 3: Sign bug in repetition penalty on negative logit (zz_err = -0.5)
z_bug = apply_rep_penalty(LOGITS_PEAK, seen_ids=[5], alpha=2.0, correct_sign=False)
z_fix = apply_rep_penalty(LOGITS_PEAK, seen_ids=[5], alpha=2.0, correct_sign=True)
print(f"Break 3 (Rep penalty sign bug on zz_err=-0.5): logit becomes {z_bug[5]:+.2f} (prob={softmax(z_bug)[5]:.4f}) vs fixed {z_fix[5]:+.2f} (prob={softmax(z_fix)[5]:.4f})")

What to notice

  1. Top-p leaks on near-certain peaks while Min-p locks in: On LOGITS_PEAK at T = 1.0, SELECT has raw probability 0.884. Because 0.884 < 0.90, Top-p (p=0.90) keeps k = 2 tokens and gives WITH a 0.063 renormalized probability (entropy 0.34b). Min-p (m=0.10) sets the bar at 0.0884, cutting WITH (0.059) and locking onto SELECT:1.000 (k = 1, 0.00b).
  2. Both adapt to flat uncertainty, unlike Top-k: On LOGITS_FLAT, the four valid SQL starters sit between 0.303 and 0.184, while banana sits at 0.025. Both Top-p (p=0.90) and Min-p (m=0.10) keep all k = 4 valid tokens (H = 1.98b) and zero out banana, whereas Top-k (k=3) blindly drops VALUES (0.184).
  3. Beam search rescues multi-step local traps: At step 1, token 0 beats token 1 (0.52 vs 0.43), so Greedy commits to [0, 0] with total logprob -1.776. Beam search (B = 2) retains token 1 and finds [1, 0] with logprob -0.899, nearly 2.4x higher joint probability (exp(-0.899) = 0.407 vs exp(-1.776) = 0.169).
  4. Repetition penalty redistributes mass to runners-up: Applying alpha = 1.5 to SELECT (+5.2 -> +3.47) and zz_err (-0.5 -> -0.75) drops SELECT from 0.884 to 0.574 and raises entropy from 0.72b to 1.72b.
Break it
  1. Hot temperature + Top-p tail leak (Break 1). Predict what happens on LOGITS_PEAK when someone wants "creative code" and sets T = 1.8, top_p = 0.95 vs T = 1.8, min_p = 0.10. In the output, Top-p=0.95 admits k = 5 tokens including banana:0.038 (3.8% chance of corrupting the SQL query!), whereas Min-p=0.10 blocks banana at k = 4.
  2. Swapping Temperature and Top-p order (Break 2). Predict what changes on LOGITS_FLAT if a buggy custom sampler runs top_p = 0.90 before dividing logits by T = 0.3. Running T = 0.3 first sharpens the top 3 tokens so they already exceed 0.90 cumulative mass (k = 3, H = 1.46b). Running top_p = 0.90 first admits k = 4 tokens at T = 1.0, so VALUES survives with 9.1% probability (H = 1.76b).
  3. Repetition penalty sign bug (Break 3). Remove the if out[idx] > 0 sign check in apply_rep_penalty so negative logits are divided by alpha = 2.0 instead of multiplied. On zz_err (logit -0.5), dividing by 2.0 raises the logit to -0.25 and more than doubles its probability from 0.0018 to 0.0038.

Stretch. Add a typical_p (locally typical sampling) filter to sample_pipeline that computes the conditional entropy H(p) and sorts tokens by |-log2(p_i) - H(p)|, keeping tokens whose information content is closest to the expected entropy.

Scenario: You build a voice AI clinical scribe that drafts SOAP notes (free-text narrative) and extracts ICD-10 billing codes (strict alphanumeric codes) in the same pipeline. A teammate configures a single global sampler: T = 1.2, top_p = 0.95, repetition_penalty = 1.35. Doctors report two bugs: billing codes occasionally contain hallucinated digits, and long patient histories start dropping repeated medical terms like "mg" and "daily" halfway through. Walk through root cause and fix.
  1. Diagnose the hallucinated ICD-10 digits: On structured code generation, valid digits have peaked logits, but T = 1.2 flattens the distribution and top_p = 0.95 forces the sampler to accumulate 95% mass, pulling wrong digit tokens into the nucleus (just like Break 1 in our kata where SELECT leaked banana).
  2. Diagnose the missing "mg" and "daily" terms: A multiplicative repetition_penalty = 1.35 divides positive logits by 1.35 as soon as a token appears once. In a medication list where "mg" and "daily" legitimately appear 10 times, penalizing them blocks the model from writing normal clinical syntax.
  3. Fix by decoupling sampler profiles per task: Split the call or use per-segment sampling parameters. For the SOAP narrative, use T = 0.5, min_p = 0.08, frequency_penalty = 0.2, repetition_penalty = 1.0 so repeated units ("mg") are barely touched unless they loop tens of times. For ICD-10 extraction, use T = 0.0 (greedy) plus constrained decoding (D12) against the valid ICD-10 prefix tree.

Interview

Say this aloud against the clock. Three levels, about 90 seconds.

1 Outcome 20 sDecoding and sampling is the six-stage post-processing pipeline that converts a transformer's raw vocabulary logits into a single chosen next token. Because the model only outputs unnormalized scores, the sampler controls the tradeoff between deterministic accuracy for tasks like SQL or code and diverse, non-repetitive generation for open-ended chat.
2 Mechanism 45 sThe pipeline runs in a strict sequence: Penalty, Temperature, Softmax, Filter, Renormalize, Draw. First, repetition or frequency penalties adjust logits of already-seen tokens, dividing positive logits by alpha and multiplying negative logits by alpha. Second, logits are divided by temperature T, where T approaching zero collapses to greedy argmax and T above one flattens the distribution. Third, softmax subtracts max(z) to prevent float16 overflow and normalizes scores to probabilities. Fourth, truncation filters zero out the long tail: top-k keeps a fixed count, top-p keeps the smallest prefix reaching cumulative probability p, and min-p keeps tokens above min_p times p_max. Finally, surviving probabilities are renormalized and sampled via a categorical draw.
3 Internals and limits 25 sOrder and thresholds matter: applying top-p before temperature filters the wrong distribution, and combining high temperature with top-p=0.95 on a peaked step pulls tail garbage into the nucleus, whereas min-p=0.10 dynamically tightens its threshold with p_max. For multi-step search, beam search tracks B parallel hypotheses, but we avoid it in chat because maximizing sequence likelihood causes generic loops and multiplies KV-cache memory by B.

Traps

Each one sounds right. Say what is wrong with it before you open it.

"Setting temperature T = 0 guarantees bit-for-bit identical outputs across every API call and batch size."
Wrong. T = 0 makes the sampler deterministic (argmax(z)), but the forward pass computing z on GPUs uses parallel floating-point reductions whose order changes with dynamic batch size and tensor-core split-K kernels. Because floating-point addition is non-associative, two nearly tied logits (within 1e-5) can flip order between runs, changing token t and every autoregressive token after it.
"Top-p = 0.90 means the sampler only considers tokens that each have at least a 90% probability."
Wrong. top_p = 0.90 is a threshold on the cumulative sum of sorted probabilities, not on individual token probabilities. If 20 tokens each have probability 0.045, none of them is anywhere near 90%, yet all 20 are kept because their cumulative sum reaches 20 * 0.045 = 0.90.
"To apply a multiplicative repetition penalty alpha > 1 to a seen token's logit z_i, you just divide z_i by alpha."
Wrong. Logits are unconstrained real numbers and are frequently negative. Dividing a negative logit like -0.5 by alpha = 2.0 yields -0.25, which is higher (closer to zero) and increases the token's softmax probability from 0.0018 to 0.0038. You must divide when z_i > 0 and multiply when z_i < 0.
"Beam search with width B = 4 always produces better chat responses than sampling because it finds a higher-probability sequence."
Wrong. In open-ended generation, the highest-probability sequence under an LLM is notoriously dull, generic, and prone to phrase loops ("I don't know, I don't know..."), because human language naturally stays in a typical-entropy band rather than maximizing likelihood at every step. Plus, B = 4 multiplies KV-cache memory and decode memory bandwidth by 4x.

Question bank

Answer aloud, then open. Grade yourself honestly.

Walk through the exact 6-stage order of operations in a modern LLM sampler.
1. Apply repetition, frequency, and presence penalties to raw logits z for seen tokens. 2. Divide logits by temperature T (z' = z / T). 3. Compute numerically stable softmax by subtracting max(z'), exponentiating, and dividing by the sum. 4. Apply truncation filters (top_k, top_p, min_p) to mask out tail tokens. 5. Renormalize surviving probabilities so they sum to 1.0. 6. Draw one token from the categorical distribution.
Follow-upWhat breaks if you apply top_p before temperature scaling? Answer: top_p computes cumulative mass using the unscaled T = 1.0 probabilities, so cooling with T = 0.3 cannot prune extra tokens out of the nucleus, and heating with T = 1.5 cannot widen the nucleus.
Prove mathematically why subtracting M = max(z) before exp() does not change softmax probabilities, and give the float16 overflow threshold.
In softmax(z - M)_i = exp(z_i - M) / sum_j exp(z_j - M), factor out exp(-M) from both numerator and denominator: (exp(-M) * exp(z_i)) / (exp(-M) * sum_j exp(z_j)). Since exp(-M) > 0, it cancels out identically. In IEEE-754 float16, the maximum representable value is 65,504, so exp(x) overflows to inf at x = ln(65504) = 11.09. Subtracting M ensures every exponent is ≤ 0.
Contrast how top_k, top_p, and min_p behave on a peaked distribution (p_max = 0.884) versus a flat distribution (p_max = 0.303).
top_k = 3 always keeps 3 tokens: on the peaked step it admits 2 unnecessary low-probability tokens, and on the flat step with 4 close options it cuts the 4th valid option. top_p = 0.90 keeps 2 tokens on the peaked step (because 0.884 < 0.90) and 4 on the flat step. min_p = 0.10 keeps only 1 token on the peaked step (cutoff 0.0884) and 4 tokens on the flat step (cutoff 0.0303).
Follow-upWhy does min_p handle high temperature (T = 1.8) better than top_p = 0.95? Answer: Raising T flattens p_max so top_p = 0.95 has to reach into the garbage tail (banana at 3.8%) to sum to 0.95, whereas min_p = 0.10 still cuts anything below 10% of p_max.
How do OpenAI's frequency_penalty and presence_penalty differ in formula and use case?
Both subtract from the logit of seen tokens: z_i = z_i - mu_freq * count(i) - mu_pres * I[count(i) > 0]. Presence penalty applies a flat one-time reduction regardless of whether the token appeared once or 50 times, encouraging the model to introduce new topics. Frequency penalty grows linearly with count(i), specifically targeting and breaking repetitive token loops.
Follow-upWhy is an additive penalty safer on negative logits than a naive multiplicative penalty? Answer: Subtracting a positive constant always makes any real number (positive or negative) smaller, so no sign check is needed.
What is the Gumbel-Max trick, and why do GPU inference kernels use it for categorical sampling?
Instead of computing a sequential prefix sum (CDF) over surviving probabilities and binary-searching for u ~ Uniform(0,1), the Gumbel-Max trick draws independent uniform variables u_i, adds Gumbel noise g_i = -log(-log(u_i)) to the log-probabilities log(p_i), and takes argmax_i(log(p_i) + g_i). The resulting argmax has the exact categorical distribution p_i and runs as a fast parallel reduction on the GPU.
When does Beam Search beat Greedy decoding, and why do we need length normalization in Beam Search?
Beam search beats greedy when the locally optimal token at step t leads to low-probability continuations at step t+1 (as in our kata where greedy path [0, 0] scored -1.776 while beam width B = 2 found [1, 0] at -0.899). Length normalization divides the cumulative log-probability by L^alpha (with alpha around 0.6-1.0) because every additional token adds a negative log-probability, which would otherwise bias beam search to pick premature EOS tokens.
Follow-upWhat is the KV-cache cost of running Beam Search with width B? Answer: Up to B times the per-request decode KV-cache memory and memory bandwidth, though prefix sharing (PagedAttention copy-on-write) shares blocks for the common prompt prefix.
If you set top_k = 1 and temperature = 100.0, what does the sampler do?
It performs deterministic greedy decoding! Even though T = 100.0 flattens the softmax probabilities so they are nearly equal, softmax(z / T) is strictly monotonic for any T > 0. The highest logit still has the highest probability, top_k = 1 masks out all other tokens, and renormalization sets that single winner's probability to 1.0.
Why should you avoid setting both top_p and temperature to non-default aggressive values according to API documentation, and when is combining a temperature with a filter actually required?
OpenAI advises beginners to tune one at a time when using T ≤ 1.0 because both reduce entropy. However, whenever you use T > 0 in production, pairing temperature with a tail truncation filter (especially min_p = 0.05-0.10 or top_p = 0.90-0.95) is essential so the 128k-token tail is zeroed out before sampling.
Follow-upIf a user asks for n = 5 diverse completions for a code problem, why is T = 0.0 useless? Answer: At T = 0.0, all 5 completions are identical greedy trajectories; you need T ~ 0.6-0.8 with min_p = 0.10 for pass@k diversity.
Calculate the renormalized probability of token B if top_k = 2 keeps only token A (raw prob 0.60) and token B (raw prob 0.20).
Renormalization divides each surviving token's probability by the sum of survivors (0.60 + 0.20 = 0.80). Token A becomes 0.60 / 0.80 = 0.75 (75%), and Token B becomes 0.20 / 0.80 = 0.25 (25%).

Mixed review

Three questions from earlier topics. Nobody tells you the topic in an interview.

D01: Why is LLM prefill compute-bound while single-stream autoregressive decode is memory-bandwidth-bound?
During prefill, all N prompt tokens are processed in parallel as a dense matrix-matrix multiplication ([N, d] x [d, d]), reusing weight matrices across N tokens for high arithmetic intensity (FLOPs per byte). During single-request decode, each step processes only 1 new token ([1, d] x [d, d] matrix-vector multiply), streaming the entire model's weights and KV cache from HBM just to do 2 FLOPs per parameter.
D02: Why do BPE tokenizers struggle with character-level tasks and arithmetic on multi-digit numbers unless digit-splitting rules are applied?
BPE merges frequent byte sequences greedily into variable-length subword tokens, so a number like "3842" may tokenize as ["384", "2"] while "38420" tokenizes as ["38", "420"]. Inconsistent digit boundaries destroy positional alignment for carry operations, which is why modern tokenizers either split every single digit or enforce 1-to-3 digit right-to-left chunking.
D03: Where do the raw logits z in R^V come from right before the D10 sampler runs, and what is weight tying?
The final layer norm output h in R^d of the last token position is multiplied by the unembedding matrix W_U in R^{d x V} to produce z = h * W_U in R^V. Weight tying shares the exact same parameter tensor between the input token embedding matrix W_E and the output unembedding transpose W_U^T, saving V * d parameters (significant in smaller models).
