Embeddings and the unembedding

How does an integer token ID become a dense vector in the residual stream, and how does the final hidden state become vocabulary logits at the other end? This page covers the input embedding table W_E, embedding space geometry and norm distortion, the output unembedding projection W_U, weight tying, and vocabulary surgery. Tokenization is D02, retrieval bi-encoder embeddings are H01, and vector math basics are A08.

In Llama 3.2 1B (vocabulary V = 128,256, width d = 2,048), if the input embedding table W_E and output unembedding matrix W_U are untied, roughly what share of the entire model's parameters do those two matrices alone consume: 5%, 15% or 35%?
About 35% (35.1% in the kata). Each matrix has 128,256 × 2,048 = 262.7 million parameters (0.53 GB in bf16). Untied, they total 525.3 million parameters (1.05 GB) against a 973 million parameter transformer body. That is why Llama 3.2 1B ties W_U = W_E.T to cut the embedding share to 21.3%, whereas Llama 3.1 8B leaves them untied (13.1%).
You inspect nearest neighbors in a trained embedding table W_E using raw dot product (u · v) and then using cosine similarity. Do they return the same top neighbors?
No. Dot product equals ||u|| ||v|| cos(θ), so tokens with large L2 norms win even when their angle is worse. In the kata, "naproxen" is closer in angle to "ibuprofen" (cosine 0.96) than to "aspirin" (cosine 0.92), but "aspirin" appears 3x as often and has norm 1.14 versus 0.75, flipping the dot-product ranking to put "aspirin" first (0.43 vs 0.29).
You add 8 new clinical special tokens to a pretrained model by resizing W_E and initializing the new rows with standard normal np.random.randn(8, d). Before any fine-tuning steps, what happens to next-token predictions?
The new tokens hijack softmax output probability (stealing 78.6% of probability mass in the kata). A vector drawn from N(0, 1) in d dimensions has expected L2 norm roughly sqrt(d) (4.26 in the kata at d = 16, or 64.0 at d = 4,096), whereas trained embeddings sit near norm 1.0. Under weight tying or shared init, the huge norm creates massive positive logits before training even starts.

The core idea

A transformer only computes on continuous vectors in R^d, called the residual stream, while a tokenizer speaks in discrete integers from 0 to V - 1. The embedding table W_E (shape V by d) and the unembedding matrix W_U (shape d by V) are the two bookends that translate between those two worlds. At the input, token ID i selects row i of W_E to start the residual stream as a d-dimensional vector. After all attention and MLP layers have refined that vector into a final normalized hidden state h in R^d, the unembedding matrix multiplies h by W_U to produce V raw scores (logits), one for every token in the vocabulary.

Although the two bookends have transpose shapes, their hardware costs are completely asymmetric. The input embedding is a dictionary lookup: copying one contiguous row of d floats from memory takes O(d) memory reads and zero arithmetic FLOPs. The output unembedding is a dense matrix-vector multiplication h @ W_U across every single vocabulary column, which costs 2 × d × V FLOPs at every generated token. When a model uses weight tying, it sets W_U = W_E.T so both bookends share the exact same physical tensor in memory, forcing the vector a token injects at the bottom of the network to equal the target vector the final hidden state must align with at the top.

Mental model. Think of the residual stream as a conference room where everyone speaks in d-dimensional arrows. W_E is the badge desk at the entrance: you hand over integer badge #i and receive your assigned starting arrow. The transformer layers rotate and add notes to that arrow. W_U is the exit poll at the door: your final arrow is compared by dot product against all V badge arrows simultaneously, and whichever badge arrow points closest (with the largest projection) wins the next token.

Memory hook

Remember L-C-N-P-T (Lookup, Cone, Norm, Project, Tie): Lookup row W_E[i] in O(d) bytes; vectors cluster in an anisotropic Cone where frequency inflates norms; final RMSNorm bounds hidden state length; Project logits z = h W_U in 2dV FLOPs; Tie W_U = W_E.T to save V × d parameters and pool rare-token gradients.

How it works

Input lookup: one-hot equivalence without the FLOPs

Mathematically, mapping token ID i to a vector is written as multiplying a one-hot row vector e_i in R^V (all zeros except a 1 at index i) by the embedding matrix W_E in R^(V × d): x = e_i @ W_E. Executing that formula literally as a dense matrix multiplication would multiply V - 1 zeros by d columns, wasting 2 × V × d FLOPs per token. Instead, frameworks implement nn.Embedding as a pointer offset: row i starts at byte offset i × d × sizeof(dtype), so the hardware issues a contiguous memory gather of d numbers (for d = 4,096 in bf16, just 8 KB per token). During backpropagation, gradients flow back only to the rows that appeared in the batch via a sparse scatter-add (np.add.at(dW_E, ids, dx)), leaving unseen vocabulary rows untouched.

Mathematical form:  x = one_hot(i) @ W_E      # 2 * V * d FLOPs (wasteful)
Hardware execution: x = W_E[i]                # O(d) memory read, 0 FLOPs
Backward pass:      scatter_add(dW_E, i, dx)  # only active rows get input gradients
Check: for V = 128,256 and d = 4,096 in bf16, how many bytes does W_E[i] read for one input token, and how many FLOPs would a naive one-hot matmul waste?
W_E[i] reads 4,096 × 2 = 8,192 bytes (8 KB) and does 0 FLOPs. A dense one-hot matmul would execute 2 × 128,256 × 4,096 = 1.05 billion FLOPs to produce the exact same 4,096 numbers.

Embedding geometry: cosine vs dot product and the anisotropy cone

Two tokens end up close in W_E when they appear in interchangeable contexts and force similar next-token predictions. However, how you measure "close" changes what you see. The dot product between two rows u and v is u · v = ||u|| ||v|| cos(θ), whereas cosine similarity divides out the norms: cos(θ) = (u · v) / (||u|| ||v||). During training, token frequency shapes vector length ||u|| because frequent tokens receive far more gradient updates (and different softmax repulsive pressure) than rare tokens. If you search W_E by dot product, high-norm tokens dominate the neighbor list even when their angle is worse. In addition, transformer embeddings are not isotropic (uniformly spread around the origin with average cosine 0); they cluster inside a narrow forward cone (anisotropy) where random pairs have positive cosine similarity, because every token shares common-mode gradients from predicting dominant words.

Check: in the kata, why does "naproxen" rank "ibuprofen" first by cosine similarity (0.96 vs 0.92) but rank "aspirin" first by dot product (0.43 vs 0.29)?
"Aspirin" appears 24 times and grows to norm ||e|| = 1.14, while "ibuprofen" appears 8 times with norm 0.75 and "naproxen" has norm 0.41. Multiplying the norms into the cosine (0.41 × 1.14 × 0.92 = 0.43 vs 0.41 × 0.75 × 0.96 = 0.29) lets the higher norm of "aspirin" override the closer angle of "ibuprofen".

The unembedding projection and final RMSNorm

At the top of the transformer, the final residual state x_L passes through a final normalization layer (RMSNorm in Llama, Qwen, and Mistral) to produce h = x_L / sqrt(mean(x_L^2) + eps) * gamma, and then multiplies by the unembedding matrix W_U in R^(d × V) to produce the logit vector z = h @ W_U in R^V. Each logit z_j = h · W_U[:, j] is the dot product between the normalized hidden state and token j's unembedding column. Softmax converts those logits into next-token probabilities P(j | h) = exp(z_j) / sum_k exp(z_k). Unlike the input lookup, the unembedding must score all V candidates on every forward pass, costing 2 × d × V FLOPs per generated token. The final RMSNorm is essential: residual stream magnitudes grow with depth, so skipping final normalization multiplies every logit by the residual stream's raw RMS scale, acting like a near-zero temperature that collapses softmax entropy.

Weight tying: sharing W_E and W_U

Weight tying sets W_U = W_E.T, eliminating a separate d by V matrix. This has two effects. First, it saves V × d parameters. On a small model with a large modern vocabulary, that saving is massive: in Llama 3.2 1B (V = 128,256, d = 2,048), a single table is 262.7M parameters (0.53 GB in bf16), so tying drops embedding share from 35.1% of the model to 21.3%. On an 8B+ model (d = 4,096), the second table is only 6% to 7% of total parameters, so Llama 3.1 8B and 70B leave W_E and W_U untied to give input representation and output scoring independent capacity. Second, tying couples gradients: every time token j is evaluated in the softmax output, the cross-entropy gradient dz_j * h directly updates row W_E[j], even on steps where token j did not appear in the input prompt.

Vocabulary surgery: resizing W_E and W_U safely

When you add special tokens (such as <|triage|> or tool-call markers) to a pretrained checkpoint, you resize W_E from V × d to (V + K) × d and W_U from d × V to d × (V + K). Calling a default random initializer like N(0, 1) is a classic production bug: trained embedding rows typically have L2 norm around 0.5 to 1.5, whereas an isotropic standard normal vector in d dimensions has expected norm sqrt(d) (64.0 when d = 4,096). In the first forward pass, the dot product h · e_new is tens of times larger than any trained logit, so the model emits the new token everywhere and the first backward step sends a massive gradient spike into the transformer body. Instead, initialize new rows to the mean vector of existing embeddings W_E.mean(dim=0) plus tiny noise (1e-4), or to the average of the existing subword embeddings that spell out the new token's meaning (for example, averaging the tokens for "clinical" and "triage").

Check: why does a vector sampled from N(0, 1) in R^4096 have an expected L2 norm near 64, and what two initialization recipes prevent logit hijacking during vocabulary surgery?
Each of the 4,096 coordinates has variance 1, so the sum of squares has expected value 4,096 and the L2 norm is roughly sqrt(4,096) = 64. Prevent logit hijacking by initializing new rows to the mean of all existing rows (mean(W_E) plus tiny noise) or to the average of the subword embeddings of a descriptive phrase.

Kata: embedding geometry, weight tying and surgery in 90 lines

This self-contained NumPy script audits real-model tied versus untied memory, trains a miniature language model on a clinical and systems corpus where "naproxen" appears only as a sentence-final target, compares cosine versus dot-product nearest neighbors, and tests three failure modes: untying weights, bad N(0, 1) vocabulary surgery, and skipping final RMSNorm.

kata.py

"""Embeddings and unembedding kata. Run: python kata.py [--untie] [--bad-init] [--no-norm]"""
import argparse, numpy as np

ap = argparse.ArgumentParser()
ap.add_argument("--untie", action="store_true", help="untie W_U from W_E.T")
ap.add_argument("--bad-init", action="store_true", help="init new tokens with N(0,1) instead of mean(W_E)")
ap.add_argument("--no-norm", action="store_true", help="skip final RMSNorm before unembedding")
args = ap.parse_args()
np.random.seed(4)

# 1. Scale audit: tied vs untied embedding memory and parameter share
print("=== 1. Real-model embedding scale (bf16 = 2 bytes/param) ===")
for name, V, d, body_m in [("Llama-3.2-1B", 128256, 2048, 973.0), ("Llama-3.1-8B", 128256, 4096, 6980.0)]:
    we_m = V * d / 1e6
    tied_pct = 100 * we_m / (body_m + we_m)
    untied_pct = 100 * (2 * we_m) / (body_m + 2 * we_m)
    print(f"{name:12} V={V} d={d} | Tied: {we_m:6.1f}M ({we_m*2/1e3:.2f} GB, {tied_pct:4.1f}%) | Untied: {2*we_m:7.1f}M ({we_m*4/1e3:.2f} GB, {untied_pct:4.1f}%)")

# 2. Clinic + systems corpus: "naproxen" appears ONLY as a target at sentence end
SENTS = (
    [["the", "patient", "took", "aspirin", "now", "fever"]] * 24 +
    [["the", "patient", "took", "ibuprofen", "now", "fever"]] * 8 +
    [["the", "patient", "took", "naproxen"]] * 3 +
    [["the", "server", "logged", "latency", "now", "alert"]] * 22 +
    [["the", "server", "logged", "jitter", "now", "alert"]] * 3
)
vocab = []
for s in SENTS:
    for w in s:
        if w not in vocab: vocab.append(w)
stoi = {w: i for i, w in enumerate(vocab)}
V, d = len(vocab), 16
triples = np.array([[stoi[s[i]], stoi[s[i+1]], stoi[s[i+2]]] for s in SENTS for i in range(len(s) - 2)])
X1, X2, Y = triples[:, 0], triples[:, 1], triples[:, 2]
counts = {w: sum(w in s for s in SENTS) for w in vocab}

# Verify lookup W_E[i] == one_hot(i) @ W_E
W_E = np.random.randn(V, d) * 0.04 + 0.08  # small init + slight common cone offset
W_U = (np.random.randn(d, V) * 0.04 + 0.08) if args.untie else W_E.T
W_1, W_2 = np.random.randn(d, d) * 0.15, np.random.randn(d, d) * 0.15
assert np.allclose(W_E[X1[:4]], np.eye(V)[X1[:4]] @ W_E)

def rmsnorm(h, skip=False):
    return h if skip else h / np.sqrt(np.mean(h * h, axis=-1, keepdims=True) + 1e-6)

lr = 0.10
for _ in range(260):
    e1, e2 = W_E[X1], W_E[X2]
    h_raw = 5.0 * (e1 @ W_1 + e2 @ W_2 + 0.6 * (e1 + e2))  # residual stream builds magnitude
    h = rmsnorm(h_raw, skip=False)
    logits = h @ (W_U if args.untie else W_E.T)
    probs = np.exp(logits - logits.max(axis=1, keepdims=True))
    probs /= probs.sum(axis=1, keepdims=True)
    dz = (probs - np.eye(V)[Y]) / len(Y)
    dh = dz @ (W_U.T if args.untie else W_E)
    if args.untie:
        W_U = 0.997 * W_U - lr * (h.T @ dz)
    else:
        W_E = 0.997 * W_E - lr * (dz.T @ h)  # tied: output gradient shapes W_E directly
    np.add.at(W_E, X1, -lr * (dh @ W_1.T + 0.6 * dh))
    np.add.at(W_E, X2, -lr * (dh @ W_2.T + 0.6 * dh))
    W_1 -= lr * (e1.T @ dh); W_2 -= lr * (e2.T @ dh)

# 3. Geometry: norms, cosine vs dot-product neighbors
norms = np.linalg.norm(W_E, axis=1)
unit_E = W_E / norms[:, None]
print(f"\n=== 2. Embedding geometry (V={V}, d={d}, {'UNTIED' if args.untie else 'TIED'}) ===")
for w in ["aspirin", "ibuprofen", "naproxen", "jitter"]:
    i = stoi[w]
    cos_s = unit_E @ unit_E[i]; cos_s[i] = -2
    dot_s = W_E @ W_E[i]; dot_s[i] = -1e9
    c_top = [(vocab[j], round(float(cos_s[j]), 2)) for j in np.argsort(-cos_s)[:2]]
    d_top = [(vocab[j], round(float(dot_s[j]), 2)) for j in np.argsort(-dot_s)[:2]]
    print(f"  {w:10} n={counts[w]:2d} ||e||={norms[i]:.2f} | cosine top: {c_top} | dot top: {d_top}")

# 4. Zero-shot input transfer ("naproxen", "now") -> "fever" (naproxen was ONLY a target in training!)
e1_t, e2_t = W_E[stoi["naproxen"]], W_E[stoi["now"]]
h_raw_t = 5.0 * (e1_t @ W_1 + e2_t @ W_2 + 0.6 * (e1_t + e2_t))
h_eval = rmsnorm(h_raw_t, skip=args.no_norm)
z_eval = h_eval @ (W_U if args.untie else W_E.T)
p_eval = np.exp(z_eval - z_eval.max()); p_eval /= p_eval.sum()
ent = -np.sum(p_eval * np.log2(p_eval + 1e-12))
print(f"Eval ('naproxen now' -> 'fever'): P('fever')={p_eval[stoi['fever']]:.3f} | max_logit={z_eval.max():.2f} | entropy={ent:.2f} bits")

# 5. Vocabulary surgery: add 8 new clinical tokens (<|triage|>, <|hipaa|>, ...)
rng = np.random.RandomState(12)
new_E = rng.randn(8, d) if args.bad_init else (W_E.mean(axis=0) + rng.randn(8, d) * 1e-3)
W_E_ext = np.vstack([W_E, new_E])
z_ext = h_eval @ W_E_ext.T
p_ext = np.exp(z_ext - z_ext.max()); p_ext /= p_ext.sum()
print(f"Surgery ({'N(0,1) bad init' if args.bad_init else 'mean(W_E) init'}): new ||e||={np.linalg.norm(new_E, axis=1).mean():.2f} vs old ||e||={norms.mean():.2f} | hijacked prob={p_ext[V:].sum():.3f}")

What to notice

  1. In Llama 3.2 1B (V = 128,256, d = 2,048), untying W_E and W_U consumes 525.3M parameters (1.05 GB in bf16), or 35.1% of the entire model. Tying cuts that to 262.7M parameters (21.3%). In Llama 3.1 8B (d = 4,096), the untied pair is 2.10 GB, or 13.1% of the model.
  2. Look at "naproxen" (count = 3, norm = 0.41) in the tied run: by cosine similarity its top neighbor is "ibuprofen" (0.96) followed by "aspirin" (0.92). By raw dot product, "aspirin" (0.43) flips ahead of "ibuprofen" (0.29) because "aspirin" occurred 24 times and grew to norm 1.14 versus 0.75.
  3. For "aspirin" itself, cosine top neighbors are the two other drugs ("ibuprofen" 0.98, "naproxen" 0.92), whereas dot product pulls in the high-frequency word "fever" (0.48) ahead of "naproxen". Always normalize rows before inspecting semantic neighbors in W_E.
  4. "Naproxen" never appeared as an input token during training (only at the end of "the patient took naproxen"). Yet with tied weights, predicting "naproxen" as an output trained its input row W_E[naproxen], giving P("fever" | "naproxen now") = 0.761.
  5. When 8 new clinical tokens are initialized around W_E.mean(axis=0), their average norm is 0.27 and they take only 4.7% of probability mass before fine-tuning.
Break it
  1. Untie W_U from W_E.T. Run python kata.py --untie. Predict first: since "naproxen" only appears as a target Y in the training sentences, what happens to its cosine similarity with "ibuprofen" in W_E and to P("fever" | "naproxen now")?
  2. Bad vocabulary surgery initialization. Run python kata.py --bad-init, which initializes the 8 new tokens with N(0, 1) instead of W_E.mean(axis=0). Predict the expected L2 norm of a 16-dimensional standard normal vector (sqrt(16) = 4.0) and see how much probability mass the untrained tokens steal.
  3. Remove final RMSNorm. Run python kata.py --no-norm, which skips normalizing the residual stream before h @ W_U. Predict what happens to max_logit and next-token entropy when residual magnitude 5x hits the unembedding directly.

Stretch. Subtract the mean vector W_E.mean(axis=0) from every row of W_E (post-processing centering, Mu et al.) before computing dot products, and check whether "aspirin" still pulls in "fever" as a top dot-product neighbor.

Interview

Say this aloud against the clock. Three levels, about 90 seconds.

1 Outcome 20 sThe embedding table W_E and unembedding matrix W_U are the two bookends of a transformer. W_E translates each integer token ID into a d-dimensional residual stream vector at the input, and W_U projects the final hidden state back across all V vocabulary tokens to produce next-token logits at the output.
2 Mechanism 45 sMathematically, input embedding is a one-hot vector times W_E of shape V by d, but in hardware it runs as an O(d) row lookup that copies d floats with zero arithmetic FLOPs. At the exit, the final residual vector passes through RMSNorm to bound its magnitude, then multiplies by W_U of shape d by V. That unembedding is a dense matrix-vector multiply costing 2dV FLOPs per generated token. Weight tying sets W_U equal to W_E transpose so both ends share one physical tensor, saving V times d parameters and letting output gradients train rare input rows.
3 Internals and limits 25 sIn Llama 3.2 1B, V is 128,256 and d is 2,048, so one bf16 table is 262.7 million parameters or 0.53 GB; tying drops embedding share from 35% to 21%. Trained embeddings form an anisotropic cone where frequency inflates vector norms, distorting dot-product neighbors relative to cosine. When adding tokens, initialize to the mean or subword average, never N(0,1), or huge norms hijack logits.
1:30
Say it like an engineer

Question: how do you add custom special tokens to a pretrained LLM for fine-tuning, and what can go wrong?

"You add the tokens to the tokenizer, call resize_token_embeddings on the model, and then fine-tune it on your dataset so the model learns what they mean."

"Adding K tokens resizes W_E from V by d to (V + K) by d and W_U to d by (V + K). Three things break if you just resize and run. First, initialization scale: trained embeddings have small L2 norms around 1, while a raw N(0,1) vector in d dimensions has norm sqrt(d), which hijacks logits in h @ W_U on step 1; in my toy run N(0,1) init stole 78.6% of probability mass versus 4.7% when initialized to mean(W_E). Second, if the model ties W_U = W_E.T like Llama 3.2 1B, you must preserve the tied pointer after resizing. Third, under LoRA, W_E and W_U are frozen by default, so you must unfreeze the new rows or add embed_tokens to modules_to_save."

The strong answer names the matrix shapes, the norm mechanism (sqrt(d)), an illustrative number from the kata (78.6% vs 4.7%), and the LoRA freeze trap.

Traps

Each one sounds right. Say what is wrong with it before you open it.

"The input embedding layer multiplies a one-hot vector of length V by the V × d matrix W_E on the GPU."
That is the mathematical identity, not what runs in hardware. A dense one-hot matmul would waste 2Vd FLOPs multiplying zeros. nn.Embedding executes an O(d) indexed memory gather (8 KB at d = 4,096 in bf16) with zero arithmetic FLOPs.
"Dot product and cosine similarity in W_E give the same nearest neighbors because embeddings have roughly unit length."
Trained token embeddings do not have unit length; their L2 norms vary systematically with token frequency and weight decay. In the kata, "aspirin" (count 24, norm 1.14) beats "ibuprofen" (count 8, norm 0.75) in dot product with "naproxen" (0.43 vs 0.29) even though "ibuprofen" is closer in cosine angle (0.96 vs 0.92).
"All modern LLMs tie their input and output embeddings because it saves memory with no downside."
Small models (Llama 3.2 1B and 3B, GPT-2, Gemma) tie weights because V × d is 20% to 35% of total parameters. Large models with big vocabularies (Llama 3.1 8B and 70B) leave W_E and W_U untied: at 8B+, the extra 1.05 GB is only 6.5% of the model, and decoupling input features from output logit scoring improves perplexity.
"When you add new special tokens for LoRA fine-tuning, calling resize_token_embeddings is enough for the model to learn them."
Two things fail: if the new rows are initialized with large variance, they hijack logits immediately; and because standard LoRA freezes W_E and W_U, the newly added rows receive zero parameter updates unless you explicitly make embed_tokens and lm_head trainable.

Question bank

Explain embeddings and the unembedding in 90 seconds.
Follow the three levels above: the bookend roles of W_E (V × d) and W_U (d × V); O(d) input lookup versus 2dV output matmul after final RMSNorm plus weight tying; and the 1B versus 8B parameter math, anisotropy/frequency norms, and safe vocabulary surgery.
Follow-upWhy is the output layer so much more expensive in FLOPs than the input layer? Input knows the single integer ID i and reads one row of d floats; output must compute a dot product against all V columns to score the full probability distribution.
Compare the parameter count and bf16 memory of W_E and W_U in Llama 3.2 1B (V = 128,256, d = 2,048) versus Llama 3.1 8B (V = 128,256, d = 4,096).
At 1B (d = 2,048), one matrix is 262.7M parameters (0.53 GB in bf16). Untied is 525.3M (1.05 GB, 35.1% of the model); tied is 262.7M (21.3%). At 8B (d = 4,096), one matrix is 525.3M parameters (1.05 GB) and untied is 1,050.7M (2.10 GB, 13.1% of the model).
Follow-upWhy does the embedding share shrink as model size grows? Embedding parameters grow linearly with d (as V × d), while transformer layer parameters grow quadratically with d (as L × d^2).
How does weight tying help rare tokens learn better representations?
With W_U = W_E.T, every softmax cross-entropy step pushes row W_E[j] toward or away from the final hidden state h. In the kata, "naproxen" appeared only as a target token, yet tying trained its input row to 0.96 cosine similarity with "ibuprofen" and lifted zero-shot input accuracy from 0.489 to 0.761.
Follow-upWhat is the theoretical downside of tying W_U = W_E.T? Input embeddings want to group words that have the same effect on future context, while unembeddings want to group words that are probable in the same current context, and tying forces one vector to serve both roles.
Why do dot-product nearest neighbors in W_E differ from cosine nearest neighbors?
Dot product multiplies cosine similarity by both vector norms (||u|| ||v|| cos θ). Because training gives different norms to frequent and rare tokens, high-norm tokens dominate dot-product queries even when another token has a smaller angle.
What is the anisotropy cone in transformer embeddings, and why does it happen?
Instead of pointing uniformly in all directions with average pairwise cosine 0, trained token embeddings cluster in a narrow cone with positive cosine similarity. Common-mode gradients from the unembedding softmax push all tokens along shared background directions.
Follow-upHow can you quickly check for anisotropy in a checkpoint's W_E? Normalize all rows to unit length, sample 1,000 random pairs, and compute their mean dot product; a value well above 0 confirms a narrow cone.
What does the final RMSNorm right before W_U do, and what happens if you remove it?
Residual stream activations accumulate across layers, so their RMS magnitude grows with depth. Final RMSNorm projects h back to a controlled shell before the dot product with W_U. Without it (as in --no-norm), logits scale up 5x (from 5.18 to 25.65) and softmax entropy collapses (from 1.14 to 0.01 bits).
Derive why initializing a new embedding row with N(0, 1) in d = 4,096 dimensions breaks generation before training starts.
For e ~ N(0, I_d), E[||e||^2] = d = 4,096, so ||e|| is about sqrt(4,096) = 64. Trained embeddings initialized at σ = 0.02 sit near norm 1. In z = h @ W_U, the new token's logit scales with ||e||, overwhelming trained logits.
Follow-upGive two safe ways to initialize new tokens when resizing W_E. Set each new row to W_E.mean(dim=0) plus tiny noise (or match the empirical mean and covariance of W_E), or average the existing subword embeddings of a short phrase describing the token.
During backward propagation on a prompt of length S, how do the gradient updates to W_E and W_U differ in sparsity?
The output gradient dW_U = h.T @ dz is dense across all V columns because softmax scores every vocabulary token at every position. The input gradient dW_E from the bottom of the residual stream is sparse: only the S token IDs present in the prompt receive scatter-add updates.
Can static rows in W_E distinguish "discharge" in "hospital discharge" from "battery discharge"?
No. W_E assigns a single static vector per token ID regardless of surrounding words. Disambiguating polysemous senses happens inside the subsequent self-attention and MLP layers as context gets mixed into the residual stream (D04).
Follow-upWhy can't you use a single token's row in W_E as a sentence embedding for RAG retrieval? W_E holds uncontextualized subword vectors; retrieval requires pooling contextualized representations trained with a contrastive objective (H01).
How are W_E and W_U sharded across GPUs in tensor-parallel serving when V = 128,256?
Using VocabParallelEmbedding, the V rows of W_E (and columns of W_U) are split evenly across N GPUs (V / N tokens per GPU). Each GPU looks up its local token range at the input and computes 1/N of the logits at the output, avoiding full-table replication.

Mixed review

Three questions from earlier topics. Nobody tells you the topic in an interview.

D01: why is autoregressive decoding memory-bandwidth-bound at batch size 1 while prefill is compute-bound?
Prefill processes all S prompt tokens in parallel with matrix-matrix multiplies that reuse model weights across S tokens. Decoding generates one token at a time with matrix-vector multiplies, reading all model weights from HBM for just one token of compute.
D02: why does a byte-level BPE tokenizer trained on English charge 4x to 5x as many tokens for Telugu or Hindi text with the same meaning?
Indic characters take 3 bytes in UTF-8, and BPE only merges byte pairs that occurred frequently in the training corpus. With English-only merges, Telugu stays near raw UTF-8 byte counts (337 vs 71 tokens, or 4.75x in the D02 kata).
K03: how many bytes per parameter do fp32, bf16, fp16, int8 and int4 use, and why do modern LLMs prefer bf16 over fp16 for training?
4, 2, 2, 1 and 0.5 bytes per parameter. bf16 keeps the same 8 exponent bits as fp32 (with 7 mantissa bits instead of fp16's 5 exponent and 10 mantissa), giving fp32's dynamic range so gradients and activations rarely overflow.
