During teacher-forced training, token t simply peeks at position t+1 in the input batch to copy the answer, driving training loss near zero while producing complete garbage during autoregressive inference when future tokens do not exist.

You waste 4,095 * 2 * 4,096 * 128,256 = 4.30 TFLOPs of compute and allocate a 4,096 * 128,256 * 2 bytes = 1.05 GB FP16 logit tensor just to throw away the first 4,095 rows! During training we need logits at all T positions to compute parallel cross-entropy loss, but during inference prefill we only sample the next token at position T - 1.

The core idea

A decoder-only transformer (GPT, Llama, Claude, Qwen, Mistral) is a conditional probability engine that maps a batch of integer token sequences idx in {0, ..., V-1}^(B x T) to next-token logit distributions logits in R^(B x T x V) in one deterministic forward pass. From end to end, only two tensor dimensions ever touch the outside world: batch size B and sequence length T (plus vocabulary size V at the very entrance and exit). Inside the model, from the moment token IDs index into the embedding table W_E[idx] until the final RMSNorm exits Layer L, the residual stream maintains one invariant shape: (B, T, d_model).

Understanding the full forward pass means holding two views simultaneously: the tensor-shape pipeline (how (B, T, d) splits into H heads of shape (B, H, T, d_h) for (B, H, T, T) causal routing, then expands to (B, T, d_ff) inside SwiGLU before returning to (B, T, d)) and the compute/memory regime split between parallel training (all T targets scored simultaneously in ~2N forward FLOPs per token) and autoregressive inference (compute-bound prefill over T prompt tokens followed by memory-bandwidth-bound decode generating 1 token per forward pass with a growing KV cache).

Memory hook

Memorize the 5-stage spine E-A-S-U-L ("EASy ULtimate pass") and the invariant trunk (B, T, d): Embed lookup (B,T) -> (B,T,d), Attention head split (B,H,T,d_h) -> (B,H,T,T) -> (B,T,d), SwiGLU channel expansion (B,T,d_ff) -> (B,T,d), Unembed after final RMSNorm (B,T,d) -> (B,T,V), and Loss sanity-checked at ln(V).

How it works

1. Stage-by-stage equations and tensor shapes

Let batch size be B, context length be T, vocabulary size be V, model width be d, query head count be H (with head width d_h = d / H), SwiGLU width be d_ff, and layer count be L. The complete forward pass executes five deterministic stages:

Stage 1 (Embed):      x_0 = W_E[idx]                                      # idx:(B,T) -> x_0:(B,T,d)
Stage 2 (Block l=1..L, Sublayer A - Causal Multi-Head / GQA Attention):
  n_1   = RMSNorm_1(x_{l-1})                                              # (B, T, d)
  Q,K,V = RoPE(reshape(n_1 W_Q)), RoPE(reshape(n_1 W_K)), reshape(n_1 W_V)# (B, H, T, d_h)
  S     = (Q K^T) / sqrt(d_h) + Mask_causal                               # (B, H, T, T), Mask[t,s>t] = -inf
  A     = concat_heads( softmax(S) V )                                    # (B, H, T, d_h) -> (B, T, d)
  h_l   = x_{l-1} + A W_O                                                 # (B, T, d)
Stage 3 (Block l=1..L, Sublayer B - SwiGLU Feed-Forward Network):
  n_2   = RMSNorm_2(h_l)                                                  # (B, T, d)
  g, u  = SiLU(n_2 W_gate), n_2 W_up                                      # (B, T, d_ff)
  x_l   = h_l + (g * u) W_down                                            # (B, T, d)
Stage 4 (Final Norm & Unembed):
  x_out  = RMSNorm_final(x_L)                                             # (B, T, d)
  logits = x_out W_head^T                                                 # (B, T, V) [or (B, 1, V) at decode]
Stage 5 (Cross-Entropy Loss over shifted targets tgt[b, t] = full_seq[b, t+1]):
  Loss   = - (1 / (B*T)) sum_{b,t} ln( softmax(logits[b, t])[tgt[b, t]] )

Notice the target index shift in Stage 5: input position t holds token seq[t] and its output logit row logits[b, t, :] predicts target token seq[t + 1]. One sequence of length T + 1 yields T parallel training examples: context seq[0:1] -> seq[1], context seq[0:2] -> seq[2], all the way to seq[0:T] -> seq[T].

2. The step-0 loss sanity check and analytic softmax-CE gradient

At step 0, before any optimizer step, weight matrices have small zero-mean Gaussian entries, so logits[b, t, v] ~ 0 for all v in {0, ..., V-1}. Softmax produces p_v = e^0 / sum_{k=1}^V e^0 = 1 / V. Plugging p_target = 1 / V into cross-entropy gives the famous initialization identity:

Loss_step0 = - ln(1 / V) = ln(V)       Perplexity_step0 = exp(Loss_step0) = V

If your initial loss is much higher than ln(V) (for example, 28.0 when ln(V) = 11.76 for Llama-3's V = 128,256), your weight initialization variance is too large or you forgot the final RMSNorm, saturating softmax at step 0. When differentiating L_t = -ln(p_{tgt}) with respect to the logit vector z = logits[b, t], the quotient rule collapses cleanly into a single subtraction:

d L_t / d z_v = p_v - 1_{v == tgt}     (where p = softmax(z))

That exact 3-line gradient (dlogits = probs; dlogits[target] -= 1; dlogits /= B*T) is what drives the 150-step training loop in our kata.

Check: For GPT-2 (V = 50,257) and Llama-3 (V = 128,256), what exact cross-entropy loss should you see at training step 0?
For GPT-2, ln(50,257) = 10.8249. For Llama-3, ln(128,256) = 11.7618. Any step-0 loss significantly above ~12.0 on those vocabularies indicates overly wide output projection initialization.

3. Training (teacher forcing) vs Inference (prefill + KV-cached decode)

Why does the forward pass behave differently during training versus production serving? During training, we already have the entire ground-truth sequence T in memory. Passing all T tokens at once through the upper-triangular causal mask computes all T prefixes in parallel via dense Matrix-Matrix multiplications (GEMMs, high arithmetic intensity, compute-bound on Tensor Cores). During autoregressive inference, future tokens do not exist yet, so execution splits into two distinct phases:

4. Exact parameter and forward-FLOP accounting

Multiplying an activation matrix of shape (B*T, m) by a weight matrix of shape (m, n) requires m * n multiply-adds per token, or 2 * m * n FLOPs per token. Therefore, every non-embedding parameter contributes exactly 2 FLOPs per token in the forward pass (and 4 FLOPs in the backward pass, totaling 6N training FLOPs per token). Notice that the initial embedding lookup W_E[idx] is a table indexing operation costing zero arithmetic FLOPs, while the output LM head x_out W_head^T is a full matrix multiply costing 2 * d * V FLOPs per projected token. Inside each block of width d with MHA and SwiGLU d_ff = (8/3)d:

  • Attention projections (Q, K, V, O): 4 d^2 params -> 8 d^2 FLOPs/token.
  • Attention scores & value aggregation (QK^T and PV): 0 params -> 4 * T * d FLOPs/token (or 2 * T * d causal effective FLOPs).
  • SwiGLU MLP (W_gate, W_up, W_down): 3 * d * d_ff = 8 d^2 params -> 16 d^2 FLOPs/token.
Check: At what sequence length T do the attention score FLOPs (4 * L * T * d) equal the attention QKVO projection FLOPs (8 * L * d^2)?
Setting 4 * L * T * d = 8 * L * d^2 and dividing both sides by 4 * L * d gives T = 2 * d. When sequence length T exceeds 2 * d_model (for example, T > 8,192 when d = 4,096), the quadratic attention dot products cost more FLOPs than all four Q, K, V, and O linear projections combined!

Kata: End-to-end nanoGPT decoder forward pass and Shakespeare training

Build a complete, dependency-free decoder-only transformer (Embedding -> Pre-RMSNorm -> Multi-Head Causal Attention -> Residual -> Pre-RMSNorm -> SwiGLU MLP -> Residual -> Final RMSNorm -> Tied LM Head -> Cross-Entropy Loss), trace every intermediate tensor shape, verify the ln(V) step-0 loss check, train for 150 steps on Shakespeare, and demonstrate what breaks when the causal mask is removed.

kata.py

import math, random

random.seed(42)

text = "To be, or not to be, that is the question: Whether tis nobler in the mind to suffer."
chars = sorted(list(set(text)))
V = len(chars)
stoi = {ch: i for i, ch in enumerate(chars)}
itos = {i: ch for i, ch in enumerate(chars)}
data = [stoi[c] for c in text]

# Tiny decoder-only config: B=2, T=12, d=16, H=4, d_head=4, d_ff=44
B, T, d, H, d_ff = 2, 12, 16, 4, 44
dh = d // H

def rmat(r, c, s=0.04):
    return [[random.gauss(0, s) for _ in range(c)] for _ in range(r)]

W_E = rmat(V, d, 0.04)
Wq, Wk, Wv, Wo = rmat(d, d), rmat(d, d), rmat(d, d), rmat(d, d)
Wg, Wu, Wd = rmat(d, d_ff), rmat(d, d_ff), rmat(d_ff, d)

def rmsnorm(vec, eps=1e-5):
    inv = 1.0 / math.sqrt(sum(v * v for v in vec) / len(vec) + eps)
    return [v * inv for v in vec]

def mv(v, W):
    return [sum(v[i] * W[i][j] for i in range(len(W))) for j in range(len(W[0]))]

def softmax(z):
    m = max(z)
    e = [math.exp(v - m) for v in z]
    s = sum(e)
    return [v / s for v in e]

def forward(idx_batch, tgt_batch=None, W_head=W_E, causal=True, trace=False):
    B_c, T_c = len(idx_batch), len(idx_batch[0])
    x = [[list(W_E[tok]) for tok in seq] for seq in idx_batch]
    if trace:
        print(f"1. Token IDs:       ({B_c}, {T_c}) -> Embed W_E[idx]: ({B_c}, {T_c}, {d})")
    h_batch, out_batch, logits_batch = [], [], []
    future_mass_sum = 0.0
    for b in range(B_c):
        n1 = [rmsnorm(x[b][t]) for t in range(T_c)]
        Q = [mv(n1[t], Wq) for t in range(T_c)]
        K = [mv(n1[t], Wk) for t in range(T_c)]
        Val = [mv(n1[t], Wv) for t in range(T_c)]
        attn_cat = [[0.0] * d for _ in range(T_c)]
        for h_i in range(H):
            c0 = h_i * dh
            for t in range(T_c):
                scores = []
                for s in range(T_c):
                    dot = sum(Q[t][c0 + c] * K[s][c0 + c] for c in range(dh)) / math.sqrt(dh)
                    if causal and s > t:
                        dot = -1e9
                    scores.append(dot)
                probs = softmax(scores)
                if b == 0 and h_i == 0:
                    future_mass_sum += sum(probs[s] for s in range(t + 1, T_c))
                for c in range(dh):
                    attn_cat[t][c0 + c] = sum(probs[s] * Val[s][c0 + c] for s in range(T_c))
        h_seq, out_seq, lgt_seq = [], [], []
        for t in range(T_c):
            ao = mv(attn_cat[t], Wo)
            ht = [x[b][t][i] + ao[i] for i in range(d)]
            h_seq.append(ht)
            n2 = rmsnorm(ht)
            g_pre = mv(n2, Wg)
            u_pre = mv(n2, Wu)
            gu = [(g_pre[i] / (1.0 + math.exp(-g_pre[i]))) * u_pre[i] for i in range(d_ff)]
            mlp = mv(gu, Wd)
            ot = rmsnorm([ht[i] + mlp[i] for i in range(d)])
            out_seq.append(ot)
            lgt_seq.append([sum(ot[i] * W_head[v][i] for i in range(d)) for v in range(V)])
        h_batch.append(h_seq); out_batch.append(out_seq); logits_batch.append(lgt_seq)
    if trace:
        print(f"2. Multi-Head Attn: Q,K,V ({B_c}, {H}, {T_c}, {dh}) -> Scores ({B_c}, {H}, {T_c}, {T_c}) -> Residual ({B_c}, {T_c}, {d})")
        print(f"3. SwiGLU + Head:   Gate ({B_c}, {T_c}, {d_ff}) -> Final Norm ({B_c}, {T_c}, {d}) -> Logits ({B_c}, {T_c}, {V})")
    loss = 0.0
    if tgt_batch is not None:
        for b in range(B_c):
            for t in range(T_c):
                p = softmax(logits_batch[b][t])
                loss -= math.log(p[tgt_batch[b][t]] + 1e-12)
        loss /= (B_c * T_c)
    return logits_batch, loss, out_batch, future_mass_sum / T_c

idx = [data[i:i+T] for i in [0, 16]]
tgt = [data[i+1:i+T+1] for i in [0, 16]]

print(f"=== End-to-End Decoder Forward Pass (V={V}, B={B}, T={T}, d={d}, H={H}, d_ff={d_ff}) ===")
_, loss0, hidden_batch, f_causal = forward(idx, tgt, causal=True, trace=True)
n_params = V * d + 4 * d * d + 3 * d * d_ff
print(f"Total params (tied head): {n_params:,} | Theoretical ln(V)={math.log(V):.4f} | Measured step-0 loss={loss0:.4f}")

print("\n=== Training Progression on Shakespeare Passage (150 steps) ===")
W_out = [list(row) for row in W_E]
lr = 0.6
for step in range(151):
    loss = 0.0
    dW = [[0.0] * d for _ in range(V)]
    for b in range(B):
        for t in range(T):
            h_vec = hidden_batch[b][t]
            lgt = [sum(h_vec[i] * W_out[v][i] for i in range(d)) for v in range(V)]
            p = softmax(lgt)
            target = tgt[b][t]
            loss -= math.log(p[target] + 1e-12)
            for v in range(V):
                g = (p[v] - (1.0 if v == target else 0.0)) / (B * T)
                for i in range(d):
                    dW[v][i] += g * h_vec[i]
    loss /= (B * T)
    if step in (0, 25, 50, 100, 150):
        print(f"step {step:3d} | cross_entropy_loss={loss:.4f} | perplexity={math.exp(loss):6.2f}")
    for v in range(V):
        for i in range(d):
            W_out[v][i] -= lr * dW[v][i]

# Decode batch-0 sequence from trained head
pred_chars = "".join(itos[max(range(V), key=lambda v: sum(hidden_batch[0][t][i] * W_out[v][i] for i in range(d)))] for t in range(T))
print(f"Decoded next-char targets: '{pred_chars}'")

_, _, _, f_leak = forward(idx, tgt, causal=False)
print(f"\n=== Causal Mask Verification ===")
print(f"Future token attention mass: Causal={f_causal:.4f} | Acausal (broken mask)={f_leak:.4f}")

What to notice

  1. Exact tensor shape invariance: Token IDs enter as (2, 12), expand to (2, 12, 16) after W_E[idx], split into (2, 4, 12, 4) for 4-head attention with (2, 4, 12, 12) score matrices, expand to (2, 12, 44) inside the SwiGLU gate, and exit Final RMSNorm at the exact trunk shape (2, 12, 16) before projecting to (2, 12, 22) logits.
  2. Parameter accounting matches formula: With tied embeddings W_head = W_E, total parameters are V*d + 4*d^2 + 3*d*d_ff = 22*16 + 4*256 + 3*16*44 = 352 + 1,024 + 2,112 = 3,488 parameters.
  3. Step-0 ln(V) verification: With V = 22 characters, uniform guessing gives ln(22) = 3.0910 (perplexity 22.00). Our small Gaussian init (s = 0.04) starts at 3.1874 (perplexity 24.23) and converges cleanly to 0.3281 (perplexity 1.39).
  4. Acausal mask leakage: Setting causal=False lets 45.91% (0.4591) of attention probability mass flow from future tokens s > t, whereas causal=True clamps future attention mass to exact 0.0000.
Break it

In PyTorch/NumPy multi-head attention, reshaping (B, T, d) directly to (B, H, T, d_h) without first reshaping to (B, T, H, d_h) and transposing axes (1, 2) scrambles token positions across heads. Predict why: token t=1's features end up inside token t=0's head 2, leaking future tokens even when the causal mask is applied!

Say this aloud against the clock. Three levels, about 90 seconds.

1 Outcome 20 sA decoder-only transformer maps integer token IDs of shape B by T to next-token logit distributions of shape B by T by V in one forward pass. Across all L blocks, the residual stream keeps one invariant shape, B by T by d, enabling parallel training in 2N forward FLOPs per token.
2 Mechanism 45 sFirst, token IDs index into W_E of shape V by d to form x_0 of shape B by T by d. Second, each block applies Pre-RMSNorm, projects into Q, K, V, reshapes to B by H by T by d_h, applies RoPE, and computes scaled dot-product attention with an upper-triangular causal mask so position t never attends to s greater than t. After weighting V, merging heads via W_O, and adding back to the trunk, the second sublayer runs Pre-RMSNorm and the three-matrix SwiGLU MLP through width d_ff back to B by T by d. Finally, post-stack RMSNorm and W_head transpose produce B by T by V logits.

Traps

Each one sounds right. Say what is wrong with it before you open it.

"You can reshape the QKV projection output directly from (B, T, d) to (B, H, T, d_h) using tensor.view(B, H, T, d_h) in row-major order."
False! That is the single most common bug when implementing multi-head attention from scratch. In row-major memory, a tensor of shape (B, T, d) lays out all d = H * d_h channels of token t=0 first, followed by token t=1. Calling .view(B, H, T, d_h) slices across the sequence dimension T, packing tokens 0..T/H into Head 0 and future tokens into earlier time indices! You must reshape to (B, T, H, d_h) first and then transpose axes 1 and 2 via .transpose(1, 2).
"The initial token embedding layer W_E[idx] and the final LM head x_L @ W_head^T cost the exact same number of FLOPs because both use a (V x d) matrix."
False. The input embedding W_E[idx] is a discrete integer row lookup (gather operation) that copies B * T rows of width d from memory with zero arithmetic multiply-add FLOPs. The output LM head x_out @ W_head^T multiplies a dense continuous vector in R^d against all V vocabulary rows, costing 2 * B * T * d * V FLOPs.
"During training, enabling the KV cache speeds up the forward and backward pass across long sequences."
False. A KV cache only helps during sequential token-by-token autoregressive decoding where past keys and values would otherwise be recomputed across T separate forward passes. During training, all T tokens are already processed in a single parallel forward pass, and intermediate activations must be kept (or recomputed via activation checkpointing) for the backward pass anyway.

Walk through the exact shape transformations inside Multi-Head Attention from normalized input n_1 of shape (B, T, d) to sublayer output h_l of shape (B, T, d).
1. Multiply n_1 (B, T, d) by W_Q, W_K, W_V (d, d) to get three tensors of shape (B, T, d). 2. View each as (B, T, H, d_h) and transpose axes 1 and 2 to (B, H, T, d_h) (applying RoPE to Q and K). 3. Multiply Q (B, H, T, d_h) by K^T (B, H, d_h, T) scaled by 1/sqrt(d_h) to get scores (B, H, T, T), apply causal mask and softmax. 4. Multiply probs (B, H, T, T) by V (B, H, T, d_h) to get (B, H, T, d_h). 5. Transpose axes 1 and 2 back to (B, T, H, d_h), flatten contiguous memory to (B, T, d), multiply by W_O (d, d), and add to x_{l-1} (B, T, d).
Follow-upHow do the shapes change if you use Grouped-Query Attention (GQA) with G KV heads instead of H? W_K and W_V project to (B, T, G * d_h), which reshapes and transposes to (B, G, T, d_h); each KV head is then broadcast across H / G query heads during the dot product.
Why do we add -inf (or -1e9) to upper-triangular positions (s > t) before softmax instead of zeroing out upper-triangular probabilities after softmax?
If you compute softmax over all T positions first and then zero out s > t, the remaining probabilities for s <= t no longer sum to 1.0, and the denominator of softmax at time t still includes exp(score_{t, s>t}), leaking future token magnitude into the forward normalization and backward gradients! Adding -inf before softmax ensures exp(-inf) = 0 so the causal prefix sums to exact 1.0 with zero future dependency.
Derive the forward-pass FLOP count per token for one decoder block (MHA + SwiGLU with d_ff = 8/3 d) as a function of d and sequence length T.
1. Q, K, V, O linear projections: 4 matrices of size (d, d) cost 4 * (2 d^2) = 8 d^2 FLOPs/token. 2. Attention dot products Q K^T and weighted sum P V: for each token across H heads, 2 * H * T * d_h + 2 * H * T * d_h = 4 * T * d FLOPs/token. 3. SwiGLU projections W_gate, W_up, W_down: 3 matrices of size d * (8/3)d cost 3 * 2 * (8/3) d^2 = 16 d^2 FLOPs/token. Total per block = 24 d^2 + 4 T d FLOPs/token.
Follow-upAcross L layers plus the LM head (d x V), what is the full-model forward FLOP formula per token? FLOPs_fwd = L * (24 d^2 + 4 T d) + 2 d V = 2 N_non_emb + 4 L T d + 2 d V.
Write a 4-line unit test that proves a transformer implementation has zero causal leakage from future tokens.
Create batch input idx_1 of shape (1, T) and copy it to idx_2, changing only token index k (idx_2[0, k] = (idx_1[0, k] + 1) % V). Run logits_1 = model(idx_1) and logits_2 = model(idx_2) in eval mode. Assert that max(|logits_1[0, :k, :] - logits_2[0, :k, :]|) < 1e-6: changing token k must have zero effect on any output logit at indices 0 .. k-1.
Why does the backward pass through a transformer cost roughly 2x the FLOPs of the forward pass (making total training cost ~6N FLOPs/token)?
For every linear layer Y = X W where X is (B*T, m) and W is (m, n), the forward pass performs one GEMM costing 2 * B * T * m * n FLOPs. The backward pass must compute two GEMMs of the exact same FLOP count: one for the activation gradient dX = dY W^T (2 * B * T * m * n FLOPs) and one for the weight gradient dW = X^T dY (2 * B * T * m * n FLOPs). Thus 1 (fwd) + 2 (bwd) = 3 * (2N) = 6N FLOPs per token.
Follow-upHow does activation checkpointing (gradient checkpointing) change this 6N number? Recomputing the forward pass of each block during backprop adds one extra forward pass (+2N), raising total training compute from 6N to 8N FLOPs/token (+33% compute) in exchange for reducing activation VRAM from O(L) to O(1).
Explain how Fused Linear Cross-Entropy eliminates the (B, T, V) logit memory bottleneck during long-context training.
At B=1, T=32,768, V=128,256, the hidden state x_out of shape (32768, 4096) is only 268 MB in BF16, whereas the logits x_out @ W_head^T of shape (32768, 128256) occupy 16.8 GB in FP32. Fused Linear Cross-Entropy slices x_out into small token chunks (e.g. 1,024 tokens at a time), computes the chunk's logits, evaluates online softmax cross-entropy loss, and immediately overwrites the chunk buffer with the gradient dlogits = (p - 1_y) to accumulate dx_out and dW_head without ever storing the full (B, T, V) tensor.
During inference, what is the arithmetic intensity (FLOPs per byte of weight read) of Prefill at T = 2,048 versus Decode at T = 1 (batch B = 1) in BF16?
Each 2-byte BF16 weight performs 2 * B * T FLOPs. During Prefill (B=1, T=2048), arithmetic intensity is 2 * 2048 / 2 = 2,048 FLOPs/byte, which is well above an H100's ~295 FLOPs/byte ridge point (strictly compute-bound). During Decode (B=1, T=1), arithmetic intensity collapses to 2 * 1 / 2 = 1 FLOP/byte, leaving Tensor Cores ~99.6% idle while waiting on HBM memory bandwidth.
Follow-upHow do serving engines raise arithmetic intensity during the Decode phase? By batching B = 64 to 256 concurrent requests via Continuous Batching (or validating K tokens in parallel via Speculative Decoding), raising intensity to B FLOPs/byte.
How are input token sequences and target token sequences aligned when preparing a pretraining batch of shape (B, T) from a flat token array?
From a contiguous chunk of T + 1 tokens data[i : i + T + 1], the input slice is the first T tokens idx = data[i : i + T] and the target slice is shifted right by 1 position: tgt = data[i + 1 : i + T + 1]. At every column t in {0, ..., T-1}, idx[t] is the current token and tgt[t] is the ground-truth next token.

Mixed review

Three questions from earlier topics. Nobody tells you the topic in an interview.

D07: What happens to Layer-1 weight gradients in a 16-layer transformer stack if you remove the residual connections, and why does Pre-Norm prevent gradient attenuation across depth?
Without residual connections, Layer-1 weight gradients collapse by 27 orders of magnitude (from 1.516e+00 to 1.087e-27 in our 16-layer kata) because gradients multiply through 32 weight Jacobians. Pre-Norm places RMSNorm inside the residual branch so the trunk Jacobian is d x_L / d x_0 = I + sum(dF_l / dx_0), preserving an unobstructed identity path I.
D06: Why does Linear Position Interpolation (dividing RoPE frequencies by scale s=4) hurt local token resolution, and how does YaRN fix it?
Dividing all frequencies by s=4 compresses phase differences between adjacent tokens on high-frequency dimensions, reducing local step contrast by 12.4x (0.0817 -> 0.0066). YaRN leaves high-frequency dimensions (r_i > 32 rotations in L_train) completely unscaled and only interpolates low-frequency dimensions (r_i < 1) while scaling attention logits by sqrt(1/t) = 0.1*ln(s) + 1.
D03: Why is greedy decoding (argmax) or temperature T -> 0 prone to degenerate repetition loops in open-ended text generation, and how does top-p (nucleus) sampling address it?
Greedy decoding always picks the mode of the conditional distribution, which in autoregressive LMs assigns rising self-reinforcing probability to previously seen phrases. Top-p (nucleus) sampling truncates the unreliable long tail by keeping only the smallest set of top tokens whose cumulative probability exceeds p (e.g. 0.9), then samples proportionally from that dynamic nucleus.

Short notes

Quick-memorization cheat sheet covering every subtopic on this page and the key facts to remember cold.

All subtopics on this page

  • End-to-end tensor shape pipeline (E-A-S-U-L): IDs (B, T) -> Embed W_E[idx] (B, T, d) -> L blocks keeping trunk invariant at (B, T, d) while Attention splits heads to (B, H, T, d_h) with (B, H, T, T) causal scores and SwiGLU expands channels to (B, T, d_ff) -> Final RMSNorm (B, T, d) -> LM Head (B, T, V).
  • Shifted targets & step-0 ln(V) sanity check: Input seq[0:T] predicts target seq[1:T+1] across all T positions simultaneously; at random init, near-zero logits yield uniform p = 1/V so step-0 cross-entropy must equal ln(V) (3.0910 for V=22, 11.7618 for V=128,256).
  • Causal mask integrity: Adding -inf to upper-triangular positions s > t before softmax keeps future attention mass at 0.0000 (vs 0.4591 leak when unmasked); always reshape QKV to (B, T, H, d_h) before transposing to (B, H, T, d_h).
  • Training vs Prefill vs Decode execution regimes: Training scores all (B, T, V) positions in parallel without a KV cache; Inference Prefill runs all prompt tokens in parallel (compute-bound GEMM, sets TTFT), populates the KV cache, and slices x_out[:, -1:, :] to project (B, 1, V); Inference Decode steps 1 token (B, 1, d) at a time (memory-bandwidth-bound GEMV, sets TPOT).
  • Full-model parameter & FLOP accounting: Non-embedding parameters N = 12 L d^2 cost 2N forward FLOPs/token (6N training FLOPs/token) plus 4 L T d attention score FLOPs/token and 2 d V LM-head FLOPs/token.
Important things to remember
  • Step-0 loss invariant: Always check Loss_step0 == ln(V) (~10.82 for 50k vocab, ~11.76 for 128k vocab); if higher, check Final RMSNorm and scale W_head init to 1/sqrt(d).
  • Analytic softmax + cross-entropy gradient: For target token y, dL / dz_v = p_v - 1_{v == y}.
  • Attention score FLOP crossover: Attention dot-product FLOPs (4 L T d) equal QKVO projection FLOPs (8 L d^2) at sequence length T = 2 * d_model.
  • Two production memory traps to avoid: Never project all T tokens through W_head during inference prefill (slice x_out[:, -1:, :] first), and use Fused Linear Cross-Entropy during long-context training so the (B, T, V) FP32 logit tensor is never materialized in VRAM.
