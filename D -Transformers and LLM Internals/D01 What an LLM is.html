What an LLM is

What is a language model actually computing, how is it trained, and why does generating text work one token at a time? This page covers the function, the loss and the loop. Tokenization, attention and sampling details have their own IDs.

Study path

Before you read

Guess first. A wrong guess now makes the right answer stick later.

The kata model has a vocabulary of 13 tokens. A model that guesses uniformly at every step scores what perplexity? What did the trained bigram score on its own training text?
Uniform guessing over 13 tokens scores perplexity 13. The trained bigram scored 2.33 on its training text, so it behaves as if it were choosing between about two equally likely tokens at each step. Perplexity is the effective number of choices per token.
Training an LLM and generating from one both "go token by token". True or false, and why?
False for training. A training sequence of n tokens gives n-1 next-token predictions scored in one parallel forward pass, because the true tokens are known and a causal mask hides the future. Only generation is sequential, because each new token must be sampled before the next step can start.
In the kata, the same trained model gave held-out perplexity of infinity on three ordinary sentences. What single event causes that, and what is the price of the fix?
One bigram never seen in training, such as "doctor books", gets probability 0, and log of 0 is minus infinity. Add-0.1 smoothing fixes it: held-out perplexity becomes 4.62. The price is that training perplexity rises from 2.33 to 2.69, because probability is moved from seen pairs to unseen ones.

The core idea

An LLM is one function. It takes a sequence of tokens, the context, and returns a probability for every token in its vocabulary being the next one. It does not return a word. It returns a distribution, and a separate step picks a token from it. Everything you have seen an LLM do, answering, coding, calling tools, is that function applied again and again.

Generation is a loop around that function: run the context through, get the distribution, sample a token, append it to the context, run again, stop on an end token or a length cap. Training is the same function scored against real text: for every position in a huge corpus, how much probability did the model give the token that actually came next? Push that probability up, across trillions of positions, and the function slowly becomes good at continuing text.

The mental model: a very good autocomplete whose only skill is estimating "what comes next, given everything so far", used as a loop. Facts, style and reasoning show up because predicting text well requires them. There is no database being queried and no plan written down before the first word.

Memory hook

One function, one loss, one loop. Function: context in, next-token distribution out. Loss: cross-entropy against the real next token at every position, all in parallel. Loop: sample, append, repeat, strictly one token at a time.

How it works

The chain rule is exact

The probability of any token sequence factorizes exactly: P(x1..xn) = P(x1) * P(x2 | x1) * P(x3 | x1,x2) * ... * P(xn | x1..x(n-1)). There is no approximation in that identity. The only approximation is in how the model estimates each factor. A bigram model keeps only the previous token: P(xt | x(t-1)). A transformer conditions on the whole window. Every language model, old or new, is a different way to estimate the same factors.

Training: score every position, minimize cross-entropy

Take a text, split it into tokens, and shift it by one: inputs are tokens 1 to n-1, targets are tokens 2 to n. The model outputs a distribution at each input position. The loss is the average of minus log of the probability it gave the true next token. A confident right answer costs near 0. A confident wrong answer costs a lot. This is cross-entropy against a one-hot target. Feeding the true previous tokens during training is called teacher forcing.

Because a causal mask stops position t from seeing later tokens (D04), one forward pass yields all n-1 predictions at once. That is why training parallelizes across positions and GPUs. Perplexity is exp(loss), the effective number of equally likely choices the model is torn between.

Check: a sequence has 2,000 tokens. How many training predictions come from one forward pass, and what stops the model from cheating by reading the answer?
1,999 predictions in one pass. The causal mask means position t only attends to positions up to t, so the target at t+1 is never visible to the prediction made at t.

Inference: weights frozen, one token per step

At serving time nothing is learned. The weights are fixed. You feed the prompt, read the logits at the last position, turn them into probabilities with softmax, choose a token (greedy, or sampled with temperature, top-k, top-p: D10), append it and go again. Step k+1 needs the token from step k, so the loop cannot be parallelized across output tokens. Latency is roughly the number of output tokens times the time per step (G15, K05).

Training and inference disagree

During training the model always sees real text as context. During generation it sees its own earlier outputs. One odd choice early on shifts every later distribution, and the errors can compound. This is called exposure bias. In the kata you can watch a model with a one-token memory wander for 12 steps without ever deciding to stop.

Check: why does a tiny error early in generation get worse, not better, as the answer gets longer?
Each new token is conditioned on the model's own earlier tokens, which training never showed it. A wrong early token becomes part of the context, so later distributions are computed from a context that is already off-distribution.

What the model is not

It is not a lookup. Training compresses text statistics into the weights, and nothing at inference retrieves a document. That is why knowledge has a cutoff date, why it can state a false fact fluently (the training objective rewards plausible continuations, not true ones), and why it does not learn from your chat: the weights do not change. What looks like learning is conditioning on tokens in the context window, and it ends when those tokens leave the window.

Base model, chat model, same loop

A base model is trained only on next-token prediction. A chat model starts from that and is post-trained (E01 to E10) so its continuations look like helpful replies inside a chat template (D25). The serving loop is identical.

Where this meets your work

In a voice agent for a clinic, the reply is produced token by token, so the per-token step time sets how soon the patient hears the first word and how long the sentence takes. And because the model only conditions on its context, it knows a patient's appointment only if retrieval put it in the prompt.

Check: a clinic assistant gives a patient the wrong opening hours. Name the mechanism, not the blame.
The model produced the most plausible continuation given its context. If the real hours were not in the context, it filled the gap from training statistics. Nothing was looked up. The fix is putting the hours in the context (retrieval) and letting it abstain when they are absent.

Kata: bigram language model

A word-level bigram model trained on a 12-sentence clinic corpus. It shows the whole story in miniature: training as counting, generation as a loop, and perplexity as the score. No API key, no GPU.

Run

python kata.py

kata.py

# D01 kata: a bigram language model. Run: python kata.py [smooth] [temperature]
import math, random, sys
from collections import Counter, defaultdict
SMOOTH = float(sys.argv[1]) if len(sys.argv) > 1 else 0.0   # break-it 1: add-k smoothing
TEMP = float(sys.argv[2]) if len(sys.argv) > 2 else 1.0     # break-it 2: sampling temperature

TRAIN = """the clinic opens at nine . the nurse calls the patient . the patient calls the clinic .
the doctor sees the patient at nine . the nurse books the patient at ten . the clinic books the doctor .
the doctor calls the nurse . the nurse sees the doctor at ten . the patient sees the nurse at nine .
the nurse sees the patient at nine . the nurse sees the patient at nine . the patient calls the clinic .""".split(" . ")
HELD = ["the doctor books the clinic", "the patient opens the doctor", "the nurse sees the patient at ten"]

def toks(s): return ["<s>"] + s.replace(" .", "").split() + ["</s>"]
train = [toks(s.strip(" .\n")) for s in TRAIN if s.strip()]
held = [toks(s) for s in HELD]

# TRAINING: one pass of counting. No gradients, no loop over epochs.
big = defaultdict(Counter)
for s in train:
    for a, b in zip(s, s[1:]): big[a][b] += 1
VOCAB = sorted({w for s in train for w in s[1:]})  # targets only, sorted: set order changes per run
V = len(VOCAB)
n_train = sum(len(s) - 1 for s in train)
print(f"vocab={V} bigram_types={sum(len(c) for c in big.values())} training_predictions={n_train}")

def probs(prev, temp=1.0):
    c = big[prev]; tot = sum(c.values())
    p = {w: (c[w] + SMOOTH) / (tot + SMOOTH * V) for w in VOCAB}
    if temp != 1.0:
        z = sum(v ** (1 / temp) for v in p.values() if v > 0)
        p = {w: (v ** (1 / temp) / z if v > 0 else 0.0) for w, v in p.items()}
    return p

print("\nP(next | 'at'), top 3 at three temperatures:")
for t in (0.3, 1.0, 2.0):
    top = sorted(probs("at", t).items(), key=lambda x: -x[1])[:3]
    print(f"  T={t}: " + "  ".join(f"{w} {p:.2f}" for w, p in top))

# INFERENCE: a sequential loop. Each token needs the previous one, so it cannot be parallel.
def sample(rng, temp=TEMP):
    out, steps = ["<s>"], 0
    while out[-1] != "</s>" and steps < 12:
        p = probs(out[-1], temp)
        out.append(rng.choices(list(p), weights=list(p.values()))[0]); steps += 1
    return out[1:], steps
rng = random.Random(0)
print(f"\nsamples (temperature={TEMP}, smooth={SMOOTH}):")
for _ in range(4):
    s, steps = sample(rng); print(f"  {steps:2d} forward steps -> {' '.join(s)}")

def ppl(data):
    nll, n = 0.0, 0
    for s in data:
        for a, b in zip(s, s[1:]):
            p = probs(a).get(b, 0.0)
            if p == 0: return float("inf")
            nll -= math.log(p); n += 1
    return math.exp(nll / n)
print(f"\nperplexity train={ppl(train):.2f}  heldout={ppl(held):.2f}")

What to notice

  1. Training is a counting pass over 81 predictions. There are no epochs and no gradients. For a bigram, counting is the exact optimum of the cross-entropy loss. A neural network reaches the same place slowly by gradient descent.
  2. The model outputs a distribution, not a word. After "at" it gives nine 0.71 and ten 0.29 at temperature 1.0. Two runs of the same prompt can differ without anything being broken.
  3. Every sample is a loop of forward steps, one per token. The sample that needed 8 steps cannot be computed in fewer than 8 sequential calls.
  4. Training perplexity 2.33 against a uniform baseline of 13 means the model learned a lot about this corpus. The held-out score is infinity, because one unseen pair gets probability 0. Low training perplexity says nothing about unseen text.
  5. Temperature reshapes the same distribution. At T=0.3 nine rises to 0.95, at T=2.0 it drops to 0.61.

  3. One-token memory. In the smoothing run, one sample hit the 12-step cap without ever ending. Predict why a model whose only state is the previous token cannot know a sentence has gone on too long.

Monitor: stop-reason distribution, output tokens per request, time to first token and time per output token, and repetition rate on a sample of responses.

Scenario: your clinic voice agent sometimes repeats the same sentence until the call times out. What do you check, in order?
  1. Pull the traces and look at the stop reason and output token count on the bad turns. Length stops mean it never emitted an end token.
  2. Check the sampling settings. Very low temperature on a context that already contains the phrase makes repetition the most likely continuation.
  3. Read the prompt on a failing turn. Is the repeated sentence already in the conversation history, so the model is continuing a pattern it was given?
  4. Reproduce with fixed settings and look at the logprobs on the repeated tokens to see how confident it is.
  5. Fix in layers: a hard per-turn output cap, stop sequences, a repetition detector that cuts the turn, a moderate temperature, and a trimmed history.

Say it like an engineer

Traps

Each one sounds right. Say what is wrong with it before you open it.

"When you ask an LLM a question, it looks up the answer in its training data."
There is no lookup at inference. Training compressed text statistics into weights, and generation computes a distribution from the context and those weights. It can reproduce memorized text, but nothing is retrieved, which is why it can be stale or invent a citation.
"Training and generation both work one token at a time."
Only generation does. Training scores all n-1 positions of a sequence in one parallel pass, using the true tokens and a causal mask. Generation is sequential because each token must exist before the next step.
"Set temperature to 0 and the answer is deterministic and therefore correct."
Greedy decoding picks the most likely token, which can still be wrong. And determinism is not guaranteed anyway: batching and floating-point order can change outputs slightly. Determinism is not accuracy.
"The model learns from your conversation as you chat with it."
The weights are frozen at inference. The model conditions on the tokens in its context window, which looks like learning but vanishes when those tokens leave the window. Persistent memory is a separate system that writes text back into the context (G11, G12).

Explain what an LLM is in 90 seconds.
Use the three levels above: function from context to next-token distribution, trained by cross-entropy in parallel and run as a sequential sample-append loop, with perplexity, exposure bias, 2N FLOPs per token and the plausibility limit as the internals.
Follow-upWhich number in your answer would a skeptical interviewer check first? Be ready to derive perplexity from loss, or 2N from the weight count.
Write the chain-rule factorization of a sequence probability. What is approximated?
P(x1..xn) = product over t of P(xt | x1..x(t-1)). The identity is exact. The model approximates each conditional factor.
Follow-upWhat does a bigram model change? It truncates the condition to the previous token only, which is why it cannot track anything longer than one step back.
What is the training loss and how does it relate to perplexity?
Average negative log probability the model gave the true next token, which is cross-entropy against a one-hot target. Perplexity is exp of that loss in nats, the effective number of equally likely choices per token.
Follow-upWhat perplexity does a uniform guess score? V, the vocabulary size. In the kata that is 13, against 2.33 trained.
Why is training parallel across positions but generation sequential?
In training the true tokens are known, so every position can be scored at once, and the causal mask prevents peeking ahead. In generation the next input is the token you are about to sample, so step k+1 waits on step k.
Follow-upWhere does that sequential cost show up in a product? In time per output token: latency is roughly output tokens times step time, and prefill versus decode behaviour is K05.
Walk through one decoding step.
Run the context through the model, take the logits at the last position, softmax to probabilities, apply the sampling rule, append the chosen token, check for an end token or the length cap.
Follow-upWhat fraction of that is the model versus sampling? Almost all the time is the forward pass. Sampling is a cheap operation on one vector of size V.
What is exposure bias?
Training conditions on true previous tokens, but inference conditions on the model's own outputs. A mistake early in generation puts off-distribution tokens into the context and later steps can drift further.
Your bigram gets infinite held-out perplexity. Why, and what does the fix cost?
An unseen pair has probability 0 and log 0 is minus infinity. Add-k smoothing assigns small mass to unseen pairs, giving held-out 4.62, but it raises training perplexity from 2.33 to 2.69.
Follow-upDoes a large neural model have this problem? Not in the same way: softmax never outputs an exact 0, and embeddings let it generalize to unseen combinations.
How does a base model differ from a chat model at the mechanism level?
Both are next-token predictors run in the same loop. The chat model is further post-trained (supervised and preference tuning) so its continuations look like helpful replies, and it is prompted through a chat template.
Does the model learn from your chat? Why or why not?
No. Weights are frozen at inference. It conditions on the tokens in the context window, so it can use what you wrote while it is in the window. Persistent memory is an external system that adds text back into the context.
Roughly how much compute does one generated token cost for a dense model with N parameters?
About 2N FLOPs, one multiply and one add per weight, ignoring the attention term that grows with context length. Training costs more per token because of the backward pass.

Mixed review

Day 1 of week 1 has no earlier topic to review, so these three come from foundations you already know and will meet properly later this week (A13, A16).

A13: State the chain rule of probability for two events, and say what conditional probability means.
P(A and B) = P(A) * P(B | A). P(B | A) is the probability of B once you know A happened, which is exactly what a language model estimates for the next token given the context.
A16: Write cross-entropy between a true distribution p and a model q. What does it reduce to when p puts all mass on one token?
H(p, q) = minus the sum over tokens of p(x) * log q(x). With a one-hot p it reduces to minus log q(correct token), the per-position loss in the kata.
A16: What is the entropy of a fair coin, and of a uniform choice among 8 outcomes, in bits?
1 bit for the coin and 3 bits for 8 outcomes, since entropy of a uniform choice among k outcomes is log2(k). Perplexity is the same idea expressed as k itself.
