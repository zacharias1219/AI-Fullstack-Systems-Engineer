Multi-head attention and its variants

Why do modern transformers split attention across dozens of parallel heads, and how do Multi-Query Attention (MQA), Grouped-Query Attention (GQA), and Multi-head Latent Attention (MLA) slash the KV-cache memory wall by 4x to 14x without losing multi-head expressivity? This page covers subspace splitting and concatenation, MHA vs GQA vs MQA vs MLA parameter and KV-cache math, grouped KV broadcasting (repeat_kv), and MLA weight absorption. Single-head causal attention is D04, RoPE positional math is D06, and serving engine KV paging is K06/K08.

Study path

Before you read

Guess first. A wrong guess now makes the right answer stick later.

You have a 32-layer transformer with d_model = 4,096, n_q = 32 query heads, and head dimension d_h = 128 in BF16 (2 bytes/element). For a single request at sequence length S = 32,768, how much VRAM does the KV cache consume under standard MHA (n_kv = 32) versus Llama-3-8B's GQA-4 (n_kv = 8)?
Standard MHA consumes 16.00 GiB (512.0 KiB per token), which is larger than the entire 8B model's weights! Switching to GQA-4 (n_kv = 8, where every 4 query heads share 1 KV head) cuts the KV cache by 4x to 4.00 GiB (128.0 KiB per token), and cuts attention layer parameters from 2,147.5M to 1,342.2M.
Does splitting d_model = 4,096 into n_q = 32 parallel heads of dimension d_h = 128 in standard MHA cost 32x as many FLOPs and parameters as a single full-width head of dimension 4,096?
No. Because d_h = d_model / n_q = 128, stacking 32 projection matrices of shape (4096, 128) produces one (4096, 4096) matrix with the exact same parameter count (4 * d_model^2 per layer) and the exact same total FLOPs (8 T d_model^2 + 4 T^2 d_model) as a single 4,096-wide head, while giving the model 32 independent softmax routing distributions per token.
In Multi-head Latent Attention (MLA, used in DeepSeek-V2/V3), the model expands a compressed latent vector c_KV (dimension d_c = 512) back into 32 full key and value heads of dimension 128 via up-projection matrices W_UK and W_UV. Why doesn't the inference engine have to cache those expanded 32-head K and V tensors in HBM?
Because linear projections are associative: during inference, W_UK is absorbed into W_Q (so each query head projects to dimension d_c = 512 and dots directly against the cached latent c_KV), and W_UV is absorbed into W_O. The engine only caches c_KV (512 floats) plus one shared decoupled RoPE key k^R (64 floats) = 576 floats per layer (36.0 KiB/tok across 32 layers, or 1.12 GiB at 32k context - 14.2x smaller than MHA).

The core idea

A single attention head (D04) has only one softmax distribution per query token: if position i needs to attend simultaneously to a syntactic subject at position 0, an anticoagulant drug at position 2, and a dosage number at position 3, one softmax row must average their value vectors together. Multi-Head Attention (MHA) fixes this by splitting the d_model residual space into n_q parallel subspaces of width d_h = d_model / n_q. Each head h runs its own independent Q_h, K_h, V_h projections and its own softmax routing matrix A_h, then concatenates all n_q outputs and mixes them back into the residual stream through an output projection W_O in R^((n_q * d_h) x d_model).

During training and prompt prefill, MHA is compute-bound and works well. During autoregressive decoding (K05, K06), however, every generated token must read all cached past keys and values from GPU HBM. The KV cache footprint 2 * L * n_kv * d_h * S * B * bytes scales directly with the number of key-value heads n_kv. That hardware bottleneck drove three evolutionary variants: Multi-Query Attention (MQA) shares a single KV head across all query heads (n_kv = 1); Grouped-Query Attention (GQA) partitions the n_q query heads into n_kv groups so each group of g = n_q / n_kv query heads shares one KV head; and Multi-head Latent Attention (MLA) compresses all keys and values into a single shared low-rank latent vector c_KV of width d_c plus a tiny decoupled RoPE key k^R of width d_r.

Memory hook

Remember 32 - 8 - 1 - Latent (the KV head progression at L = 32, d = 4,096, S = 32k): 32 KV heads in MHA = 512 KiB/tok (16.00 GiB); 8 KV heads in GQA-4 = 128 KiB/tok (4.00 GiB); 1 KV head in MQA = 16 KiB/tok (0.50 GiB); Latent c_KV(512) + k^R(64) in MLA = 36 KiB/tok (1.12 GiB, equivalent to 2.25 KV heads).

How it works

Multi-Head Attention (MHA): subspace projections and W_O mixing

In standard MHA with n_q heads and head width d_h = d_model / n_q, each head h in {0 .. n_q - 1} has projection matrices W_Q^h, W_K^h, W_V^h in R^(d_model x d_h). In practice, frameworks fuse the n_q small matrices into three single dense matrices W_Q, W_K, W_V in R^(d_model x (n_q * d_h)), execute three large GEMMs, and reshape/transpose the outputs from (B, T, n_q * d_h) to (B, n_q, T, d_h) so the head axis sits next to the batch axis. Batched causal attention runs in parallel across all B * n_q slices, producing (B, n_q, T, d_h), which is transposed back to (B, T, n_q * d_h) and multiplied by the output matrix W_O in R^((n_q * d_h) x d_model). Notice why W_O is mandatory: concatenation alone places head 0 in coordinates 0..d_h-1 and head 1 in d_h..2d_h-1; W_O linearly mixes the findings of all heads across the full residual stream.

MHA(X) = Concat(head_0, ..., head_{n_q-1}) @ W_O
where head_h = Attention(X @ W_Q^h, X @ W_K^h, X @ W_V^h)   # each head_h is (B, T, d_h)
Per-layer MHA params (when n_q * d_h = d): 4 * d^2  (W_Q, W_K, W_V, W_O each d x d)

MQA and GQA: grouped KV broadcasting and repeat_kv

In Grouped-Query Attention (GQA), we keep n_q query heads (so W_Q and W_O each remain size d_model x (n_q * d_h)), but reduce the key and value projections to n_kv heads, where n_kv divides n_q evenly. Setting n_kv = n_q recovers MHA; setting n_kv = 1 gives Multi-Query Attention (MQA). Let the group size be g = n_q / n_kv. Query heads {g*k, g*k + 1, ..., g*(k+1) - 1} all attend to the same key-value head k.

How you broadcast K_kv from shape (B, n_kv, T, d_h) to (B, n_q, T, d_h) is a notorious implementation bug. You must repeat each KV head g times contiguously along the head axis ([kv_0, kv_0, kv_0, kv_0, kv_1, kv_1, kv_1, kv_1] via torch.repeat_interleave(K_kv, g, dim=1) or expanding (B, n_kv, 1, T, d_h) -> (B, n_kv, g, T, d_h)). If you tile the whole array instead (np.tile or reshaping with the group axis in front, producing [kv_0, kv_1, kv_0, kv_1, ...]), query head 1 is paired with kv_1 instead of kv_0, scrambling the pretrained head alignment (an immediate 2.8578 output error in our kata). Production kernels like FlashAttention-2/3 avoid copying memory altogether by indexing kv_head = q_head // g directly inside SRAM.

Per-layer GQA params: 2 * d * (n_q * d_h)  +  2 * d * (n_kv * d_h)   # W_Q, W_O + W_K, W_V
KV cache bytes:       2 * L * n_kv * d_h * S * B * bytes_per_elem
Correct repeat_kv:    K_expanded[:, h, :, :] = K_kv[:, h // g, :, :] # contiguous groups!
Check: in a 32-layer model with d = 4,096, n_q = 32, d_h = 128, how many total attention parameters (in millions) and how many KiB per token of BF16 KV cache do MHA (n_kv = 32), GQA-4 (n_kv = 8), and MQA (n_kv = 1) use?
Across 32 layers: MHA uses 2,147.5M attention parameters and 512.0 KiB/token of KV cache. GQA-4 (n_kv = 8) uses 1,342.2M parameters and 128.0 KiB/token (4x cache reduction). MQA (n_kv = 1) uses 1,107.3M parameters and 16.0 KiB/token (32x cache reduction).

Multi-head Latent Attention (MLA): low-rank KV compression and decoupled RoPE

GQA reduces the KV cache by forcing g query heads to look at identical K and V vectors. DeepSeek-V2 introduced Multi-head Latent Attention (MLA) to achieve an even smaller KV cache than GQA-8 while letting every query head retain its own distinct K and V vectors. Instead of projecting X directly into n_kv heads, MLA compresses each token x_t through a down-projection matrix W_DKV in R^(d_model x d_c) into a shared low-rank latent vector c_t^KV = x_t W_DKV of dimension d_c << n_q * d_h (for example, d_c = 512 versus n_q * d_h = 4,096). From that single latent vector, up-projection matrices W_UK, W_UV in R^(d_c x (n_q * d_h)) reconstruct all n_q content key heads k_t^C = c_t^KV W_UK and value heads v_t = c_t^KV W_UV.

Why does MLA also need a separate decoupled RoPE key k_t^R? As you will see in Stepper 2 (Station 7), MLA avoids caching the reconstructed k_t^C and v_t during inference by absorbing W_UK into W_Q: q_t^C (k_j^C)^T = (x_t W_Q W_UK^T) (c_j^KV)^T. However, Rotary Position Embedding (RoPE, D06) multiplies queries and keys by a position-dependent rotation matrix R_{t-j} between them: (x_t W_Q) R_{t-j} (W_UK^T (c_j^KV)^T). Because R_{t-j} depends on the relative token distance t - j, W_Q R_{t-j} W_UK^T is not a constant matrix and cannot be pre-multiplied! MLA solves this cleanly by splitting each query and key into a non-positional content part (q_t^C, k_t^C of width d_h, where W_UK absorbs into W_Q) and a small positional RoPE part: per-head RoPE queries q_{t,h}^R of width d_r = 64 and a single shared RoPE key k_t^R = RoPE(x_t W_KR) of width d_r = 64 broadcast across all heads. The KV cache stores only (c_t^KV, k_t^R), which is d_c + d_r = 512 + 64 = 576 floats per layer per token.

c_KV = X @ W_DKV                         # cached compressed latent: (B, T, d_c = 512)
k^R  = RoPE(X @ W_KR)                    # cached shared RoPE key:   (B, 1, T, d_r = 64)
Score(i, j, head h) = (q_{i,h}^C . k_{j,h}^C  +  q_{i,h}^R . k_j^R) / sqrt(d_h + d_r)
Cached floats/layer/token = d_c + d_r = 576  (equivalent to 576 / (2 * 128) = 2.25 KV heads!)
Check: how many standard GQA KV heads (with d_h = 128) is MLA's 576-float per-layer cache equivalent to, and why isn't that an integer?
One standard KV head stores 2 * d_h = 256 floats per layer (128 for K and 128 for V). MLA stores d_c + d_r = 512 + 64 = 576 floats per layer, which equals 576 / 256 = 2.25 KV heads (or 9 / 4 KV heads). It is not an integer because MLA caches a single shared latent vector plus a 64-dim RoPE key rather than discrete K and V head pairs.

"""D05 Multi-head attention variants kata: MHA, GQA, MQA, and MLA shapes, params, and KV cache."""
import math, random

random.seed(11)
B, T, D_MODEL = 2, 6, 64
N_Q, D_H = 8, 8  # N_Q * D_H = 64

def rand_mat(r, c, s):
    return [[random.gauss(0.0, s) for _ in range(c)] for _ in range(r)]

def matmul(A, B):
    return [[sum(a * b for a, b in zip(row, col)) for col in zip(*B)] for row in A]

def transpose(M):
    return [list(col) for col in zip(*M)]

X = [rand_mat(T, D_MODEL, 1.0) for _ in range(B)]  # shape (B, T, D_MODEL)

def attend_heads(Q_heads, K_heads, V_heads):
    # Q_heads, K_heads, V_heads: (B, N_Q, T, d_qk / d_v)
    d_qk = len(Q_heads[0][0][0])
    d_v = len(V_heads[0][0][0])
    scale = 1.0 / math.sqrt(d_qk)
    concat_out = [[[0.0] * (N_Q * d_v) for _ in range(T)] for _ in range(B)]
    for b in range(B):
        for h in range(N_Q):
            Q_bh, K_bh, V_bh = Q_heads[b][h], K_heads[b][h], V_heads[b][h]
            raw = matmul(Q_bh, transpose(K_bh))
            A = []
            for i in range(T):
                scores = [(-1e9 if j > i else raw[i][j] * scale) for j in range(T)]
                m = max(scores)
                ex = [math.exp(x - m) for x in scores]
                s = sum(ex)
                A.append([e / s for e in ex])
            out_bh = matmul(A, V_bh)  # (T, d_v)
            for t in range(T):
                concat_out[b][t][h * d_v : (h + 1) * d_v] = out_bh[t]
    return concat_out

def split_heads(M_bt, n_heads, d_head):
    # M_bt: (B, T, n_heads * d_head) -> (B, n_heads, T, d_head)
    return [[[M_bt[b][t][h * d_head : (h + 1) * d_head] for t in range(T)] for h in range(n_heads)] for b in range(B)]

def run_gqa_family(X_in, n_kv, wrong_tile=False):
    random.seed(20 + n_kv)
    g = N_Q // n_kv
    s = 1.0 / math.sqrt(D_MODEL)
    W_Q = rand_mat(D_MODEL, N_Q * D_H, s)
    W_K = rand_mat(D_MODEL, n_kv * D_H, s)
    W_V = rand_mat(D_MODEL, n_kv * D_H, s)
    W_O = rand_mat(N_Q * D_H, D_MODEL, s)

    Q = split_heads([matmul(X_in[b], W_Q) for b in range(B)], N_Q, D_H)
    K_kv = split_heads([matmul(X_in[b], W_K) for b in range(B)], n_kv, D_H)
    V_kv = split_heads([matmul(X_in[b], W_V) for b in range(B)], n_kv, D_H)

    # Expand K_kv, V_kv from n_kv heads to N_Q heads
    if not wrong_tile:
        # Correct repeat_kv: head h maps to KV group h // g -> [0,0,0,0, 1,1,1,1]
        K = [[K_kv[b][h // g] for h in range(N_Q)] for b in range(B)]
        V = [[V_kv[b][h // g] for h in range(N_Q)] for b in range(B)]
    else:
        # Buggy tile: head h maps to h % n_kv -> [0,1,0,1, 0,1,0,1]
        K = [[K_kv[b][h % n_kv] for h in range(N_Q)] for b in range(B)]
        V = [[V_kv[b][h % n_kv] for h in range(N_Q)] for b in range(B)]

    concat = attend_heads(Q, K, V)
    out = [matmul(concat[b], W_O) for b in range(B)]
    return out, (B, n_kv, T, D_H), 2 * n_kv * D_H

def run_mla(X_in, d_c=16, d_r=4):
    random.seed(99)
    s_m, s_c = 1.0 / math.sqrt(D_MODEL), 1.0 / math.sqrt(d_c)
    W_DKV = rand_mat(D_MODEL, d_c, s_m)
    W_UK = rand_mat(d_c, N_Q * D_H, s_c)
    W_UV = rand_mat(d_c, N_Q * D_H, s_c)
    W_Q = rand_mat(D_MODEL, N_Q * D_H, s_m)
    W_QR = rand_mat(D_MODEL, N_Q * d_r, s_m)
    W_KR = rand_mat(D_MODEL, d_r, s_m)
    W_O = rand_mat(N_Q * D_H, D_MODEL, s_m)

    c_KV = [matmul(X_in[b], W_DKV) for b in range(B)]          # cached latent: (B, T, d_c)
    k_R = [matmul(X_in[b], W_KR) for b in range(B)]            # cached RoPE key: (B, T, d_r)
    q_C = split_heads([matmul(X_in[b], W_Q) for b in range(B)], N_Q, D_H)
    q_R = split_heads([matmul(X_in[b], W_QR) for b in range(B)], N_Q, d_r)
    k_C = split_heads([matmul(c_KV[b], W_UK) for b in range(B)], N_Q, D_H)
    V = split_heads([matmul(c_KV[b], W_UV) for b in range(B)], N_Q, D_H)

    Q_full = [[[q_C[b][h][t] + q_R[b][h][t] for t in range(T)] for h in range(N_Q)] for b in range(B)]
    K_full = [[[k_C[b][h][t] + k_R[b][t] for t in range(T)] for h in range(N_Q)] for b in range(B)]
    concat = attend_heads(Q_full, K_full, V)
    out = [matmul(concat[b], W_O) for b in range(B)]

    # Verify weight absorption for head 0: q_C0 @ k_C0^T == (X @ (W_Q0 @ W_UK0^T)) @ c_KV^T
    W_Q0 = [row[:D_H] for row in W_Q]
    W_UK0 = [row[:D_H] for row in W_UK]
    W_abs = matmul(W_Q0, transpose(W_UK0))                     # (D_MODEL, d_c) absorbed matrix
    s_direct = matmul(q_C[0][0], transpose(k_C[0][0]))
    s_absorb = matmul(matmul(X_in[0], W_abs), transpose(c_KV[0]))
    max_err = max(abs(s_direct[i][j] - s_absorb[i][j]) for i in range(T) for j in range(T))
    return out, (B, T, d_c), (B, 1, T, d_r), d_c + d_r, max_err

out_mha, sh_mha, fl_mha = run_gqa_family(X, n_kv=8)
out_gqa, sh_gqa, fl_gqa = run_gqa_family(X, n_kv=2)
out_bug, _, _ = run_gqa_family(X, n_kv=2, wrong_tile=True)
out_mqa, sh_mqa, fl_mqa = run_gqa_family(X, n_kv=1)
out_mla, sh_ckv, sh_kr, fl_mla, abs_err = run_mla(X, d_c=16, d_r=4)

gqa_bug_diff = max(abs(out_gqa[b][t][d] - out_bug[b][t][d]) for b in range(B) for t in range(T) for d in range(D_MODEL))
print("=== 1. Forward pass & cached tensor shapes (B=2, T=6, d_model=64, n_q=8, d_h=8) ===")
print(f"MHA   (n_kv=8) out: ({B}, {T}, {D_MODEL}) | cached K,V shape each: {sh_mha} -> {fl_mha:3d} floats/tok")
print(f"GQA-4 (n_kv=2) out: ({B}, {T}, {D_MODEL}) | cached K,V shape each: {sh_gqa} -> {fl_gqa:3d} floats/tok")
print(f"MQA   (n_kv=1) out: ({B}, {T}, {D_MODEL}) | cached K,V shape each: {sh_mqa} -> {fl_mqa:3d} floats/tok")
print(f"MLA (dc=16,dr=4) out: ({B}, {T}, {D_MODEL}) | cached c_KV {sh_ckv} + k_R {sh_kr} -> {fl_mla:3d} floats/tok")
print(f"MLA matrix absorption max score diff (q_C @ k_C^T vs absorbed W_Q @ W_UK^T): {abs_err:.2e}")
print(f"GQA wrong head-group tiling (interleaved vs grouped repeat_kv) output diff:  {gqa_bug_diff:.4f}")

print("\n=== 2. Production scale audit: L=32, d=4096, n_q=32, d_h=128, S=32768, BF16 (2B) ===")
L, d, nq, dh, S = 32, 4096, 32, 128, 32768
configs = [

    ("GQA-4 (n_kv=8)",     2 * d * (nq * dh) + 2 * d * (8 * dh),  2 * 8 * dh),

    ("MLA (dc=512,dr=64)", d*(nq*dh) + d*512 + 512*(2*nq*dh) + d*64 + d*(nq*64) + (nq*dh)*d, 512 + 64),
]
for name, p_layer, kv_el in configs:
    p_m = (L * p_layer) / 1e6
    kv_kib = (L * kv_el * 2) / 1024

    print(f"{name:19s} | Attn params: {p_m:7.1f}M | KV/tok: {kv_kib:5.1f} KiB | KV @ 32k: {kv_gib:5.2f} GiB")

What to notice

  1. Identical external interface: all four variants accept input X of shape (2, 6, 64) and return output of shape (2, 6, 64), so residual stream connections, LayerNorm/RMSNorm, and MLPs outside the attention block do not change at all.
  2. Cached floats per token scale with KV representation: in the toy run (n_q = 8, d_h = 8), cached floats per token drop from 128 (MHA) to 32 (GQA-4) to 20 (MLA with d_c = 16, d_r = 4) to 16 (MQA).
  3. MLA matrix absorption is algebraically exact: computing content scores via absorbed weight (X @ (W_Q0 @ W_UK0^T)) @ c_KV^T matches explicit key reconstruction q_C0 @ k_C0^T to 4.88e-15 (IEEE 754 float64 machine precision).
  4. GQA head grouping order is critical: replacing contiguous head grouping h // g ([0,0,0,0, 1,1,1,1]) with modulo/interleaved tiling h % n_kv ([0,1,0,1, 0,1,0,1]) produces a massive 2.8578 output error on the exact same weights.
  5. Parameter savings accompany KV savings: in the 32-layer production audit, switching from MHA to GQA-4 saves 805.3M parameters (2,147.5M -> 1,342.2M, or 1.61 GB of BF16 weights) in addition to saving 12.00 GiB of KV cache at 32k context.

Interview

Say this aloud against the clock. Three levels, about 90 seconds.

1 Outcome 20 sMulti-head attention splits the residual stream into parallel subspaces so each token can route information from multiple context positions simultaneously. Variants like MQA, GQA, and MLA keep all query heads for expressivity while sharing or compressing keys and values to slash the KV-cache memory wall during decoding.
2 Mechanism 45 sIn standard MHA with n_q heads of width d_h, every query head has its own key and value head, so n_kv equals n_q. During decoding, reading that KV cache from HBM bottlenecks throughput. Multi-Query Attention sets n_kv to 1 so all query heads share one KV head. Grouped-Query Attention partitions n_q query heads into n_kv groups so g equals n_q over n_kv adjacent query heads share one KV head via contiguous repeat_kv broadcasting. Multi-head Latent Attention projects tokens into a single compressed latent vector c_KV plus a shared decoupled RoPE key k^R, and absorbs the up-projections W_UK into W_Q and W_UV into W_O at inference.
3 Internals and limits 25 sOn a 32-layer, 4096-wide model in BF16 at 32k context, MHA caches 512 KiB per token or 16 GiB total. GQA-4 with 8 KV heads cuts that 4x to 4 GiB, MQA cuts it 32x to 0.5 GiB, and MLA with a 512-dim latent and 64-dim RoPE key caches 36 KiB per token or 1.12 GiB - a 14.2x reduction while preserving full per-head rank.

Traps

Each one sounds right. Say what is wrong with it before you open it.

"Splitting a d_model = 4,096 attention layer into 32 heads multiplies the projection FLOPs and parameters by 32."
Each head projects into dimension d_h = d_model / n_q = 128, not 4,096. All 32 heads concatenated have total width 32 * 128 = 4,096, so the total parameters (4 * d_model^2) and total FLOPs are identical to a single head of width 4,096.
"GQA reduces prompt prefill FLOPs by 4x because there are 4x fewer KV heads."
GQA only shrinks the W_K and W_V projection matmuls. The query projection W_Q, output projection W_O, and all n_q = 32 attention score/value matmuls (Q @ K^T and A @ V) still run across all 32 query heads! GQA primarily saves HBM capacity and memory bandwidth during decode, not prefill attention FLOPs.
"In GQA inference, the serving engine calls repeat_interleave to copy the KV cache in GPU HBM from n_kv heads to n_q heads before running attention."
Copying the KV cache in HBM would waste the very memory capacity and HBM bandwidth GQA was designed to save. Production kernels (FlashAttention, PagedAttention) keep only n_kv heads in HBM and map query head h to KV head h // g on the fly in SRAM registers.
"In MLA, you can apply Rotary Position Embedding (RoPE) directly to the compressed latent vector c_KV and still absorb W_UK into W_Q."
RoPE inserts a relative-position rotation matrix R_{i-j} between query i and key j. Because R_{i-j} varies with every pair of positions (i, j), W_Q R_{i-j} W_UK^T cannot be pre-multiplied into a static weight matrix. That is why MLA must decouple RoPE into a separate small shared key k^R (d_r = 64).

Compare MHA, MQA, GQA, and MLA in 90 seconds.

Follow-upWhy does MHA need multiple heads at all if total width n_q * d_h equals d_model? A single softmax over T keys forces one convex combination per token; n_q heads give each token n_q independent softmax distributions so different heads can track syntax, coreference, and nearby tokens simultaneously.
What role does the output projection matrix W_O play in Multi-Head Attention, and what is its shape when n_q * d_h != d_model?
Each head writes into its own isolated d_h-dimensional slice of the concatenated vector. W_O has shape (n_q * d_v, d_model); it projects the concatenated head outputs back to the residual stream width d_model and linearly mixes features across all n_q heads.
Derive the attention parameter count per layer for GQA when d_model = 4,096, n_q = 32, n_kv = 8, and d_h = 128, and compare it to MHA.
In GQA, W_Q and W_O each have 4,096 * (32 * 128) = 16,777,216 parameters (33.55M together). W_K and W_V each have 4,096 * (8 * 128) = 4,194,304 parameters (8.39M together). Total per layer is 41.94M parameters (1,342.2M across 32 layers), compared to 67.11M per layer (2,147.5M across 32 layers) in MHA.
Follow-upWhere do model designers usually spend the parameter budget saved by switching from MHA to GQA? They widen the SwiGLU FFN intermediate dimension (D07) so total model parameter count stays constant while KV-cache memory drops by 4x.
Explain the bug that occurs if you broadcast GQA keys from (B, n_kv, T, d_h) to (B, n_q, T, d_h) using np.tile(K, (1, g, 1, 1)) instead of np.repeat(K, g, axis=1).
In GQA, adjacent query heads [g*k .. g*(k+1)-1] form group k and were trained against KV head k. np.repeat duplicates each head contiguously ([0,0,0,0, 1,1,1,1]), whereas np.tile alternates heads ([0,1,0,1, 0,1,0,1]), pairing 75% of query heads with the wrong KV subspace (causing a 2.8578 max error in the kata).
Walk through Ainslie et al.'s recipe for converting (uptraining) an existing pretrained MHA checkpoint into a GQA checkpoint.
Partition the n_q original K and V projection head matrices into n_kv contiguous groups of size g = n_q / n_kv. Mean-pool the g key projection matrices in each group into one new key head matrix, and mean-pool the g value projection matrices into one new value head matrix. Then continue pretraining (uptraining) for ~5% of original training tokens.
Follow-upWhy is mean-pooling the head weight matrices better than picking one head per group and discarding the other g - 1 heads? Mean-pooling preserves the average key and value subspace information from all g heads at step 0, giving much lower initial loss before uptraining.
Show the matrix algebra for how MLA absorbs W_UK into W_Q and W_UV into W_O during inference.
For head h, content key is k_j^C = c_j^KV W_UK^h and query is q_i^C = x_i W_Q^h. The dot product is q_i^C (k_j^C)^T = x_i (W_Q^h (W_UK^h)^T) (c_j^KV)^T, so defining W_Q_abs^h = W_Q^h (W_UK^h)^T in R^(d_model x d_c) lets the query dot directly with c_j^KV. Similarly, head output before W_O is (A_h V_h) W_O^h = (A_h c^KV) (W_UV^h W_O^h), so W_O_abs^h = W_UV^h W_O^h in R^(d_c x d_model).
Why does an MLA serving engine use unabsorbed weights during prompt prefill and absorbed weights during autoregressive decode?
During prefill, we do not read a large historical cache, and unabsorbed head dimension is small (d_h = 128), whereas absorbed queries and values have width d_c = 512 per head (4x more attention matrix FLOPs). Since prefill is compute-bound, unabsorbed d_h = 128 is faster; since decode is memory-bandwidth-bound, absorbed MQA over c_KV (512 floats shared across all heads) is much faster.
Follow-upIn absorbed MLA decode, what are the effective query head width and number of KV heads seen by the attention kernel? Each of the n_q query heads has width d_c + d_r = 512 + 64 = 576, and all of them attend to n_kv = 1 shared 576-dim KV cache tensor (an MQA kernel).
How does the number of KV heads n_kv constrain Tensor Parallelism (TP) across GPUs?
Standard Megatron-style Tensor Parallelism shards attention heads across TP GPUs so each GPU holds n_q / TP query heads and n_kv / TP KV heads. As long as n_kv >= TP (e.g., n_kv = 8 on 8 GPUs), each GPU gets at least 1 unique KV head. When n_kv < TP (e.g., MQA with n_kv = 1 on 8 GPUs), the KV head must be replicated across ranks.

Mixed review

Three questions from earlier topics. Nobody tells you the topic in an interview.

D04: why does scaled dot-product attention divide Q @ K^T by sqrt(d_k), and why must causal masks use -infinity before softmax instead of 0.0?
Dot products of unit-variance d_k-dimensional vectors have variance d_k and std sqrt(d_k); dividing by sqrt(d_k) keeps variance at 1.0 so softmax does not saturate and vanish gradients. Masking with 0.0 leaves exp(0) = 1.0 in softmax, leaking future weights, whereas exp(-inf) = 0.0.
K06: in our K06 pure-Python causal decoder kata (L = 2, d = 16, prompt = 16, gen = 64), how much speedup did KV caching achieve and what was the numerical difference between cached and uncached outputs?
KV caching achieved a 31.52x wall-clock speedup (31.54x fewer arithmetic operations, dropping from 10.42M to 0.33M ops) with an exact numerical difference of 0.00e+00 at a cost of 10,240 bytes of cache.
D03: why does Llama 3.2 1B tie its input embedding table W_E and output unembedding W_U while Llama 3.1 8B leaves them untied?
With V = 128,256, one embedding table is 262.7M params (0.53 GB bf16) at 1B (d = 2,048), so untying would consume 35.1% of the 1B model (tying cuts it to 21.3%). At 8B (d = 4,096), the second table is only ~6.5% of total parameters, so untying is affordable and improves perplexity.

Short notes

Quick-memorization cheat sheet covering every subtopic on this page and the key facts to remember cold.

All subtopics on this page

  • Multi-Head Attention (MHA): Splits d_model into n_q parallel heads of width d_h = d_model / n_q (n_kv = n_q) and mixes concatenated outputs via W_O; uses 4 * d_model^2 params/layer and caches 512.0 KiB/tok (16.00 GiB @ 32k) on a 32-layer 8B-scale model.
  • Multi-Query Attention (MQA): Shares a single KV head (n_kv = 1) across all n_q query heads, shrinking the 32-layer BF16 cache 32x to 16.0 KiB/tok (0.50 GiB @ 32k) and params to 1,107.3M at the cost of KV capacity and TP replication when TP > 1.
  • Grouped-Query Attention (GQA): Groups g = n_q / n_kv adjacent query heads per KV head via contiguous repeat_kv (h // g); GQA-4 (n_kv = 8, Llama-3-8B) uses 1,342.2M params and 128.0 KiB/tok (4.00 GiB @ 32k), while GQA-8 (n_kv = 4) uses 64.0 KiB/tok (2.00 GiB @ 32k).
  • Multi-head Latent Attention (MLA): Compresses KV into a shared latent c_KV = X W_DKV (d_c = 512) plus a shared decoupled RoPE key k^R (d_r = 64), caching 576 floats/layer = 36.0 KiB/tok (1.12 GiB @ 32k, 14.22x smaller than MHA, equivalent to 2.25 KV heads).
  • MLA weight absorption & decoupled RoPE: Absorbs W_UK into W_Q and W_UV into W_O during decode (4.88e-15 max diff in kata) so full K and V never materialize in HBM; RoPE must be decoupled because relative rotation R_{i-j} between Q and K breaks constant matrix associativity.
Important things to remember
  • KV cache formulas: Standard/GQA: 2 * L * n_kv * d_h * S * B * b bytes. MLA: L * (d_c + d_r) * S * B * b bytes. Memory hook: 32 - 8 - 1 - Latent (16.00 GiB -> 4.00 GiB -> 0.50 GiB -> 1.12 GiB at 32k).
  • repeat_kv bug: Always map query head h to KV head h // g (contiguous groups [0,0,0,0, 1,1,1,1]), never interleaved tiling h % n_kv (which gave 2.8578 output corruption in the kata), and never copy expanded KV into HBM during decode.
  • MHA-to-GQA uptraining: Mean-pool each group of g adjacent K and V head weight matrices and uptrain on ~5% of pretraining tokens.
  • MLA dual-kernel rule: Run unabsorbed projections during compute-bound prefill (d_h = 128 saves 4x attention FLOPs) and absorbed MQA projections during memory-bound decode (d_c + d_r = 576 saves 14.2x HBM reads).
