One token end to end

When you hand six prompt token IDs to a decoder-only transformer, what exact tensors, shapes, and matrix multiplications happen inside one forward pass to produce the seventh token? This page traces every stage from [B, S] integers through Pre-RMSNorm, Grouped-Query Attention, SwiGLU MLP, and the LM head to logits[:, -1, :]. Embedding geometry and weight tying belong to D03, sampling rules to D10, and prefill-versus-decode hardware arithmetic intensity to K05.

Before you read

Guess first. A wrong guess now makes the right answer stick later.

You pass a 6-token prompt of shape [1, 6] into a model with vocabulary V = 1,000. The LM head outputs a logit tensor of shape [1, 6, 1000]. Which slice predicts the 7th token, and what saves 6x of LM head compute at inference?
Only the final position logits[0, -1, :] (index 5, shape [1000]) predicts the unseen 7th token. Positions 0 through 4 predict prompt tokens 1 through 5, which you already know. Slicing the final normalized hidden state to x[:, -1:, :] (shape [1, 1, 64]) before multiplying by the LM head drops LM head compute in the kata from 768,000 FLOPs to 128,000 FLOPs, a 6.0x reduction.
In Layer 0 of our miniature model (B=1, S=6, d_model=64, d_ff=172, H=4, KVH=2), which costs more FLOPs: the entire Grouped-Query Attention block (Q, K, V projections, causal attention scores, and O projection combined) or the SwiGLU MLP?
The SwiGLU MLP costs 397,824 FLOPs per layer (mlp_gate_up 265,728 + mlp_down 132,096), which is 2.54x the entire attention block's 156,672 FLOPs (q_proj 49,152 + k_proj 24,576 + v_proj 24,576 + attn_scores 9,216 + o_proj 49,152). At short sequence lengths (S = 6 << d_model), dense channel mixing in the 3-matrix MLP dominates token-to-token mixing.
To match KVH = 2 key/value heads to H = 4 query heads in GQA, both np.repeat(k, 2, axis=2) and np.tile(k, (1, 1, 2, 1)) produce the exact shape (1, 6, 4, 16). Does np.tile raise a runtime error, or what happens?
No error is raised because the shapes are identical, but np.tile interleaves heads as [KV0, KV1, KV0, KV1] instead of [KV0, KV0, KV1, KV1]. Query heads 1 and 2 silently attend to the wrong KV head groups, shifting the final next-token logits by a max absolute delta of 0.357 (3.57e-01) in the kata.

The core idea

A decoder-only transformer is a shape-preserving residual pipeline sandwiched between two vocabulary translations. On entry, an embedding lookup converts integer token IDs [B, S] into a dense floating-point tensor [B, S, d_model], where B is batch size, S is sequence length, and d_model is the width of each token vector. That [B, S, d_model] tensor is the residual stream. Every transformer layer reads a normalized copy of the stream, computes an update across tokens (Grouped-Query Attention) or across channels within each token (SwiGLU MLP), and adds that update back into [B, S, d_model] with an elementwise +.

On exit, a final RMSNorm stabilizes the stream and the LM head multiplies [B, S, d_model] by [d_model, V] to score every vocabulary token at every position, producing logits of shape [B, S, V]. Because causal masking prevents position t from seeing any token after t, position S - 1 is the only slot that has read the entire prompt. You take logits[:, -1, :] of shape [B, V], turn it into probabilities with softmax, and pick the next token ID.

Mental model. Picture an assembly conveyor belt carrying S trays side by side, each holding d_model dials. No layer ever replaces a tray. Instead, each station photographs the trays through a normalizing lens (Pre-RMSNorm), runs either a cross-tray conference where tray t may only look left at trays 0..t (causal attention) or a private per-tray calculation (SwiGLU MLP), and stamps the resulting adjustments onto the original trays. At the end of the line, only tray S - 1 holds the summary of the whole belt, so only tray S - 1 is compared against the V vocabulary templates to emit the next token.

Memory hook

Remember E-A-M-N-L-S ("Every Attention Matrix Needs Last Slice"): Embed [B,S]->[B,S,d], Attend with causal GQA ([B,H,S,S]) + residual, MLP with SwiGLU ([B,S,d_ff]) + residual, Norm at the end, LM head to [B,S,V], and Slice logits[:, -1, :] to [B,V].

How it works

1. Embedding lookup and the Pre-RMSNorm residual stream

The input to a forward pass is an integer matrix ids of shape [B, S]. The embedding layer is a lookup table W_tok of shape [V, d_model]: integer ids[b, t] simply selects row ids[b, t] from W_tok, yielding [B, S, d_model] with zero matrix-multiply FLOPs. Position information enters either by adding a positional vector [S, d_model] (as in our miniature trace, costing B * S * d_model = 384 additions) or by rotating Q and K inside each attention layer with RoPE (covered in D06). Before each sublayer, Pre-RMSNorm normalizes each token's d_model vector by its root-mean-square without subtracting the mean:

RMSNorm(x) = (x / sqrt(mean(x^2, axis=-1, keepdims=True) + eps)) * gamma
x_next     = x + Sublayer(RMSNorm(x))   # x stays [B, S, d_model]

Here gamma is a learned scale vector of shape [d_model] (64 parameters in the kata) and eps (typically 1e-5) prevents division by zero. Because normalization sits on the branch input rather than the main highway, activations and gradients travel straight through the + nodes from layer 0 to layer L - 1.

2. Grouped-Query Attention (GQA) projections and head layout

From the normalized hidden state h of shape [B, S, d_model], three linear projections create Queries (Q), Keys (K), and Values (V). A full Multi-Head Attention (MHA) layer uses H heads of width d_head = d_model / H for all three. Grouped-Query Attention (GQA) keeps H query heads so each head can ask a distinct question, but shares KVH key and value heads across groups of g = H / KVH query heads to shrink KV projection weights and the KV cache (K06):

Q = (h @ W_q).reshape(B, S, H,   d_head)   # W_q: [d_model, H * d_head]
K = (h @ W_k).reshape(B, S, KVH, d_head)   # W_k: [d_model, KVH * d_head]
V = (h @ W_v).reshape(B, S, KVH, d_head)   # W_v: [d_model, KVH * d_head]
K_rep = np.repeat(K, H // KVH, axis=2)     # [KV0, KV0, KV1, KV1], NOT tile!

In the kata (d_model=64, H=4, KVH=2, d_head=16), W_q has 64 * 64 = 4,096 parameters and costs 2 * B * S * d_model * (H * d_head) = 49,152 FLOPs, whereas W_k and W_v each have 64 * 32 = 2,048 parameters and cost 24,576 FLOPs (half of W_q). To compute attention, each KV head must be repeated g = H // KVH = 2 times along the head axis with repeat_interleave (np.repeat), so query heads (0, 1) share KV0 and (2, 3) share KV1. Using tile produces [KV0, KV1, KV0, KV1], which has the identical (1, 6, 4, 16) shape but scrambles head pairings.

Check: in a model with H = 32 query heads, KVH = 8 key-value heads, and d_head = 128, what are the shapes of W_q, W_k, and W_v, and how many times is each KV head repeated?
d_model = 32 * 128 = 4,096. W_q has shape [4096, 4096], while W_k and W_v each have shape [4096, 1024] (8 * 128 = 1,024, a 4x reduction). Each KV head is repeated g = 32 / 8 = 4 times via repeat_interleave so groups of 4 query heads share one KV head.

3. Causal attention scores and value aggregation

After transposing head and sequence axes to [B, H, S, d_head], each head computes all-pairs dot products between queries and keys, scaled by 1 / sqrt(d_head) so variance stays near 1.0 instead of growing with d_head (which would push softmax into flat, zero-gradient saturation):

scores = (Q_t @ K_t.transpose(0, 1, 3, 2)) / sqrt(d_head)   # [B, H, S, S]
scores = scores + triu(-1e9, k=1)                           # mask j > i BEFORE softmax
probs  = softmax(scores, axis=-1)                           # rows sum to 1.0
out    = (probs @ V_t).transpose(0, 2, 1, 3).reshape(B, S, d_model) @ W_o

In row i of scores, column j measures how much token i attends to token j. Adding -inf (or -1e9) to all upper-triangular entries j > i before softmax guarantees exp(-1e9) = 0.0, so token i distributes 100% of its probability mass across past and present tokens 0..i. In the kata, modifying token 5 changes token 2's output by 0.00e+00 when masked, but leaks a 1.34e-01 change into token 2 when the causal mask is omitted. Multiplying probs @ V_t costs 2 * B * H * S^2 * d_head FLOPs (so Q @ K^T and probs @ V together cost 4 * B * H * S^2 * d_head = 9,216 FLOPs in Layer 0), after which the heads are concatenated back to [B, S, d_model] and mixed by W_o ([d_model, d_model]).

4. SwiGLU MLP: three matrices per token

Attention mixes information across token positions S; the MLP mixes channels independently inside each token position. Modern Llama-family models replace the classic two-matrix ReLU/GELU MLP with SwiGLU, which uses three matrices (W_gate and W_up of shape [d_model, d_ff], and W_down of shape [d_ff, d_model]):

gate = h2 @ W_gate                      # [B, S, d_ff], 2*B*S*d_model*d_ff FLOPs
up   = h2 @ W_up                        # [B, S, d_ff], 2*B*S*d_model*d_ff FLOPs
act  = (gate * sigmoid(gate)) * up      # SiLU(gate) * up, elementwise [B, S, d_ff]
down = act @ W_down                     # [B, S, d_model], 2*B*S*d_model*d_ff FLOPs

Because SwiGLU uses three d_model * d_ff matrices instead of two, setting d_ff = (8 / 3) * d_model (rounded to a hardware multiple, such as 172 for d_model = 64 or 14,336 for d_model = 4,096 in Llama 3 8B) keeps parameter count and FLOPs (6 * B * S * d_model * d_ff) roughly equal to a classic d_ff = 4 * d_model two-matrix MLP (2 * 4 = 8 vs 3 * 8/3 = 8).

Check: why must the causal mask add -inf before softmax rather than multiplying the post-softmax matrix by a lower-triangular 0/1 mask?
If you zero out upper-triangular entries after softmax, the remaining entries in each row no longer sum to 1.0, and their denominator sum_j exp(s_ij) still depended on future tokens j > i. That both distorts output scale and leaks future token magnitudes into earlier positions.

5. Final RMSNorm, LM head unembedding, and the logits[:, -1, :] slice

After all L layers finish updating the residual stream, one last final_norm (RMSNorm) scales [B, S, d_model]. The LM head (W_lm of shape [d_model, V]) projects hidden states into vocabulary space. During training, you multiply the full [B, S, d_model] tensor by W_lm to get [B, S, V] because cross-entropy loss grades all S next-token predictions simultaneously. During inference, you already have prompt tokens 0..S-1 and only want token S, which is predicted at index S - 1 (logits[:, -1, :]). Slicing the normalized hidden state to xn[:, -1:, :] ([B, 1, d_model]) before W_lm avoids (S - 1) wasted vocabulary projections.

Check: write the per-layer matmul FLOP formulas for (a) GQA Q, K, V, O projections, (b) causal attention scores + value weighted sum, and (c) the SwiGLU MLP.
(a) Q and O each cost 2 * B * S * d_model^2, while K and V each cost 2 * B * S * d_model * (KVH * d_head), totaling 4 * B * S * d_model^2 * (1 + KVH / H). (b) Q @ K^T and probs @ V each cost 2 * B * H * S^2 * d_head, totaling 4 * B * S^2 * d_model. (c) Three matrices (gate, up, down) each cost 2 * B * S * d_model * d_ff, totaling 6 * B * S * d_model * d_ff.

Kata: hook every stage of one forward pass

This self-contained NumPy script builds a 2-layer Llama-style decoder-only model (B=1, S=6, V=1000, d_model=64, H=4, KVH=2, d_head=16, d_ff=172), attaches a stage hook to every operation in the forward pass, prints the exact output shapes, parameter counts, and FLOPs, extracts the top-5 next-token predictions at logits[0, -1, :], and runs three break-it checks.

"""One token end to end: forward pass trace with stage hooks. Run: python kata.py"""
import argparse, numpy as np

ap = argparse.ArgumentParser()
ap.add_argument("--no-causal-mask", action="store_true", help="omit causal mask in attention")
ap.add_argument("--bad-gqa-order", action="store_true", help="tile KV heads instead of repeat_interleave")
ap.add_argument("--last-only-head", action="store_true", help="project only the final token at lm_head")
args = ap.parse_args()

B, S, V, D, L, H, KVH, Dh, Dff = 1, 6, 1000, 64, 2, 4, 2, 16, 172

def init_weights(seed=42):
    rng = np.random.default_rng(seed)
    r = lambda *sh: rng.normal(0.0, 0.02, size=sh).astype(np.float32)
    w = {"tok": r(V, D), "pos": r(S, D), "final_norm": np.ones(D, dtype=np.float32), "lm_head": r(D, V)}
    for l in range(L):
        w[f"l{l}"] = {"rms1": np.ones(D, np.float32), "rms2": np.ones(D, np.float32),
                      "wq": r(D, H * Dh), "wk": r(D, KVH * Dh), "wv": r(D, KVH * Dh),
                      "wo": r(H * Dh, D), "wgate": r(D, Dff), "wup": r(D, Dff), "wdown": r(Dff, D)}
    return w

def rmsnorm(x, g, eps=1e-5):
    return (x / np.sqrt(np.mean(x * x, axis=-1, keepdims=True) + eps)) * g

def forward(ids, w, hooks=None, causal=True, bad_gqa=False, last_only_head=False):
    rec = lambda name, t, p, f: hooks.append((name, t.shape, p, f)) if hooks is not None else None
    b, s = ids.shape
    x = w["tok"][ids] + w["pos"][:s]
    rec("embed", x, V * D + S * D, b * s * D)
    for l in range(L):
        lw, tag = w[f"l{l}"], (lambda n: n if l == 0 else None)
        h = rmsnorm(x, lw["rms1"])
        if l == 0: rec("rms_1", h, D, 4 * b * s * D)
        q = (h @ lw["wq"]).reshape(b, s, H, Dh)
        k = (h @ lw["wk"]).reshape(b, s, KVH, Dh)
        v = (h @ lw["wv"]).reshape(b, s, KVH, Dh)
        if l == 0:
            rec("q_proj", q, D * H * Dh, 2 * b * s * D * H * Dh)
            rec("k_proj", k, D * KVH * Dh, 2 * b * s * D * KVH * Dh)
            rec("v_proj", v, D * KVH * Dh, 2 * b * s * D * KVH * Dh)
        rep = H // KVH
        kr = np.tile(k, (1, 1, rep, 1)) if bad_gqa else np.repeat(k, rep, axis=2)
        vr = np.tile(v, (1, 1, rep, 1)) if bad_gqa else np.repeat(v, rep, axis=2)
        qt, kt, vt = q.transpose(0, 2, 1, 3), kr.transpose(0, 2, 1, 3), vr.transpose(0, 2, 1, 3)
        scores = (qt @ kt.transpose(0, 1, 3, 2)) / np.sqrt(Dh)
        if causal:
            scores = scores + np.triu(np.full((s, s), -1e9, np.float32), k=1)
        probs = np.exp(scores - scores.max(axis=-1, keepdims=True))
        probs = probs / probs.sum(axis=-1, keepdims=True)
        if l == 0: rec("attn_scores", probs, 0, 4 * b * H * s * s * Dh)
        attn_out = (probs @ vt).transpose(0, 2, 1, 3).reshape(b, s, D) @ lw["wo"]
        if l == 0: rec("o_proj", attn_out, H * Dh * D, 2 * b * s * H * Dh * D)
        x = x + attn_out
        if l == 0: rec("resid_1", x, 0, b * s * D)
        h2 = rmsnorm(x, lw["rms2"])
        gate = h2 @ lw["wgate"]
        up = h2 @ lw["wup"]
        act = (gate / (1.0 + np.exp(-gate))) * up
        if l == 0: rec("mlp_gate_up", act, D + 2 * D * Dff, 4 * b * s * D + 4 * b * s * D * Dff)
        down = act @ lw["wdown"]
        if l == 0: rec("mlp_down", down, Dff * D, 2 * b * s * Dff * D)
        x = x + down
        if l == 0: rec("resid_2", x, 0, b * s * D)
    xn = rmsnorm(x, w["final_norm"])
    rec("final_norm", xn, D, 4 * b * s * D)
    x_head = xn[:, -1:, :] if last_only_head else xn
    logits = x_head @ w["lm_head"]
    rec("lm_head", logits, D * V, 2 * b * x_head.shape[1] * D * V)
    return logits

w, ids = init_weights(), np.array([[101, 245, 512, 88, 734, 319]])
hooks = []
logits = forward(ids, w, hooks, causal=not args.no_causal_mask, bad_gqa=args.bad_gqa_order, last_only_head=args.last_only_head)
print(f"Model: B={B}, S={S}, V={V}, d_model={D}, layers={L}, H={H}, KVH={KVH}, d_head={Dh}, d_ff={Dff}")
print(f"\n{'Stage (L0 + heads)':<18} {'Output shape':<18} {'Params':>10} {'FLOPs':>12}")
print("-" * 62)
l0_p = l0_f = 0
for name, sh, p, f in hooks:
    print(f"{name:<18} {str(sh):<18} {p:>10,} {f:>12,}")
    if name not in ("embed", "final_norm", "lm_head"): l0_p += p; l0_f += f
tot_p = hooks[0][2] + L * l0_p + hooks[-2][2] + hooks[-1][2]
tot_f = hooks[0][3] + L * l0_f + hooks[-2][3] + hooks[-1][3]
print("-" * 62)
print(f"{'Total (2 layers)':<18} {'logits->(1, 1000)':<18} {tot_p:>10,} {tot_f:>12,}")

last = logits[0, -1, :]
e = np.exp(last - last.max()); probs = e / e.sum()
top5 = np.argsort(-last)[:5]
print("\nNext-token prediction from logits[0, -1, :] (position S-1 = 5):")
for rank, tid in enumerate(top5, 1):
    print(f"  #{rank}: token_id={tid:<4d} logit={last[tid]:+.5f}  prob={probs[tid]:.5f}")

ids_alt = ids.copy(); ids_alt[0, 5] = 999
diff_masked = np.max(np.abs(forward(ids, w)[:, 2, :] - forward(ids_alt, w)[:, 2, :]))
diff_unmask = np.max(np.abs(forward(ids, w, causal=False)[:, 2, :] - forward(ids_alt, w, causal=False)[:, 2, :]))
diff_gqa = np.max(np.abs(last - forward(ids, w, bad_gqa=True)[0, -1, :]))
_, _, _, f_full = [h for h in hooks if h[0] == "lm_head"][0]
h_last = []; forward(ids, w, h_last, last_only_head=True)
_, sh_last, _, f_last = [h for h in h_last if h[0] == "lm_head"][0]
print("\nBreak-it checks:")
print(f"  1. Causal mask check (change token 5, measure max |delta| at token 2): masked={diff_masked:.2e}, unmasked={diff_unmask:.2e}")
print(f"  2. GQA KV repeat check (np.repeat vs np.tile max |delta| at pos S-1):  delta={diff_gqa:.2e}")
print(f"  3. LM head slice: full [1,6,1000] FLOPs={f_full:,} vs last-only {sh_last} FLOPs={f_last:,} ({f_full/f_last:.1f}x)")

What to notice

  1. The residual spine never changes shape. embed, rms_1, o_proj, resid_1, mlp_down, resid_2, and final_norm all emit (1, 6, 64). Attention temporarily reshapes to (1, 6, 4, 16) and (1, 4, 6, 6), and the MLP expands to (1, 6, 172), before returning to (1, 6, 64).
  2. Embedding lookup is parameter-heavy, FLOP-light. embed holds 64,384 parameters (29.4% of the 219,328-parameter model) yet performs only 384 FLOPs (adding positional vectors to row lookups).
  3. GQA halves K and V projection cost. In Layer 0, q_proj has 4,096 parameters and 49,152 FLOPs for 4 heads, while k_proj and v_proj each have 2,048 parameters and 24,576 FLOPs for 2 KV heads.
  4. At short S, MLP beats attention 2.54x. One layer's SwiGLU MLP costs 265,728 + 132,096 = 397,824 FLOPs, whereas all attention projections plus the [1, 4, 6, 6] score matrix cost 156,672 FLOPs (9,216 of which is the S x S score core).
  5. Computing all S logits wastes 640,000 FLOPs. Projecting [1, 6, 64] @ [64, 1000] costs 768,000 FLOPs (40.8% of the entire 2-layer pass), even though next-token decoding only reads logits[0, -1, :] (token_id=694, logit=+0.50892). Slicing to (1, 1, 64) first drops lm_head to 128,000 FLOPs.

Say this aloud against the clock. Three levels, about 90 seconds.

1 Outcome 20 sOne decoder-only forward pass takes a batch of integer token IDs of shape [B, S] and produces a next-token probability distribution over vocabulary V from the final position logits[:, -1, :]. Inside the model, a residual stream of fixed shape [B, S, d_model] carries every token's state from embedding to unembedding while layers add contextual and channel updates.
2 Mechanism 45 sFirst, an embedding table lookup maps [B, S] to [B, S, d_model]. Each of the L layers runs two residual sub-blocks with Pre-RMSNorm. The first is Grouped-Query Attention: h projects into H query heads [B, S, H, d_head] and KVH key-value heads, KV heads repeat in contiguous blocks to match H, scaled dot products Q @ K^T / sqrt(d_head) form [B, H, S, S], an upper-triangular -inf mask blocks future tokens before softmax, and probs @ V projects via W_o back onto the residual stream. The second is a SwiGLU MLP that expands d_model to d_ff through gate and up projections, multiplies SiLU(gate) * up, and projects down to [B, S, d_model].
3 Internals and limits 25 sFinally, RMSNorm and the LM head [d_model, V] produce logits. Only index S - 1 predicts token S, so slicing x[:, -1:, :] before the LM head cuts its 2*B*S*d_model*V FLOPs and memory by S-fold. Watch for GQA tile bugs and missing causal masks.

Question: what happens at the end of a transformer forward pass to get the next token, and where do engineers accidentally waste memory?

"At the end of the transformer, the final layer outputs embeddings for the words, and a classification layer with softmax predicts the most likely next word."

Traps

Each one sounds right. Say what is wrong with it before you open it.

"The embedding layer multiplies a one-hot vector [B, S, V] by W_tok [V, d_model], so it costs 2 * B * S * V * d_model FLOPs just like the LM head."
Mathematically it is equivalent to a one-hot matmul, but in hardware and code it is an array gather (W_tok[ids]) that copies B * S rows of length d_model with zero matrix-multiply FLOPs. Only the LM head at the output performs the dense 2 * B * S * d_model * V matrix multiplication.
"In a forward pass on a 6-token prompt, the attention layer collapses the 6 tokens into a single [B, 1, d_model] summary vector for the MLP."
No layer ever collapses the sequence dimension S. Every sublayer takes [B, S, d_model] and returns [B, S, d_model]. All S tokens travel in parallel through all L layers; the sequence length only reduces to 1 if you explicitly slice x[:, -1:, :] right before the LM head.
"To apply a causal mask in attention, you compute probs = softmax(Q @ K^T / sqrt(d_head)) and then zero out the upper triangle where j > i."
Zeroing after softmax leaves rows summing to less than 1.0 and leaks future tokens through the softmax denominator sum_j exp(s_ij). You must add -inf (or -1e9) to j > i BEFORE softmax so exp(-inf) = 0 and each row normalizes cleanly over j <= i.
"Attention is always the largest FLOP cost in a transformer forward pass because it is quadratic in sequence length."
The S x S attention score core costs 4 * B * S^2 * d_model FLOPs per layer, while QKVO projections plus the SwiGLU MLP cost B * S * (4 * d_model^2 * (1 + KVH/H) + 6 * d_model * d_ff). Whenever S is much smaller than d_model (in the kata S = 6 vs d_model = 64; in Llama 3 8B up to several thousand tokens), linear projections and the SwiGLU MLP dominate total FLOPs.

Question bank

Walk me through one forward pass of a Llama-style transformer from token IDs [B, S] to the next token, naming the tensor shape at every stage.
Start with ids [B, S]. Embedding lookup W_tok[ids] creates the residual stream x [B, S, d_model]. In each of L layers: (1) h = RMSNorm(x) [B, S, d_model]; (2) Q projects to [B, S, H, d_head] and K, V to [B, S, KVH, d_head], KV heads repeat_interleave to H, transpose to [B, H, S, d_head], Q @ K^T / sqrt(d_head) plus causal -inf mask and softmax yields probs [B, H, S, S], probs @ V reshapes to [B, S, d_model], o_proj maps to [B, S, d_model], and x = x + attn_out; (3) h2 = RMSNorm(x), SwiGLU computes (SiLU(h2 @ W_gate) * (h2 @ W_up)) @ W_down expanding to [B, S, d_ff] and returning [B, S, d_model], added to x. After L layers, final_norm keeps [B, S, d_model], slicing x[:, -1:, :] gives [B, 1, d_model], and lm_head [d_model, V] produces [B, 1, V] logits for next-token selection.
Follow-upWhy does d_head satisfy H * d_head = d_model? So that concatenating all H head outputs of width d_head along the last axis restores the exact d_model width required by W_o and the residual stream.
Why do we only read logits[:, -1, :] during inference, and what do positions 0 through S - 2 represent?
Because of causal masking, row i of the output has attended only to tokens 0..i and predicts token i + 1. Positions 0..S-2 predict prompt tokens 1..S-1, which the user already supplied. Only position S - 1 has conditioned on the entire prompt 0..S-1 to predict the unknown next token S.
Follow-upWhen during inference DO you actually need logits[:, 0:S-1, :]? When scoring the log-probability or perplexity of a prompt, or during speculative decoding verification where a single target pass verifies K draft tokens in positions S-K..S-1.
How does Grouped-Query Attention (GQA) differ from Multi-Head Attention (MHA) and Multi-Query Attention (MQA) in shapes and parameter counts?
All three project Q to [B, S, H, d_head] with d_model * (H * d_head) parameters. MHA uses KVH = H key and value heads; MQA uses KVH = 1 shared across all H query heads; GQA uses an intermediate KVH (such as 8 for H = 32), shrinking W_k, W_v, and the KV cache by H / KVH while preserving multiple KV subspaces.
Follow-upHow must KV heads be expanded to match H query heads before Q @ K^T? Each KV head must be repeated g = H // KVH times in contiguous blocks (repeat_interleave, yielding [KV0, KV0, KV1, KV1]) so query heads in the same group share their assigned KV head.
Why do we divide Q @ K^T by sqrt(d_head) before softmax?
If components of Q and K have zero mean and unit variance, their dot product over d_head dimensions has mean 0 and variance d_head. For large d_head (such as 128), unscaled dot products take large positive and negative values, pushing softmax into one-hot saturation where gradients vanish. Dividing by sqrt(d_head) restores unit variance.
Write the formula for RMSNorm, count its trainable parameters, and explain why Llama uses Pre-RMSNorm instead of Post-LayerNorm.
RMSNorm(x) = (x / sqrt(mean(x^2, axis=-1, keepdims=True) + eps)) * gamma. It has d_model trainable parameters (the scale vector gamma, with no bias beta and no mean subtraction). Pre-RMSNorm normalizes only the branch input x + Sublayer(RMSNorm(x)), leaving an unobstructed identity path on the residual stream so deep networks train stably without warmup spikes.
Explain the SwiGLU MLP equation, why it has three matrices instead of two, and why d_ff is roughly 8/3 * d_model.
SwiGLU(h) = (SiLU(h @ W_gate) * (h @ W_up)) @ W_down, where SiLU(z) = z * sigmoid(z). It uses two [d_model, d_ff] matrices (W_gate, W_up) and one [d_ff, d_model] matrix (W_down), costing 6 * B * S * d_model * d_ff FLOPs. Choosing d_ff = 8/3 * d_model makes 3 * d_model * d_ff = 8 * d_model^2, matching the parameter and FLOP budget of a classic 2-matrix MLP with d_ff = 4 * d_model.
Follow-upHow do inference engines optimize W_gate and W_up? They concatenate them into a single [d_model, 2 * d_ff] matrix so h is read from memory once and multiplied in a single larger GEMM before splitting into gate and up.
In our kata (B=1, S=6, d_model=64, d_ff=172, H=4, KVH=2, V=1000), verify the exact FLOP counts for q_proj, k_proj, attn_scores, mlp_down, and lm_head.
q_proj: 2 * 1 * 6 * 64 * 64 = 49,152. k_proj: 2 * 1 * 6 * 64 * 32 = 24,576. attn_scores (Q@K^T + P@V): 4 * 1 * 4 * 6 * 6 * 16 = 9,216. mlp_down: 2 * 1 * 6 * 172 * 64 = 132,096. lm_head (full): 2 * 1 * 6 * 64 * 1000 = 768,000 (or 128,000 when sliced to [1, 1, 64]).
How would you write a 3-line unit test to prove a custom attention kernel enforces causality?
Run the forward pass on ids, clone ids and modify the final token ids_alt[:, -1] = new_id, run the forward pass on ids_alt, and assert np.max(np.abs(out[:, :-1, :] - out_alt[:, :-1, :])) == 0 (up to floating-point tolerance 1e-6). In the kata, this delta is 0.00e+00 with the mask and 1.34e-01 without it.
Where in the forward pass does vocabulary size V affect compute and memory, and how does Llama 3's V = 128,256 change that stage?
V appears at embed ([V, d_model] lookup table, 0 matmul FLOPs) and lm_head ([d_model, V] projection, 2 * B * d_model * V FLOPs per scored token). At d_model = 4,096 and V = 128,256, W_lm holds 525M parameters (1.05 GB in bf16) and costs 1.05 GFLOPs per generated token, or 17.2 TFLOPs and 8.4 GB of bf16 logits if wastefully applied to all S = 16,384 prefill tokens.
Follow-upWhy does the transformer body (L layers) have zero dependence on V? Because embed immediately projects any vocabulary size V into the fixed channel width d_model, and all attention and MLP layers operate strictly on d_model, d_head, and d_ff.
At what sequence length S does the per-layer quadratic attention core (4 * B * S^2 * d_model) overtake the per-layer GQA projections + SwiGLU MLP in our kata (d_model=64, d_ff=172, H=4, KVH=2)?
In Layer 0 at S = 6, QKVO projections (147,456) + MLP (397,824) = 545,280 FLOPs, which is 90,880 * S FLOPs. The quadratic attention core is 4 * S^2 * 64 = 256 * S^2 FLOPs. Setting 256 * S^2 = 90,880 * S gives S = 90,880 / 256 = 355 tokens. Below S = 355, linear weights dominate; above S = 355, the S x S attention matrix dominates.

Mixed review

Three questions from earlier topics. Nobody tells you the topic in an interview.

D02: Why does a byte-level BPE tokenizer trained mostly on English charge 4x to 5x more tokens for Telugu or Hindi, and how does that directly affect the forward pass you traced in K04?
Indic characters take 3 UTF-8 bytes and earn few merges when the training corpus is English-dominated, inflating sequence length S by 4x to 5x for the same sentence. In the K04 forward pass, a 4x larger S multiplies all projection and MLP FLOPs (O(S)) by 4x and multiplies the S x S causal attention score matrix (O(S^2)) by 16x.
K03: When you call an LLM server with temperature = 0 vs temperature = 1.0, what changes inside the forward pass you traced in K04?
Nothing changes inside the forward pass from embed through lm_head: the exact same logits[:, -1, :] vector [B, V] is computed. Temperature only scales logits[:, -1, :] / T after lm_head (or selects argmax(logits[:, -1, :]) at T = 0), so the forward pass itself is 100% identical.
A02: Why do we subtract max(scores, axis=-1, keepdims=True) before calling np.exp(scores) in both the causal attention softmax and the next-token probability calculation?
Subtracting a constant c from every element of a vector leaves softmax unchanged because exp(z_i - c) / sum_j exp(z_j - c) = exp(z_i) / sum_j exp(z_j). Setting c = max(z) makes the largest exponent 0 (exp(0) = 1.0), which prevents exp(z_i) from overflowing to Inf while masked -1e9 entries cleanly underflow to 0.0.
