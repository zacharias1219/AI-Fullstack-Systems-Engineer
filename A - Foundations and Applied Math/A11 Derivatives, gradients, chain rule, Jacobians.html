Derivatives, gradients, chain rule, Jacobians

Why neural network training never materializes full Jacobian matrices, how Vector-Jacobian Products (VJPs) compute exact gradients in one backward pass, and how centered finite differences catch backward bugs at 10^-10 precision.

Before you read

Guess first. A wrong guess now makes the right answer stick later.

You write a custom backward pass for Softmax Cross-Entropy and forget the off-diagonal Jacobian terms (-p_i * p_j for i != j), keeping only the diagonal derivative p_t * (1 - p_t) on the target class. Does the loss still decrease, and what relative error does a centered gradient check report?
The loss still decreases early in training because the target logit is pushed up, making this a silent accuracy killer. A centered finite-difference check at eps = 1e-6 immediately catches it: the relative error jumps from 3.664e-10 (correct VJP) to 2.268e-01 (22.7% error) because all non-target logits receive zero gradient instead of p_i.
In 64-bit floating point (FP64), a centered finite-difference check at eps = 1e-5 gives a relative error of 3.620e-11. If you shrink eps to 1e-14 to make the Taylor approximation tighter, does the error get smaller or larger?
It gets nearly nine orders of magnitude worse, jumping to 3.353e-02 (3.35% error). At eps = 1e-14, f(x + eps) and f(x - eps) agree in their first 14 decimal digits; subtracting them destroys almost all significant mantissa bits (catastrophic cancellation), amplifying rounding error as O(u / eps).
An RMSNorm layer maps an activation vector x in R^4096 to y in R^4096. How many entries are in its full Jacobian matrix J, and why does the backward pass compute dL/dx in O(d) time without ever allocating J?
The full Jacobian has 4096 x 4096 = 16,777,216 entries (64 MB per token in FP32). Because the Jacobian is a diagonal scale plus a rank-1 outer product, J = inv_rms * (I - (1/d) y y^T), its Vector-Jacobian Product v^T J reduces to a dot product and vector subtraction: inv_rms * (v - y * mean(v * y)) in O(d) time and O(d) memory.

The core idea

Every neural network layer is a vector-valued function f: R^n -> R^m, and its local linear approximation is the Jacobian matrix J in R^{m x n} containing all partial derivatives J_{ij} = df_i / dx_j. By the multivariable chain rule, the derivative of a composition of layers is the matrix product of their individual Jacobians. However, materializing an m x n Jacobian for hidden dimension d = 4096 would cost d^2 = 16.7M floats per token per layer, turning every elementwise or normalization layer into an OOM bottleneck.

The key realization of modern deep learning is that training optimizes a single scalar loss L in R (m = 1) with respect to millions of parameters (n >> 1). Instead of multiplying full matrices J_K ... J_2 J_1, reverse-mode differentiation propagates a single cotangent row vector v^T = dL / dy backward from the scalar loss, contracting it with each layer's local Jacobian via a Vector-Jacobian Product (VJP) v^T J in O(n) work. To verify that a hand-written or custom CUDA VJP kernel is exact, we benchmark it against a centered finite-difference probe in FP64 at step size eps ~ 10^-6.

Memory hook

SGJ-VC ("Scalar, Gradient, Jacobian - VJP, Centered check"): Scalar slope f'(x) in R^1 -> Gradient nabla f(x) in R^d -> Jacobian J in R^{m x n} -> VJP v^T J contracts left-to-right in O(1) pass for scalar loss -> Centered check at eps = u^(1/3) ~ 10^-6 balances O(eps^2) Taylor error against O(u/eps) cancellation.

How it works

1. Partial derivatives, gradients, and directional derivatives

For a differentiable scalar function f: R^d -> R, the partial derivative df / dx_i = lim_{h->0} (f(x + h e_i) - f(x)) / h measures sensitivity along coordinate axis e_i while holding all other d - 1 coordinates fixed. Stacking all d partials into a column vector defines the gradient nabla f(x) = [df/dx_1, ..., df/dx_d]^T in R^d. From the first-order Taylor expansion f(x + u) = f(x) + nabla f(x)^T u + O(||u||^2), the rate of change along any unit vector u is the directional derivative D_u f(x) = nabla f(x)^T u = ||nabla f(x)|| cos(theta). By Cauchy-Schwarz, this inner product is maximized when theta = 0 (u aligns with nabla f(x)), proving that the gradient points in the direction of steepest ascent and is orthogonal to the level set {x : f(x) = c}.

2. The Jacobian matrix and multivariable chain rule

When a layer maps an input vector x in R^n to an output vector y = f(x) in R^m, its first-order linear approximation f(x + dx) approx f(x) + J(x) dx is governed by the Jacobian matrix J(x) = df / dx in R^{m x n}, defined entrywise as J_{ij} = df_i / dx_j. Row i is the transposed gradient (nabla f_i(x))^T of output coordinate i; column j is the partial derivative vector df / dx_j showing how nudging input x_j moves all m outputs. If we compose two vector functions z = g(y) (g: R^m -> R^k) and y = f(x) (f: R^n -> R^m), the multivariable chain rule states that the Jacobian of the composition is the matrix product of their Jacobians:

J_{g o f}(x) = J_g(f(x)) @ J_f(x)   in R^{k x n},   where (J_{g o f})_{ij} = sum_{r=1}^m (dg_i / dy_r) * (df_r / dx_j)

3. JVP (forward mode) vs VJP (reverse mode)

For a deep network L = f_K(f_{K-1}(...f_1(x))) where x in R^n and the final output is a scalar loss L in R^1, the total derivative dL / dx in R^{1 x n} is the product J_K J_{K-1} ... J_1, where J_K in R^{1 x d_{K-1}} is a single row vector. Matrix multiplication is associative, but parenthesizing left-to-right versus right-to-left changes the asymptotic complexity by a factor of n:

  • Forward-mode JVP (right-to-left): Seed a tangent vector u in R^{n x 1} at the input and propagate u_1 = J_1 u, u_2 = J_2 u_1, ..., J u. One forward pass gives the directional derivative along u. To get all n partial derivatives of L, you must set u = e_1, ..., e_n, requiring n passes. JVP is ideal when n is tiny and m is huge (e.g., sensitivity of 10,000 outputs to 1 hyperparameter).
  • Reverse-mode VJP (left-to-right): Seed a cotangent row vector v^T = [1] in R^{1 x 1} at the scalar loss and propagate backward: v_{K-1}^T = v^T J_K, v_{K-2}^T = v_{K-1}^T J_{K-1}, ..., dL/dx = v_1^T J_1. Every step contracts a 1 x m row vector with an m x n operator to produce a 1 x n row vector in 1 backward pass, at the price of storing intermediate forward activations.
Check: Suppose a physics simulator maps 3 control parameters (n = 3) to a 50,000-dimensional mesh state (m = 50,000) and you need the full 50,000 x 3 Jacobian matrix. Should you use JVP or VJP, and how many passes does each take?
Use forward-mode JVP. Seeding the 3 standard basis vectors u = e_1, e_2, e_3 builds all 3 columns of the 50,000 x 3 Jacobian in just 3 JVP passes. Reverse-mode VJP would build the matrix row-by-row, requiring 50,000 backward passes.

4. Analytic Jacobians of Softmax Cross-Entropy and RMSNorm

Two of the most common interview derivations in LLM engineering are the Softmax Jacobian and the RMSNorm VJP. Neither materializes an O(d^2) matrix during execution, yet both rely on dense off-diagonal coupling inside their true Jacobians:

Softmax + Cross-Entropy: Let p_i = exp(z_i) / sum_k exp(z_k). Differentiating the quotient gives dp_i / dz_j = p_i (delta_{ij} - p_j), or in matrix form J_soft = diag(p) - p p^T. Notice that increasing logit z_j increases p_j (diagonal term p_j(1 - p_j)) while decreasing every other probability p_i (off-diagonal term -p_i p_j) because probabilities sum to 1. For cross-entropy loss L = -log p_t on target class t, the upstream cotangent is dL / dp_i = -delta_{it} / p_t. Taking the VJP (dL/dp) J_soft gives:

dL/dz_j = (-1 / p_t) * (dp_t / dz_j) = (-1 / p_t) * p_t * (delta_{tj} - p_j) = p_j - delta_{tj}   (or dL/dz = p - e_t)

If you forget the off-diagonal -p_i p_j terms in J_soft, non-target logits get zero gradient and our kata's gradient check fails with a 2.268e-01 relative error.

RMSNorm VJP: Define rms(x) = sqrt((1/d) sum_k x_k^2 + eps), s = 1 / rms(x), and normalized output y = s * x. Because s depends on every coordinate of x via ds / dx_j = -(s^3 / d) x_j = -(s / d) y_j, the product rule yields dy_i / dx_j = s * delta_{ij} - (s / d) y_i y_j, so J_rms = s * (I - (1/d) y y^T). Contracting with upstream gradient dy gives the O(d) VJP:

dx = J_rms^T @ dy = s * (dy - y * mean(dy * y))

5. Finite-difference gradient checks and the U-shaped error curve

Before trusting a custom backward pass, we compare the analytic VJP against numerical differentiation. Expanding f(x + eps) and f(x - eps) in Taylor series around x:

f(x + eps) = f(x) + eps f'(x) + (eps^2 / 2) f''(x) + (eps^3 / 6) f'''(x) + O(eps^4)
f(x - eps) = f(x) - eps f'(x) + (eps^2 / 2) f''(x) - (eps^3 / 6) f'''(x) + O(eps^4)

Forward difference (f(x + eps) - f(x)) / eps = f'(x) + (eps / 2) f''(x) + O(eps^2) has O(eps) truncation error. Centered difference subtracts the two expansions, canceling the even f(x) and eps^2 f''(x) terms to yield (f(x + eps) - f(x - eps)) / (2 eps) = f'(x) + (eps^2 / 6) f'''(x) + O(eps^4), achieving O(eps^2) truncation error at the cost of 2d forward evaluations.

However, floating-point representation introduces a competing error. Each evaluation of f has rounding error bounded by |f| * u, where unit roundoff u is 1.11e-16 in FP64, 5.96e-8 in FP32, and 3.91e-3 in BF16. Dividing the difference by 2 eps magnifies rounding noise to O(u / eps). Total error is therefore E(eps) approx c_1 eps^2 + c_2 (u / eps). Setting dE / d(eps) = 0 reveals that optimal step size scales as eps* ~ u^(1/3) (~10^-5.3 in FP64, achieving ~10^-11 error) while forward difference optimizes at eps* ~ u^(1/2) (~10^-8 in FP64, achieving ~10^-8 error).

Check: Why does PyTorch's torch.autograd.gradcheck require double precision (FP64) inputs and fail with false alarms if you run it on FP32 or BF16 tensors at eps = 1e-6?
In FP32, unit roundoff is u = 5.96e-8, so at eps = 1e-6 the rounding cancellation error O(u / eps) is roughly 0.03 to 0.06 (3% to 6% error), which looks identical to a broken backward pass. Even at FP32's optimal eps = u^(1/3) ~ 4e-3, centered difference only reaches ~1e-5 accuracy. FP64 (u = 1.11e-16) pushes the centered-difference floor down to ~3.6e-11 at eps = 1e-5 to 1e-6, cleanly separating valid VJPs from subtle bugs.

Kata: Analytic VJP and finite-difference gradient checker

We implement a two-layer RMSNorm + Linear + Softmax Cross-Entropy block in pure Python (FP64), verify that its matrix-free O(d) RMSNorm VJP matches the explicit 32 x 32 Jacobian matrix to machine epsilon, sweep step sizes from 1e-1 to 1e-14 to expose the U-shaped truncation-versus-cancellation curve, and catch a planted Softmax off-diagonal Jacobian bug.

kata.py

import math
import random
import time

random.seed(42)
d, c = 32, 8
x = [random.gauss(0.0, 1.0) for _ in range(d)]
W = [[random.gauss(0.0, 0.25) for _ in range(d)] for _ in range(c)]
target = 3
eps_norm = 1e-5

def rmsnorm(vec):
    ms = sum(v * v for v in vec) / len(vec)
    inv_rms = 1.0 / math.sqrt(ms + eps_norm)
    return [v * inv_rms for v in vec], inv_rms

def forward(vec, W_mat):
    y, inv_rms = rmsnorm(vec)
    z = [sum(W_mat[i][j] * y[j] for j in range(d)) for i in range(c)]
    m = max(z)
    exps = [math.exp(zi - m) for zi in z]
    s = sum(exps)
    p = [e / s for e in exps]
    loss = -math.log(p[target])
    return loss, y, inv_rms, p

def analytic_vjp(vec, W_mat, buggy=False):
    loss, y, inv_rms, p = forward(vec, W_mat)
    # 1. Softmax + Cross-Entropy VJP: dL/dz = p - e_target
    # Buggy version omits off-diagonal -p_i*p_j in Softmax Jacobian: dL/dz_buggy = -(1 - p_target) on target only
    if buggy:
        dz = [-(1.0 - p[target]) if i == target else 0.0 for i in range(c)]
    else:
        dz = [p[i] - (1.0 if i == target else 0.0) for i in range(c)]
    # 2. Linear layer VJP: dL/dy = W^T @ dz
    dy = [sum(W_mat[i][j] * dz[i] for i in range(c)) for j in range(d)]
    # 3. RMSNorm VJP: J_rms^T @ dy = inv_rms * (dy - y * mean(dy * y))
    dot_dy_y = sum(dy[j] * y[j] for j in range(d)) / d
    dx = [inv_rms * (dy[j] - y[j] * dot_dy_y) for j in range(d)]
    return dx, dy, dz

def full_jacobian_rmsnorm(vec):
    y, inv_rms = rmsnorm(vec)
    return [[inv_rms * ((1.0 if i == j else 0.0) - (y[i] * y[j]) / d) for j in range(d)] for i in range(d)]

def norm(v):
    return math.sqrt(sum(vi * vi for vi in v))

def rel_err(a, b):
    diff = [ai - bi for ai, bi in zip(a, b)]
    return norm(diff) / (norm(a) + norm(b) + 1e-30)

dx_true, dy_true, _ = analytic_vjp(x, W, buggy=False)
dx_bug, _, _ = analytic_vjp(x, W, buggy=True)

# Verify reverse-mode VJP matches explicit J_rms^T @ dy
J_rms = full_jacobian_rmsnorm(x)
dx_via_J = [sum(J_rms[i][j] * dy_true[i] for i in range(d)) for j in range(d)]
print(f"RMSNorm VJP vs full Jacobian (d={d}x{d}) rel_err: {rel_err(dx_true, dx_via_J):.2e}")

print("\n--- Step-size sweep: Forward O(eps) vs Centered O(eps^2) ---")
print(f"{'eps':>8} | {'Forward diff err':>16} | {'Centered diff err':>17} | {'Dominant error regime'}")
print("-" * 72)
f0 = forward(x, W)[0]
for k in [1, 2, 3, 4, 5, 6, 7, 8, 10, 12, 14]:
    eps = 10.0 ** (-k)
    fd_fwd, fd_cen = [], []
    for i in range(d):
        xp = x[:]; xp[i] += eps
        xm = x[:]; xm[i] -= eps
        fp = forward(xp, W)[0]
        fm = forward(xm, W)[0]
        fd_fwd.append((fp - f0) / eps)
        fd_cen.append((fp - fm) / (2.0 * eps))
    ef, ec = rel_err(dx_true, fd_fwd), rel_err(dx_true, fd_cen)
    regime = "Truncation O(eps^2)" if k <= 4 else ("Optimal sweet spot" if k <= 7 else "Cancellation O(u/eps)")
    print(f"1e-{k:<5d} | {ef:16.3e} | {ec:17.3e} | {regime}")

# Compare buggy analytic gradient at optimal eps=1e-6
eps_opt = 1e-6
fd_opt = []
for i in range(d):
    xp = x[:]; xp[i] += eps_opt
    xm = x[:]; xm[i] -= eps_opt
    fd_opt.append((forward(xp, W)[0] - forward(xm, W)[0]) / (2.0 * eps_opt))

print("\n--- Gradient Check Diagnostic (eps = 1e-6) ---")
print(f"Correct analytic VJP vs Centered FD rel_err : {rel_err(dx_true, fd_opt):.3e} (PASS < 1e-7)")
print(f"Buggy Softmax VJP    vs Centered FD rel_err : {rel_err(dx_bug, fd_opt):.3e} (FAIL > 1e-3)")

What to notice

  1. Matrix-free VJP equals the full Jacobian contraction to 1.17e-16: Contracting dy with the explicit 32 x 32 RMSNorm Jacobian J_rms = inv_rms * (I - y y^T / d) agrees with the O(d) vector formula inv_rms * (dy - y * mean(dy * y)) to machine precision (1.17e-16).
  2. Quadratic 100x error drop per decade for centered difference: From eps = 1e-1 to 1e-4, reducing eps by 10x shrinks forward-difference error by exactly 10x (8.427e-3 -> 8.426e-4 -> 8.426e-5 -> 8.426e-6), whereas centered-difference error drops by 100x per decade (1.856e-4 -> 1.857e-6 -> 1.857e-8 -> 1.842e-10).
  3. Catastrophic cancellation reverses the trend below 1e-7: Past the 3.620e-11 minimum at eps = 1e-5, every 100x reduction in eps multiplies centered error by roughly 100x (4.039e-8 at 1e-8 -> 4.853e-6 at 1e-10 -> 3.353e-2 at 1e-14).
  4. Planted off-diagonal Jacobian bug jumps out by 9 orders of magnitude: Omitting -p_i p_j in the Softmax backward pass raises relative error at eps = 1e-6 from 3.664e-10 to 2.268e-01.
Break it
  1. Omit the RMSNorm denominator derivative. In analytic_vjp, replace dx = [inv_rms * (dy[j] - y[j] * dot_dy_y) for j in range(d)] with the naive scale dx = [inv_rms * dy[j] for j in range(d)] (treating inv_rms as a constant). Predict whether the relative error is small or > 0.1, then run.
  2. Simulate an FP32 gradient check. Round fp and fm inside the finite-difference loop to 7 significant digits using float(f"{fp:.7g}"). Predict which eps now gives the lowest error and watch eps = 1e-6 fail with > 1e-2 noise.
  3. Plant a non-differentiable ReLU kink at zero. Set x[0] = 1e-7 and apply max(0.0, v) before RMSNorm. Perturb with eps = 1e-5 so x[0] - eps < 0 < x[0] + eps and observe why gradient checks fail when straddling a kink.

Stretch. Add a learnable RMSNorm gain vector gamma in R^d so out_j = gamma_j * y_j, derive both dL / d(gamma) and the updated dL / dx, and verify both gradients to < 1e-9 relative error.

"Gradients tell the model how to update weights using the chain rule. Jacobians are used for multi-dimensional layers, and we use gradient checking with a very small epsilon to make sure our derivatives are accurate before deploying to production."

"For a layer f: R^n -> R^m, the Jacobian J is m-by-n, but since our loss L is a scalar (m = 1), reverse-mode autodiff propagates a 1-by-m cotangent via Vector-Jacobian Products v^T J in one backward pass instead of materializing O(d^2) matrices. When we write a custom VJP kernel, we verify it in FP64 against centered finite differences at eps = 1e-6, where O(eps^2) truncation error and O(u/eps) cancellation balance at ~3.6e-10 relative error."

The strong answer names dimensions (m x n vs 1 x m), contrasts VJP complexity against full Jacobian materialization, and cites the exact FP64 step size (1e-6) and error floor (~3.6e-10) from the kata.

Traps

Each one sounds right. Say what is wrong with it before you open it.

"The smaller you make epsilon in a finite-difference gradient check, the closer you get to the true mathematical limit lim_{eps->0}."
Wrong in floating-point arithmetic. While Taylor truncation error shrinks as O(eps^2) for centered differences, subtracting two nearly equal numbers f(x + eps) and f(x - eps) causes catastrophic cancellation whose error grows as O(u / eps). In our FP64 run, shrinking eps from 1e-5 to 1e-14 degrades relative error from 3.620e-11 to 3.353e-02.
"An elementwise or normalization layer like Softmax or RMSNorm over d features has a diagonal Jacobian because each output corresponds to the same feature index."
Wrong. Only purely independent elementwise functions (like ReLU or SiLU) have diagonal Jacobians. Both Softmax (sum_k exp(z_k)) and RMSNorm (sqrt(mean(x^2) + eps)) couple every output to every input through their shared denominator, adding a dense rank-1 outer product (-p p^T for Softmax, -(s/d) y y^T for RMSNorm) to the diagonal.
"Backpropagation computes the full Jacobian matrix of each layer and multiplies those matrices together from output to input."
Wrong. For a transformer hidden dimension d = 4096, materializing a single d x d Jacobian per token costs 64 MB in FP32. Backpropagation never builds J; it applies the linear operator v^T -> v^T J (the Vector-Jacobian Product) directly to the 1 x d upstream gradient vector in O(d) memory and time.
"Running torch.autograd.gradcheck in the model's native BF16 training dtype is the most realistic way to validate a custom backward kernel."
Wrong. BF16 has only 7 explicit mantissa bits (u = 3.91e-3), so finite differences suffer massive rounding noise (> 5% error at any eps), drowning out real derivative bugs and triggering false failures. Always validate the mathematical VJP formula in float64 first, then test the BF16 kernel against the FP64 analytic VJP reference.

Question bank

Answer aloud, then open. Grade yourself honestly.

1. What is the difference between a gradient vector, a Jacobian matrix, and a Hessian matrix, including their exact shapes for f: R^n -> R^m and L: R^n -> R?
For a scalar function L: R^n -> R, the gradient nabla L(x) is an n x 1 column vector of first partial derivatives dL / dx_i, and the Hessian H(x) is the n x n symmetric matrix of second partial derivatives H_{ij} = d^2 L / (dx_i dx_j) (which equals the Jacobian of the gradient). For a vector function f: R^n -> R^m, the Jacobian J(x) is the m x n matrix of first partial derivatives J_{ij} = df_i / dx_j.
Follow-upWhat is the convention difference between the numerator layout Jacobian of a scalar function and its gradient? Answer: In numerator layout, the Jacobian of L: R^n -> R^1 is a 1 x n row vector (a covector/cotangent), whereas the gradient nabla L(x) is its n x 1 transpose.
2. Derive the O(eps^2) truncation error of centered finite differences and explain why it beats forward differences by four orders of magnitude at eps = 1e-4.
Taylor-expanding f(x + eps) = f(x) + eps f'(x) + (eps^2/2) f''(x) + (eps^3/6) f'''(x) + O(eps^4) and f(x - eps) = f(x) - eps f'(x) + (eps^2/2) f''(x) - (eps^3/6) f'''(x) + O(eps^4), subtracting gives f(x + eps) - f(x - eps) = 2 eps f'(x) + (eps^3/3) f'''(x) + O(eps^5). Dividing by 2 eps cancels the O(eps) second-derivative term completely, leaving (eps^2/6) f'''(x). At eps = 1e-4 in our kata, forward error is O(1e-4) = 8.426e-6 while centered error is O(1e-8) = 1.842e-10.
3. Derive the optimal step size eps* as a function of unit roundoff u for both forward and centered finite differences.
For forward difference, total error is E(eps) approx a * eps + b * (u / eps); setting dE/d(eps) = a - b u / eps^2 = 0 gives eps* ~ u^(1/2) (~1e-8 in FP64) with minimum error O(u^(1/2)) ~ 1e-8. For centered difference, total error is E(eps) approx c * eps^2 + b * (u / eps); setting dE/d(eps) = 2 c eps - b u / eps^2 = 0 gives eps* ~ u^(1/3) (~5e-6 in FP64) with minimum error O(u^(2/3)) ~ 3.6e-11.
Follow-upWhat happens to optimal eps* if you must run centered differences in FP32 (u = 5.96e-8)? Answer: eps* ~ (5.96e-8)^(1/3) approx 3.9e-3 (around 1e-2 to 1e-3), yielding a minimum relative error around 1e-5.
4. Derive the Softmax Jacobian J_ij = dp_i / dz_j and show how it simplifies when combined with Cross-Entropy loss L = -sum_i y_i log(p_i).
With p_i = e^{z_i} / S where S = sum_k e^{z_k}, for i = j the quotient rule gives dp_i / dz_i = (e^{z_i} S - e^{z_i} e^{z_i}) / S^2 = p_i (1 - p_i). For i != j, dp_i / dz_j = (0 - e^{z_i} e^{z_j}) / S^2 = -p_i p_j. Combining both via Kronecker delta gives J_{ij} = p_i (delta_{ij} - p_j). With cross-entropy dL / dp_i = -y_i / p_i, the VJP is dL / dz_j = sum_i (-y_i / p_i) p_i (delta_{ij} - p_j) = -y_j + p_j sum_i y_i = p_j - y_j.
Follow-upWhy is computing dL/dz = p - y numerically superior to computing dL/dp and multiplying by J_soft separately? Answer: When p_t underflows near 0, dL/dp_t = -1 / p_t overflows to -Inf and (-1 / p_t) * p_t produces NaN, whereas p_t - 1 stays bounded in [-1, 1].
5. Derive the RMSNorm backward pass (VJP) for y = x / sqrt(mean(x^2) + eps) and interpret its two terms geometrically.
Let s = (mean(x^2) + eps)^(-1/2) so y = s x. Then ds / dx_j = (-1/2) s^3 (2 x_j / d) = -(s / d) y_j. By the product rule, dy_i / dx_j = s delta_{ij} - (s / d) y_i y_j. Multiplying J_rms^T by upstream gradient dy gives dx = s * (dy - y * mean(dy * y)). Geometrically, y lies on a sphere of radius sqrt(d); the second term subtracts the radial component of dy parallel to y, projecting the gradient onto the tangent plane of the sphere.
6. For a linear layer y = W x + b where x in R^n, y in R^m, and W in R^{m x n}, write the VJPs dL/dx, dL/dW, and dL/db given upstream cotangent dz = dL/dy in R^{m x 1}.
Since dy_i / dx_j = W_{ij}, the Jacobian with respect to x is J_x = W. In column-vector form, dL/dx = W^T dz in R^{n x 1}. For weight entry W_{ij}, dy_k / dW_{ij} = delta_{ki} x_j, so contracting with dz_k gives the outer product dL/dW = dz @ x^T in R^{m x n}. Since dy / db = I_m, dL/db = dz in R^{m x 1} (summed across the batch dimension if batched).
Follow-upHow do you quickly sanity-check VJP formulas during a whiteboard interview? Answer: Match tensor shapes: dL/dW must have the exact shape of W (m x n), which uniquely forces the outer product (m x 1) @ (1 x n) = dz @ x^T.
7. How can you estimate the trace or Frobenius norm of a giant n x n Jacobian without running n backward passes?
Use Hutchinson's trace estimator with random VJPs or JVPs. Draw k random Rademacher or standard normal vectors v in R^n with E[v v^T] = I. Compute a single VJP u^T = v^T J per sample; then E[u^T v] = E[v^T J v] = Tr(J) and E[||u||_2^2] = E[v^T J J^T v] = ||J||_F^2. Just k = 10..30 backward passes estimate the Frobenius norm of a billion-parameter Jacobian.
8. Why do gradient checks fail on functions containing ReLU, max-pooling, or dropout, and how do you fix the test harness?
Finite differences assume f is C^3 smooth on [x - eps, x + eps]. If a coordinate crosses a ReLU(z) = max(0, z) kink at z = 0 or switches the argmax winner in max-pooling between x - eps and x + eps, the secant slope averages two different linear regimes while the analytic subgradient uses the point slope at x. For dropout, different random masks between f(x + eps) and f(x - eps) inject O(1 / eps) noise. Fix by freezing the random seed/mask and choosing inputs bounded at least 10 * eps away from kinks.
Follow-upHow do you gradient-check a large weight matrix W in R^{4096 x 4096} without running 33 million forward passes? Answer: Sample 20 random indices (i, j) or check a random directional projection (f(W + eps U) - f(W - eps U)) / (2 eps) == sum(dL/dW * U) for a random unit Frobenius matrix U in just 2 forward passes.

Mixed review

Three questions from earlier topics. Nobody tells you the topic in an interview.

A09: Two tensors have shapes (B, 1, T, D) and (H, T, D). Are they broadcast-compatible, what is the resulting shape, and how many bytes of memory does broadcasting allocate for the expanded views?
Yes. Aligning trailing dimensions gives (B, 1, T, D) and (1, H, T, D); dimensions of size 1 stretch to match, producing output shape (B, H, T, D). Broadcasting allocates 0 extra bytes for the input views by setting their stride along the stretched axis to 0.
A09: Write the einsum string for batched multi-head attention score computation Q @ K^T where Q has shape (B, H, T_q, d_k) and K has shape (B, H, T_k, d_k).
torch.einsum("bhqd,bhkd->bhqk", Q, K), which contracts the head dimension d and preserves batch b and head h to produce an attention logit tensor of shape (B, H, T_q, T_k).
L04: Why does an event-loop server (epoll/asyncio) handle 10,000 concurrent I/O-bound LLM streaming connections in a single thread, and what breaks if one handler runs a 200 ms CPU-bound tokenizer loop synchronously?
An event loop registers non-blocking sockets with epoll and consumes zero thread stack while waiting on network I/O, waking only on readiness events. A synchronous 200 ms CPU loop blocks the single event-loop thread, freezing all 9,999 other connections and adding 200 ms of head-of-line blocking latency to every in-flight token stream.

Short notes

Quick-memorization cheat sheet covering every subtopic on this page and the key facts to remember cold.

All subtopics on this page

  • Gradient & Directional Derivative: nabla f(x) in R^d collects all partials df/dx_i; directional slope along unit u is nabla f(x)^T u, maximized along nabla f(x).
  • Jacobian Matrix & Chain Rule: For f: R^n -> R^m, J in R^{m x n} with J_{ij} = df_i / dx_j; composition satisfies J_{g o f}(x) = J_g(f(x)) @ J_f(x).
  • JVP vs VJP: Forward-mode JVP (J u) propagates tangents right-to-left (needs n passes for R^n -> R^1); reverse-mode VJP (v^T J) propagates cotangents left-to-right (needs 1 backward pass for scalar loss).
  • Softmax + Cross-Entropy VJP: J_soft = diag(p) - p p^T; contracting with dL/dp = -e_t / p_t collapses to dL/dz = p - e_t (omitting off-diagonal -p_i p_j causes 2.268e-01 error).
  • RMSNorm VJP: J_rms = inv_rms * (I - (1/d) y y^T); matrix-free VJP is dx = inv_rms * (dy - y * mean(dy * y)) in O(d) time and O(d) memory.
  • Finite-Difference U-Curve: Centered FD (f(x+e)-f(x-e))/(2e) cancels f''(x) to achieve O(eps^2) truncation error against O(u / eps) subtraction cancellation.
Important things to remember
  • Optimal step size formulas: Centered FD optimizes at eps* ~ u^(1/3) (1e-5..1e-6 in FP64 -> 3.62e-11..3.66e-10 error; 1e-2..1e-3 in FP32); Forward FD optimizes at eps* ~ u^(1/2) (1e-7..1e-8 in FP64 -> 1.03e-8 error).
  • Cancellation trap: Shrinking eps to 1e-14 in FP64 ruins centered FD (error jumps to 3.353e-02) because f(x+eps) and f(x-eps) share 14 leading digits.
  • Fast O(1)-pass gradient check for huge tensors: Project along a random unit direction U and check (f(W + eps U) - f(W - eps U)) / (2 eps) == sum(dL/dW * U) in just 2 forward evaluations.
  • Production rule: Always run gradcheck in float64 away from ReLU/max kinks with frozen dropout masks.
