Before you read

Guess first. A wrong guess now makes the right answer stick later. The numbers come from the kata in station 6.

In a transformer layer with hidden width d = 256, does attention (QK^T and PV) or linear projection (Q, K, V, O) do more floating-point operations at sequence length n = 256, and at what exact length n do their FLOP counts become equal?
At n = 256, the four linear projections do twice as many FLOPs as attention (0.134 GFLOP vs 0.067 GFLOP). Projections cost 8*n*d^2 FLOPs and attention matmuls cost 4*n^2*d FLOPs, so they become equal at n = 2*d = 512 (0.268 GFLOP each). When you include the feed-forward MLP (16*n*d^2), total linear block FLOPs are 24*n*d^2, which crosses attention at n = 6*d = 1,536.
In the kata, raising sequence length 16x from n = 256 to n = 4096 increases linear projection time by 8.0x (1.63 ms to 13.11 ms), but increases causal attention time by 149.5x (1.18 ms to 176.42 ms). Why did attention grow nearly 150x while its score matrix grew 256x to 64.00 MB?
Attention FLOPs scale as O(n^2 * d) and score-matrix bytes scale as O(n^2), so a 16x increase in n multiplies both arithmetic and score memory by 16^2 = 256x. At small n = 256, fixed call overhead and L2/L3 cache residency mask the curve; from n = 1024 to n = 4096, the 64 MB score matrix spills out of CPU cache into main RAM and the empirical log-log exponent reaches alpha = 1.93.
Generating 1 token during batch-1 decode on a 7B model requires only about 14 GFLOPs (2 * P), whereas a single GPU can execute over 300,000 GFLOPs/s. Why can the GPU not generate 20,000 tokens per second for that single user?
Batch-1 decode is memory-bandwidth-bound, not compute-bound. To compute those 14 GFLOPs for 1 token, the GPU must stream all 14 GB of FP16 model weights from HBM into SRAM on every single token step. Even at 2,000 GB/s memory bandwidth, reading 14 GB takes 7 ms per token, capping throughput at roughly 140 tokens/s while the compute units sit over 99% idle.

The core idea

Algorithmic complexity in AI systems has two dimensions that rarely bottleneck at the same time: floating-point operations (compute) and bytes moved across the memory hierarchy (bandwidth and capacity). Inside a transformer block of sequence length n and model dimension d, dense weight projections and MLPs touch every token independently in O(n * d^2) compute, while self-attention compares every token pair in O(n^2 * d) compute and materializes an O(n^2) score matrix. At short sequences (n << d), weight projections dominate runtime; past the crossover n = 6*d, the quadratic attention term takes over.

In serving, the bottleneck flips between two phases. Prefill processes all n prompt tokens in parallel, amortizing one weight read across n tokens (high arithmetic intensity, compute-bound) and paying the full O(n^2 * d) attention cost. Autoregressive decode generates one token at a time against a KV cache of length n, cutting per-step compute to O(d^2 + n * d) but streaming every weight matrix and all n cached KV vectors from memory for each token (low arithmetic intensity, memory-bandwidth-bound).

Memory hook

L-Q-C-B-S (Linear, Quadratic, Crossover, Bandwidth, Slope): Linear projections 24*n*d^2 (8*n*d^2 for QKVO, 16*n*d^2 for MLP), Quadratic attention 4*n^2*d FLOPs and n^2 score memory, Crossover at n = 6*d (or 2*d vs QKVO alone), Bandwidth-bound decode vs compute-bound prefill, Slope alpha = d(log T)/d(log n) to verify empirical scaling.

How it works

Big-O of a transformer layer: projections vs attention

Recall from A09 that multiplying an (M, K) matrix by a (K, N) matrix performs M * K * N multiply-accumulates, or 2 * M * K * N FLOPs. For a single sequence of length n and model width d (where multi-head dimensions sum to H * d_head = d), each of the four attention projections (W_Q, W_K, W_V, W_O of shape d x d) costs 2*n*d^2 FLOPs, totaling 8*n*d^2 FLOPs. A standard feed-forward MLP with hidden width 4*d adds two (n, d) @ (d, 4d) matmuls, or 16*n*d^2 FLOPs, giving 24*n*d^2 linear-in-n FLOPs per layer.

Self-attention computes the score matrix S = Q @ K^T of shape (n, n) in 2*n^2*d FLOPs, applies causal mask and softmax in O(n^2) elementwise operations, and multiplies P @ V in another 2*n^2*d FLOPs, totaling 4*n^2*d FLOPs. Dividing attention FLOPs by linear FLOPs yields the exact crossover:

Attention / QKVO ratio = (4 * n^2 * d) / (8 * n * d^2)  = n / (2 * d)   --> crosses 1.0 at n = 2 * d
Attention / Full-block = (4 * n^2 * d) / (24 * n * d^2) = n / (6 * d)   --> crosses 1.0 at n = 6 * d
Check: for a Llama-scale layer with d = 4096, at what context length n do attention matmul FLOPs overtake the combined QKVO + MLP linear projections?
At n = 6 * d = 6 * 4096 = 24,576 tokens. Below 24k tokens, the 24*n*d^2 dense weight matmuls actually consume more FLOPs than the 4*n^2*d attention matmuls.

Compute vs memory: arithmetic intensity and prefill vs decode

A processor with peak compute C_peak (FLOPs/s) and memory bandwidth BW (bytes/s) finishes an operation of F FLOPs and M bytes of memory traffic in at least T >= max(F / C_peak, M / BW). The ratio I = F / M (FLOPs per byte moved) is the operation's arithmetic intensity. When I is below the hardware ridge point I_ridge = C_peak / BW (typically 150 to 300 FLOPs/byte on modern GPUs; covered in detail in K23), execution is memory-bandwidth-bound.

During prefill of B * n tokens, a weight matrix of d^2 parameters (2*d^2 bytes in FP16) performs 2*B*n*d^2 FLOPs, so arithmetic intensity is roughly B * n FLOPs/byte: easily compute-bound. During autoregressive decode, each step processes only 1 new token per sequence (2*B*d^2 FLOPs) while still reading all 2*d^2 weight bytes plus the KV cache of 4*B*n*d FP16 bytes per layer. At B = 1, intensity collapses to ~1 FLOP/byte, so latency per token equals total bytes streamed divided by BW.

Throughput math and fitting the empirical exponent

For a model with P parameters stored in b_w bytes per parameter (b_w = 2 for FP16/BF16), a full forward pass over N = B * n tokens takes approximately 2 * P * N weight FLOPs (and a training step takes 6 * P * N FLOPs: 2P forward + 4P backward). Consequently, batch-1 decode step time is bounded below by weight streaming plus KV cache streaming:

T_decode_step(B, n) >= (P * b_w + B * n * bytes_kv_per_tok) / BW
Throughput (tok/s)  = B / T_decode_step(B, n)

Raising batch size B amortizes the fixed weight read P * b_w across B sequences, multiplying token throughput almost linearly with B until either arithmetic intensity reaches I_ridge or the KV cache term B * n * bytes_kv_per_tok saturates memory capacity or bandwidth. To verify whether any code path scales linearly (alpha = 1) or quadratically (alpha = 2) in practice, time it across powers of two and fit a straight line to log2(T) = log2(c) + alpha * log2(n): a doubling ratio T(2n) / T(n) of 2x gives alpha = 1, while a 4x doubling ratio gives alpha = 2.

Check: you double sequence length from n = 2048 to n = 4096 and wall-clock latency rises from 47.21 ms to 176.42 ms (a 3.74x ratio). What is the empirical two-point exponent alpha?
alpha = log2(176.42 / 47.21) = log2(3.737) = 1.90, confirming near-quadratic O(n^2) runtime growth.

"""A20 kata: time causal self-attention vs linear projection across sequence lengths n=256..4096."""
import time
import numpy as np

D = 256
SEQ_LENS = [256, 512, 1024, 2048, 4096]
REPS = 5
RNG = np.random.default_rng(42)
W_QKV = RNG.standard_normal((D, 3 * D), dtype=np.float32) * 0.02
W_O = RNG.standard_normal((D, D), dtype=np.float32) * 0.02


def linear_projections(x):
    """O(n * d^2) Q, K, V, O projections: 4 matmuls of (n, d) @ (d, d) -> 8*n*d^2 FLOPs."""
    q, k, v = np.split(x @ W_QKV, 3, axis=-1)
    out_proj = q @ W_O
    return q, k, v, out_proj


def causal_attention(q, k, v):
    """O(n^2 * d) dot-product attention (QK^T + softmax + PV) with O(n^2) score matrix."""
    n = q.shape[0]
    scores = (q @ k.T) * (D ** -0.5)
    mask = np.triu(np.ones((n, n), dtype=bool), k=1)
    scores[mask] = -1e9
    scores -= scores.max(axis=-1, keepdims=True)
    weights = np.exp(scores)
    weights /= weights.sum(axis=-1, keepdims=True)
    return weights @ v


def bench(fn, *args):
    fn(*args)  # warm up cache / BLAS threads
    t0 = time.perf_counter()
    for _ in range(REPS):
        fn(*args)
    return (time.perf_counter() - t0) * 1000.0 / REPS


def fit_exponent(ns, times):
    """Fit T(n) ~ c * n^alpha via OLS on log2(n) vs log2(T)."""
    lx, ly = np.log2(ns), np.log2(times)
    alpha, _ = np.polyfit(lx, ly, 1)
    r2 = np.corrcoef(lx, ly)[0, 1] ** 2
    return alpha, r2


if __name__ == "__main__":
    proj_ms_list, attn_ms_list = [], []
    print(f"Config: d={D}, dtype=float32, reps={REPS}")
    print(f"{'n':>5} | {'proj_ms':>8} | {'attn_ms':>8} | {'attn/proj':>9} | {'proj_GFLOP':>10} | {'attn_GFLOP':>10} | {'score_MB':>8}")
    print("-" * 76)
    for n in SEQ_LENS:
        x = RNG.standard_normal((n, D), dtype=np.float32)
        q, k, v, _ = linear_projections(x)
        p_ms = bench(linear_projections, x)
        a_ms = bench(causal_attention, q, k, v)
        proj_ms_list.append(p_ms)
        attn_ms_list.append(a_ms)
        proj_gflops = (8.0 * n * (D ** 2)) / 1e9  # Q,K,V,O projections = 4 * (2*n*d^2)
        attn_gflops = (4.0 * (n ** 2) * D) / 1e9  # QK^T + PV = 2 * (2*n^2*d)
        score_mb = (n * n * 4) / (1024 ** 2)      # float32 n x n matrix in MiB
        print(f"{n:5d} | {p_ms:8.2f} | {a_ms:8.2f} | {a_ms/p_ms:8.1f}x | {proj_gflops:10.3f} | {attn_gflops:10.3f} | {score_mb:8.2f}")

    a_proj, r2_proj = fit_exponent(SEQ_LENS, proj_ms_list)
    a_attn, r2_attn = fit_exponent(SEQ_LENS, attn_ms_list)
    a_tail, r2_tail = fit_exponent(SEQ_LENS[2:], attn_ms_list[2:])
    print("-" * 76)
    print(f"Log-log slope alpha (n=256..4096): projection={a_proj:.2f} (R^2={r2_proj:.3f}) | attention={a_attn:.2f} (R^2={r2_attn:.3f})")
    print(f"Asymptotic attention slope (n=1024..4096): alpha={a_tail:.2f} (R^2={r2_tail:.3f}), 4096/2048 time ratio={attn_ms_list[-1]/attn_ms_list[-2]:.2f}x")

What to notice

  1. Exact FLOP crossover at n = 2*d = 512: At n = 256, the four projections execute 0.134 GFLOP vs 0.067 GFLOP for attention, and attention is faster (1.18 ms vs 1.63 ms, 0.7x). At n = 512, both perform exactly 0.268 GFLOP, yet attention already takes 3.92 ms vs 2.01 ms (2.0x) because masking and softmax move the 1.00 MB score matrix through memory.
  2. Quadratic takeoff past n = 1024: Each doubling of n from 1024 to 2048 to 4096 quadruples attention FLOPs (1.074 to 4.295 to 17.180 GFLOP) and quadruples score memory (4.00 to 16.00 to 64.00 MB), driving wall-clock latency from 12.18 ms to 47.21 ms (3.88x) to 176.42 ms (3.74x).
  3. Log-log regression proves the exponent: Across all five points, np.polyfit(log2(n), log2(T), 1) gives alpha = 0.74 for linear projections and alpha = 1.80 for attention. In the asymptotic regime n = 1024..4096, where fixed dispatch overhead is negligible, attention slope hits alpha = 1.93 with R^2 = 1.000.
  4. Memory bandwidth amplifiers: Even though at n = 4096 attention has 8.0x more FLOPs than projections (17.180 vs 2.147 GFLOP), its wall time is 13.5x longer (176.42 ms vs 13.11 ms) because materializing, masking, and exponentiating the 64.00 MB float32 matrix thrashes main-memory bandwidth.

Traps

Each one sounds right. Say what is wrong with it before you open it.

"FlashAttention reduces self-attention time complexity from O(n^2) to O(n)."
Wrong. FlashAttention still computes every causal pair in Q @ K^T and performs the exact same 4*n^2*d FLOPs, so prefill compute complexity remains O(n^2 * d). What FlashAttention reduces from O(n^2) to O(n) is HBM memory footprint and HBM read/write traffic, by tiling blocks in on-chip SRAM with online softmax.
"Self-attention is always the biggest compute bottleneck in a transformer forward pass."
Wrong whenever sequence length n is shorter than 6*d. For a model with d = 4096, the linear weight projections (24*n*d^2) do more FLOPs than attention (4*n^2*d) at every context length below n = 24,576 tokens. At n = 2048 and d = 4096, attention is only 8% of layer FLOPs.

Question bank

Answer aloud, then open. Grade yourself honestly.

Derive the exact FLOP counts for QKVO projections, a 4d feed-forward MLP, and multi-head self-attention for batch 1, sequence length n, and hidden dimension d.
A matmul (n, d) @ (d, d) takes 2*n*d^2 FLOPs. Four projections (W_Q, W_K, W_V, W_O) take 4 * 2*n*d^2 = 8*n*d^2 FLOPs. Two MLP matmuls (n, d) @ (d, 4d) and (n, 4d) @ (4d, d) take 2 * 8*n*d^2 = 16*n*d^2 FLOPs (total linear = 24*n*d^2). Across H heads with H * d_head = d, Q @ K^T takes H * 2*n^2*d_head = 2*n^2*d FLOPs and P @ V takes 2*n^2*d FLOPs, giving 4*n^2*d attention FLOPs.
Follow-upHow does causal masking affect the effective FLOPs of FlashAttention? Because the upper triangle of the causal mask is zero, tiled causal FlashAttention skips roughly half the blocks, executing about 2*n^2*d useful FLOPs instead of 4*n^2*d.
Why does increasing batch size from B = 1 to B = 16 during autoregressive decode raise total throughput nearly 16x with only a tiny increase in per-token step latency?
At B = 1, the step is memory-bandwidth-bound on streaming the model weights (P * b_w bytes) from HBM, and arithmetic intensity is ~1 FLOP/byte. At B = 16, the exact same weight read from HBM is reused across all 16 tokens in SRAM registers, multiplying arithmetic intensity 16x while adding almost no extra weight-memory traffic until reaching the GPU's ridge point.
A 7B parameter model in FP16 (14 GB of weights) runs batch-1 decode on a GPU with 1,400 GB/s achieved memory bandwidth. Ignoring KV cache size, what is the theoretical minimum time per output token and maximum tokens/second?
Minimum step time is 14 GB / (1,400 GB/s) = 0.010 s = 10 ms per token. The maximum single-stream decode throughput is 1 / 0.010 s = 100 tokens/s, no matter how many teraflops of compute the GPU has.
Follow-upIf you quantize the weights from FP16 (2 bytes) to INT4 (0.5 bytes), how do the weight size and theoretical bandwidth-bound decode speed change? Weight traffic drops 4x from 14 GB to 3.5 GB, cutting the bandwidth floor to 2.5 ms/token (~400 tokens/s).
During autoregressive decode with a KV cache of length n, what is the per-step time and memory-traffic complexity of generating token n + 1, and what is the total complexity of generating a sequence of n tokens from scratch?
For a single decode step at context length n, projections cost O(d^2) and attending the 1 new query against n cached keys and values costs O(n * d) FLOPs and streams O(d^2 + n * d) bytes. Summing over all n generated tokens from t = 1..n gives sum(t * d) = O(n * d^2 + n^2 * d) total generation FLOPs.
In the kata, why was the fitted log-log exponent for attention alpha = 1.80 across n = 256..4096, but alpha = 1.93 across n = 1024..4096?
Measured runtime is a sum of lower-order terms plus the asymptotic term: T(n) = c_0 + c_1 * n + c_2 * n^2. At small n = 256 and 512, fixed Python/BLAS launch overhead c_0 and fast L2/L3 cache hits make doubling ratios smaller than 4x. Once n >= 1024, the quadratic term dominates and the empirical slope approaches 2.0 (1.93).
At what batch-times-context threshold does KV cache memory traffic overtake model weight traffic during a decode step?
Per layer, weight traffic in FP16 is roughly 24 * d^2 bytes (12 * d^2 params * 2 bytes), while MHA KV cache traffic for batch B and sequence n is 4 * B * n * d bytes (K and V, 2 bytes each). Setting 4 * B * n * d = 24 * d^2 shows KV traffic overtakes weight traffic when B * n > 6 * d (or 6 * d * (H / KVH) under GQA).

  • Kata numbers (d = 256, FP32): at n = 256, proj = 1.63 ms (0.134 GFLOP), attn = 1.18 ms (0.067 GFLOP, 0.25 MB); at n = 512, FLOPs tie at 0.268 GFLOP; at n = 4096, proj = 13.11 ms (2.147 GFLOP), attn = 176.42 ms (13.5x proj, 17.180 GFLOP, 64.00 MB), asymptotic slope alpha = 1.93.

Mixed review

Three questions from earlier topics. Nobody tells you the topic in an interview.

A09: Why does parenthesizing a rank-r LoRA update as (x @ A) @ B instead of x @ (A @ B) save massive FLOPs at runtime when r << d_model?
For input x of shape (B, S, d), (x @ A) @ B contracts down to bottleneck width r first in 4*B*S*d*r FLOPs. x @ (A @ B) materializes the dense (d, d) matrix first and runs a full dense projection in 2*d^2*r + 2*B*S*d^2 FLOPs (6.67x more FLOPs in the A09 kata).
A07: In cProfile and pstats, why can a function with the highest cumtime have almost zero tottime, and which column tells you what to optimize?
cumtime includes all time spent inside child functions called by a wrapper, whereas tottime measures only exclusive time inside the function's own body. Sort by tottime to find the leaf function actually burning CPU cycles.
A16: Why does minimizing cross-entropy loss H(P, Q) during LLM pretraining automatically minimize forward KL divergence D_KL(P || Q)?
Because H(P, Q) = H(P) + D_KL(P || Q), and the true data entropy H(P) does not depend on model parameters Q, so its gradient with respect to model weights is identically zero.

Short notes

Quick-memorization cheat sheet covering every subtopic on this page and the key facts to remember cold.

All subtopics on this page

  • Linear projections & MLP complexity: O(n * d^2) compute; four attention projections (W_Q, W_K, W_V, W_O) cost 8*n*d^2 FLOPs and a 4d MLP costs 16*n*d^2 FLOPs, totaling 24*n*d^2 FLOPs per layer.
  • Self-attention compute & memory complexity: O(n^2 * d) compute (4*n^2*d FLOPs across QK^T and PV) and O(n^2) memory to materialize the (B, H, n, n) score matrix (64 MB at n = 4096 in FP32).
  • Compute vs memory & prefill vs decode: Arithmetic intensity I = FLOPs / Bytes; prefill runs n tokens in parallel (I ~ B*n, compute-bound), while batch-1 decode runs 1 token per step (I ~ 1, memory-bandwidth-bound on streaming weights + KV cache).
  • Throughput math & empirical log-log fitting: Forward pass is ~2*P FLOPs/token; decode step time T >= (P*b_w + B*n*bytes_kv)/BW; fitting log2(T) vs log2(n) gives empirical exponent alpha (1.93 for attention across n = 1024..4096 in the kata).
Important things to remember
  • Crossover rule: Attention FLOPs (4*n^2*d) overtake QKVO projections (8*n*d^2) at n = 2*d and overtake the full linear block (24*n*d^2) at n = 6*d.
  • FlashAttention rule: FlashAttention reduces HBM memory footprint and IO from O(n^2) to O(n) via SRAM tiling, but prefill FLOPs remain O(n^2 * d).
  • Batch-1 decode rule: Single-stream decode latency is set by HBM bandwidth (Weight_Bytes / BW), not peak TFLOPs; batching B sequences multiplies throughput ~Bx until KV cache traffic or compute saturates.
  • KV vs weight traffic crossover: During MHA decode, KV cache bandwidth overtakes weight bandwidth when B * n > 6 * d (or 6 * d * H / KVH with GQA).
  • Doubling test: When n doubles, runtime multiplies by 2^alpha: 2x means O(n) (alpha = 1), 4x means O(n^2) (alpha = 2; kata measured 3.74x from 2048 to 4096, alpha = 1.93).
