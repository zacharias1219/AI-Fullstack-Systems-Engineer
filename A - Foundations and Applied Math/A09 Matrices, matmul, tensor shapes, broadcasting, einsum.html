The core idea

Every forward pass in deep learning is a pipeline of coordinate contractions and axis rearrangements. Matrix multiplication (matmul) contracts the last axis of the left tensor against the second-to-last axis of the right tensor while treating all leading dimensions as parallel batches. When a layer needs independent subspaces, such as multi-head attention or Grouped-Query Attention (GQA), we factor a wide feature axis into (H, d_head), permute the head axis ahead of the sequence axis so each head runs its own sequence-by-sequence matmul, and merge the heads back afterward.

Because Python frameworks verify only shape compatibility at each step, the hardest bugs in ML systems are operations that succeed with plausible shapes while corrupting data or exploding compute. Direct reshape(B, H, S, d_head) scrambles token memory across heads without throwing an error; right-aligned broadcasting turns a 1D vector and a 2D column vector into an O(B^2) outer product; and unfactored matrix chains waste massive FLOPs. Mastering tensor shapes means tracking both logical axes and physical memory strides at every line, and using einsum to name every contracted and surviving axis explicitly.

Memory hook

R-T-E-B-F rebuilds the five rules of tensor geometry: Right-align shapes for broadcasting (1s stretch, mismatches fail), Transpose before and after multi-head reshape (never reshape across non-adjacent logical axes), Einsum contracts every index absent from the arrow's right side, Batched matmul contracts only (..., M, K) @ (..., K, N) -> (..., M, N), and Factor low-rank chains as (x @ A) @ B so FLOPs scale with rank r instead of d_model^2.

How it works

1. Matrix multiplication as linear transformation and batched contraction

A 2D matrix W of shape (K, N) is a linear map from R^K to R^N. When multiplying A @ B with shapes (M, K) and (K, N), entry (i, j) is the dot product of row i of A and column j of B, requiring K multiplies and K adds (counted as 2 * M * K * N FLOPs). Equivalently, A @ B is a sum of K rank-1 outer products of columns of A with rows of B.

For N-D tensors (rank 3 or higher), the @ operator (np.matmul / torch.matmul) acts exclusively on the last two axes and broadcasts all leading batch axes. Given activations x_norm of shape (B, S, d_model) = (2, 6, 64) and a 2D weight matrix W_q of shape (64, 64), matmul treats (2, 6) as 12 independent row vectors of length 64, contracting the shared 64-dim axis to return (2, 6, 64) in 2 * 2 * 6 * 64 * 64 = 98,304 FLOPs.

# Batched matmul rule: (..., M, K) @ (..., K, N) -> (..., M, N)
# 2D weight (K, N) broadcasts across all leading batch dimensions (...)
q_flat = x_norm @ W_q  # (2, 6, 64) @ (64, 64) -> (2, 6, 64)

2. Memory layout, strides, reshape vs transpose

A tensor in NumPy or PyTorch is a 1D contiguous block of memory paired with a shape tuple and a strides tuple stating how many elements (or bytes) to step along each axis. For a row-major (C-contiguous) tensor of shape (B=2, S=6, d=64), the element strides are (384, 64, 1): moving +1 along the feature axis steps 1 element, moving +1 token steps 64 elements, and moving +1 batch item steps 6 * 64 = 384 elements.

reshape changes the shape metadata while reading physical memory in sequential order. Therefore, splitting d_model=64 into (H=4, d_head=16) MUST first reshape the contiguous last axis into (2, 6, 4, 16) (strides (384, 64, 16, 1)), and only then call transpose(0, 2, 1, 3) to swap the stride metadata to (384, 16, 64, 1) with logical shape (2, 4, 6, 16). Calling q_flat.reshape(2, 4, 6, 16) directly assumes memory is already laid out head-first (stride 96 per head), mixing tokens 0 to 2 into head 0 and tokens 3 to 5 into head 1.

# RIGHT: split contiguous last axis first, then permute stride metadata
q = q_flat.reshape(B, S, H, d_head).transpose(0, 2, 1, 3)  # (2, 4, 6, 16)

# WRONG: same (2, 4, 6, 16) shape, but scrambles tokens across heads!
q_bug = q_flat.reshape(B, H, S, d_head)  # max_abs_diff = 36.2399
Check: Why does merging attention heads back to (B, S, d_model) in PyTorch require .contiguous() (or .reshape()) after .transpose(1, 2) instead of .view(B, S, d_model)?
Because attn_out of shape (B, H, S, d_head) after transpose(1, 2) has shape (B, S, H, d_head) with non-monotonic strides (384, 64, 16, 1) only if it was already contiguous in (B, S, H, d_head); since attn_out was produced by matmul in (B, H, S, d_head) order, its physical strides are (384, 96, 16, 1) and transposing to (B, S, H, d_head) leaves strides (384, 16, 96, 1). Since 16 != 4 * 16, the last two axes are not contiguous in memory, so .view() throws a stride error until .contiguous() or .reshape() copies the bytes into row-major order.

3. Broadcasting rules, keepdims, and silent outer products

When two tensors of different ranks or sizes meet in an elementwise operation, NumPy and PyTorch apply two deterministic rules: first, align the shape tuples on the right and prepend 1s to the shorter shape until both have the same rank; second, compare each axis pair, succeeding if the dimensions are equal or one of them is 1 (in which case the size-1 axis is virtually stretched with stride 0 without copying memory).

This rule makes 4D mask combination effortless: adding attention scores (2, 4, 6, 6), causal mask (1, 1, 6, 6), and key-padding mask (2, 1, 1, 6) stretches every singleton axis to (2, 4, 6, 6) in zero extra memory allocations. However, right-alignment causes two classic bugs: omitting keepdims=True in a reduction like mean(x**2, axis=-1) collapses (2, 6, 64) to (2, 6), which right-aligns against (2, 6, 64) as (1, 2, 6) and crashes; worse, multiplying a 1D vector (B,) by a column vector (B, 1) pads (B,) on the left to (1, B) and silently outputs a (B, B) outer product.

4. Einstein summation (einsum) grammar and attention contractions

einsum("subscripts->output", *operands) specifies any multi-linear contraction in a single string. Every letter names an axis: letters repeated across inputs are multiplied elementwise, and any letter omitted from the right side of -> is summed over (contracted). Letters that appear on the right side survive in the exact permutation written.

In multi-head attention, queries q have shape (B, H, S_q, d_head) labeled bhid and keys k_rep have shape (B, H, S_k, d_head) labeled bhjd. Writing np.einsum("bhid,bhjd->bhij", q, k_rep) contracts the shared head dimension d (since d is absent after ->) while keeping batch b and head h locked together and taking all pairwise token products (i, j) to yield (2, 4, 6, 6) without needing a separate k_rep.transpose(0, 1, 3, 2) call.

# Einsum grammar: missing index on RHS = summed over; order on RHS = output transpose
scores   = np.einsum("bhid,bhjd->bhij", q, k_rep)       # contracts d -> (2, 4, 6, 6)
attn_out = np.einsum("bhij,bhjd->bhid", masked, k_rep)  # contracts j -> (2, 4, 6, 16)

5. Contraction order, low-rank factoring, and slice-before-project

Matrix multiplication is associative in exact arithmetic, (X @ A) @ B == X @ (A @ B), but its computational complexity depends dramatically on parenthesization. For input X of shape (B*S, d_model) and LoRA adapters A of shape (d_model, r) and B of shape (r, d_model) with r << d_model, computing (X @ A) @ B projects down to the narrow rank-r bottleneck first in 2*B*S*d*r + 2*B*S*r*d = 4*B*S*d*r FLOPs. Grouping as X @ (A @ B) materializes a dense (d_model, d_model) matrix first in 2*d^2*r FLOPs and then runs a full dense matmul in 2*B*S*d^2 FLOPs.

Similarly, during autoregressive decode or next-token evaluation, projecting all S tokens through the vocabulary head x_norm @ W_lm computes (B, S, V) logits only to discard S - 1 rows. Slicing the last token first via x_norm[:, -1:, :] @ W_lm reduces the matmul from (2, 6, 64) @ (64, 1000) to (2, 1, 64) @ (64, 1000), cutting FLOPs and output memory by a factor of S = 6.

Check: In Grouped-Query Attention (GQA) with H=4 query heads and KVH=2 key-value heads, why do we project keys to (B, S, KVH * d_head) = (2, 6, 32) and then apply repeat_interleave along the head axis to reach (2, 4, 6, 16)?
Because sharing each KV head across H // KVH = 2 query heads cuts the KV projection weights and KV cache memory footprint in half (32 features per token instead of 64), while repeating each KV head twice along the head axis produces a (2, 4, 6, 16) view that aligns 1-to-1 with the 4 query heads in batched matmul or einsum("bhid,bhjd->bhij").

"""
A09 Kata: Matrices, matmul, tensor shapes, broadcasting, einsum
Predicts 15 canonical LLM and ML tensor shapes and verifies every one in NumPy,
then demonstrates three silent shape/broadcasting/einsum bugs.
"""
import numpy as np

np.random.seed(42)

# Canonical dimensions
B, S, V = 2, 6, 1000
d_model, d_ff = 64, 172
H, KVH, d_head = 4, 2, 16
r = 8  # LoRA rank

ids = np.random.randint(0, V, size=(B, S))
W_emb = np.random.randn(V, d_model)
W_q = np.random.randn(d_model, H * d_head)
W_k = np.random.randn(d_model, KVH * d_head)
W_g = np.random.randn(d_model, d_ff)
W_d = np.random.randn(d_ff, d_model)
W_lm = np.random.randn(d_model, V)
gamma = np.ones((d_model,))
causal_mask = np.triu(np.full((1, 1, S, S), -1e9), k=1)
pad_mask = np.zeros((B, 1, 1, S))
lora_A = np.random.randn(d_model, r)
lora_B = np.random.randn(r, d_model)

# 15 shape predictions vs live NumPy execution
x = W_emb[ids]                                            # 1. Embedding lookup
rms = np.sqrt(np.mean(x ** 2, axis=-1, keepdims=True))    # 2. RMS reducer with keepdims
x_norm = (x / (rms + 1e-5)) * gamma                       # 3. Broadcast scale [B,S,d] * [d]
q_flat = x_norm @ W_q                                     # 4. Batched Q projection
q = q_flat.reshape(B, S, H, d_head).transpose(0, 2, 1, 3) # 5. Split + transpose heads
k = (x_norm @ W_k).reshape(B, S, KVH, d_head)             # 6. GQA K projection
k_rep = np.repeat(k, H // KVH, axis=2).transpose(0, 2, 1, 3) # 7. GQA repeat_interleave
scores = np.einsum("bhid,bhjd->bhij", q, k_rep)           # 8. Attention scores via einsum
masked = scores + causal_mask + pad_mask                  # 9. 4D broadcast of two masks
attn_out = np.einsum("bhij,bhjd->bhid", masked, k_rep)    # 10. Value weighted sum
merged = attn_out.transpose(0, 2, 1, 3).reshape(B, S, d_model) # 11. Merge heads
ff_act = (x_norm @ W_g) * (x_norm @ W_g)                  # 12. Gated MLP intermediate
ff_out = ff_act @ W_d                                     # 13. MLP down-projection
lora_delta = (x_norm @ lora_A) @ lora_B                   # 14. LoRA low-rank update
logits_last = (x_norm[:, -1:, :] @ W_lm)[:, 0, :]         # 15. Sliced LM head unembedding

cases = [
    ("01. W_emb[ids] lookup",               (2, 6, 64),      x.shape),
    ("02. mean(x^2, axis=-1, keepdims)",    (2, 6, 1),       rms.shape),
    ("03. (x / rms) * gamma broadcast",     (2, 6, 64),      x_norm.shape),
    ("04. x_norm @ W_q batched matmul",     (2, 6, 64),      q_flat.shape),
    ("05. Q reshape+transpose(0,2,1,3)",    (2, 4, 6, 16),   q.shape),
    ("06. K GQA reshape(B,S,KVH,d_head)",   (2, 6, 2, 16),   k.shape),
    ("07. K repeat_interleave + transpose", (2, 4, 6, 16),   k_rep.shape),
    ("08. einsum('bhid,bhjd->bhij')",       (2, 4, 6, 6),    scores.shape),
    ("09. scores + [1,1,S,S] + [B,1,1,S]",  (2, 4, 6, 6),    masked.shape),
    ("10. einsum('bhij,bhjd->bhid')",       (2, 4, 6, 16),   attn_out.shape),
    ("11. transpose(0,2,1,3)+reshape",      (2, 6, 64),      merged.shape),
    ("12. SwiGLU gate*up intermediate",     (2, 6, 172),     ff_act.shape),
    ("13. ff_act @ W_d down-projection",    (2, 6, 64),      ff_out.shape),
    ("14. LoRA (x @ A) @ B rank-8",         (2, 6, 64),      lora_delta.shape),
    ("15. Sliced LM head [:, -1:, :] @ W",  (2, 1000),       logits_last.shape),
]

print(f"=== A09 KATA: 15 TENSOR SHAPE PREDICTIONS & VERIFICATION (B={B}, S={S}, d={d_model}, H={H}, KVH={KVH}) ===")
print(f"{'Operation':<37} | {'Predicted':<16} | {'Actual':<16} | {'Match'}")
print("-" * 80)
for name, pred, actual in cases:
    assert pred == actual, f"Mismatch on {name}: {pred} != {actual}"
    print(f"{name:<37} | {str(pred):<16} | {str(actual):<16} | OK")

print("\n1. BREAK IT #1: RESHAPE(B, H, S, d_head) WITHOUT TRANSPOSE (Same shape, scrambled memory!)")
q_bug = q_flat.reshape(B, H, S, d_head)  # WRONG: mixes sequence positions into heads!
max_diff = float(np.max(np.abs(q - q_bug)))
print(f"  q.shape={q.shape} vs q_bug.shape={q_bug.shape} -> shapes identical, max_abs_diff = {max_diff:.4f}")

print("\n2. BREAK IT #2: SILENT OUTER-PRODUCT BROADCAST ([B] * [B, 1] instead of [B, 1] * [B, 1])")
loss_per_sample = np.array([1.2, 0.8])          # shape (2,)
sample_weights = np.array([[1.0], [0.5]])       # shape (2, 1)
silent_outer = loss_per_sample * sample_weights # broadcasts to (2, 2) instead of (2,)!
print(f"  (2,) * (2, 1) -> shape {silent_outer.shape}, mean={np.mean(silent_outer):.3f} vs true weighted mean={np.mean(loss_per_sample * sample_weights.squeeze()):.3f}")

print("\n3. BREAK IT #3: LORA CONTRACTION ORDER FLOPS ((x @ A) @ B vs x @ (A @ B))")
flops_factored = 2 * B * S * d_model * r + 2 * B * S * r * d_model
flops_dense = 2 * d_model * r * d_model + 2 * B * S * d_model * d_model
print(f"  Factored (x @ A) @ B : {flops_factored:,} FLOPs")

What to notice

  1. Every single head-level attention operation lives in 4D (B, H, S, *): step 05 splits and transposes queries to (2, 4, 6, 16), step 08 contracts d=16 via einsum('bhid,bhjd->bhij') to (2, 4, 6, 6), step 10 contracts j=6 back to (2, 4, 6, 16), and step 11 transposes and reshapes back to (2, 6, 64).
  2. Identical shape does not mean identical tensor (Break #1): q_flat.reshape(2, 4, 6, 16) has the exact same (2, 4, 6, 16) shape tuple as the properly transposed tensor, yet its elements differ by max_abs_diff = 36.2399 because tokens were chunked across heads.
  3. Right-aligned broadcasting turns mismatched ranks into silent outer products (Break #2): multiplying loss_per_sample of shape (2,) by sample_weights of shape (2, 1) produces a (2, 2) matrix whose mean is 0.750 instead of the true weighted mean 0.800.
  4. Parenthesization changes FLOPs by 6.67x on the exact same algebraic expression (Break #3): (x_norm @ lora_A) @ lora_B costs 24,576 FLOPs via rank r=8, while x_norm @ (lora_A @ lora_B) costs 163,840 FLOPs.

Interview

Say this aloud against the clock. Three levels, about 90 seconds.

1 Outcome 20 sMatrix multiplication, broadcasting, stride permutations, and einsum are the core execution primitives of every neural network. Mastering them lets you trace any 3D or 4D transformer forward pass by hand, eliminate silent data-corruption bugs that pass shape checks, and cut compute by 6x or more through optimal contraction order.
2 Mechanism 45 sBatched matmul contracts the last axis of the left tensor against the second-to-last axis of the right tensor while broadcasting leading batch axes. To split a hidden state of shape (B, S, d_model) into attention heads, we first factor the contiguous feature axis to (B, S, H, d_head) and then transpose axes 1 and 2 to (B, H, S, d_head). Einsum expresses multi-head contractions directly by index letter, such as bhid,bhjd->bhij to contract head width d into (B, H, S, S) attention scores. Elementwise broadcasting right-aligns shape tuples and stretches size-1 axes with stride zero, merging causal mask (1, 1, S, S) and padding mask (B, 1, 1, S) in place.
3 Internals and limits 25 sThree failure modes dominate production code. First, reshaping (B, S, d_model) directly to (B, H, S, d_head) without transposing keeps the target shape but scrambles tokens across heads, yielding a 36.24 max error in our kata. Second, multiplying shapes (B,) and (B, 1) right-aligns to a (B, B) outer product. Third, computing LoRA as x @ (A @ B) instead of (x @ A) @ B costs 163,840 FLOPs vs 24,576 FLOPs, a 6.67x penalty.

Traps

Each one sounds right. Say what is wrong with it before you open it.

"If tensor.shape matches the expected (B, H, S, d_head) tuple at every layer, the tensor transformations are bug-free."
Wrong. Shape metadata only verifies axis lengths, not which physical elements sit at each coordinate. Calling q_flat.reshape(B, H, S, d_head) on a (B, S, d_model) tensor produces the exact (2, 4, 6, 16) shape tuple while slicing sequence positions across heads, producing max_abs_diff = 36.2399 against the true transposed tensor.
"Broadcasting aligns tensor shapes from left to right, just like reading a tuple in Python."
Wrong. Broadcasting always aligns shape tuples from the right (trailing axis first) and prepends 1s on the left of the lower-rank shape. That is why a 1D tensor of shape (64,) broadcasts across the last axis of (2, 6, 64), whereas a 2D tensor of shape (2, 6) becomes (1, 2, 6) and fails against (2, 6, 64) unless you keep the trailing singleton axis (2, 6, 1) via keepdims=True.
"Because matrix multiplication is associative, (X @ A) @ B and X @ (A @ B) have the same runtime cost."
Wrong. Associativity guarantees identical mathematical results (up to floating-point rounding), not identical FLOPs. When A is (64, 8) and B is (8, 64) on input X of shape (2, 6, 64), (X @ A) @ B contracts through the narrow rank-8 bottleneck in 24,576 FLOPs, whereas X @ (A @ B) forms a dense (64, 64) matrix first and takes 163,840 FLOPs (6.67x more work).
"Broadcasting a mask of shape (1, 1, S, S) onto attention scores of shape (B, H, S, S) copies the mask B * H times in GPU memory before adding."
Wrong. Broadcasting stretches singleton dimensions by setting their physical memory stride to 0 in the kernel iterator. The fused elementwise addition reads the same (1, 1, S, S) mask elements across all batches and heads without allocating a duplicated (B, H, S, S) mask buffer.

Walk through the exact tensor shapes from token IDs (B=2, S=6) to multi-head attention output (2, 6, 64) when d_model=64, H=4, KVH=2, d_head=16.
1) Embedding lookup W_emb[ids] maps (2, 6) with (1000, 64) to (2, 6, 64). 2) RMSNorm computes rms of shape (2, 6, 1) via keepdims=True, divides (2, 6, 64) / (2, 6, 1), and scales by gamma of shape (64,) to stay (2, 6, 64). 3) x_norm @ W_q gives (2, 6, 64), reshaped to (2, 6, 4, 16) and transposed via (0, 2, 1, 3) to q of shape (2, 4, 6, 16). 4) x_norm @ W_k gives (2, 6, 32), reshaped to (2, 6, 2, 16), repeated by H // KVH = 2 along axis 2, and transposed to (2, 4, 6, 16). 5) einsum("bhid,bhjd->bhij", q, k_rep) contracts d=16 to (2, 4, 6, 6), adds masks (1, 1, 6, 6) and (2, 1, 1, 6), contracts against values via bhij,bhjd->bhid to (2, 4, 6, 16), and transposes (0, 2, 1, 3) plus reshapes back to (2, 6, 64).
Follow-upWhat is the shape of W_k in this GQA layer, and how many parameters does it save compared to standard MHA? It has shape (64, 32) instead of (64, 64), cutting K (and V) projection parameters by 50% (2,048 vs 4,096 weights each).
State the two rules of NumPy and PyTorch broadcasting and trace what happens when you add tensors of shape (2, 4, 6, 6), (1, 1, 6, 6), and (2, 1, 1, 6).
Rule 1 (Right-alignment): align shape tuples on their trailing axis and prepend 1s to the left of any shorter shape tuple until ranks match. Rule 2 (Axis compatibility): at each axis position, dimensions must either be equal or one of them must be 1; size-1 axes stretch with stride 0 to the maximum size along that axis. For (2, 4, 6, 6), (1, 1, 6, 6), and (2, 1, 1, 6), all three are already rank 4, and the axis-wise maxima are (max(2,1,2), max(4,1,1), max(6,6,1), max(6,6,6)) = (2, 4, 6, 6).
Follow-upWhat happens if someone passes a padding mask of shape (2, 6) without unsqueezing it first? Right-alignment pads (2, 6) on the left to (1, 1, 2, 6), which collides with axis 2 of (2, 4, 6, 6) because 2 != 6, raising a broadcast error (or even worse, if B == S, silently broadcasting batch items across query token rows!).
Why does multiplying a 1D loss vector of shape (B,) by a 2D weight vector of shape (B, 1) silently corrupt training gradients?
Right-alignment pads (B,) on the left to (1, B). When multiplied by (B, 1), axis 0 stretches from 1 to B and axis 1 stretches from 1 to B, producing a (B, B) outer-product matrix where every sample's loss is multiplied by every other sample's weight. Calling .mean() on that (B, B) matrix collapses it to a scalar without raising an error; in the kata, [1.2, 0.8] * [[1.0], [0.5]] yields a mean of 0.750 instead of the true weighted mean 0.800.
Explain in terms of physical memory strides why q_flat.reshape(B, H, S, d_head) fails when q_flat has shape (B, S, d_model).
In row-major memory, q_flat of shape (2, 6, 64) stores all 64 features of token 0 first (offsets 0..63), then all 64 features of token 1 (offsets 64..127), and so on. Reshaping never moves bytes; it just assigns new strides for the target shape. Reshaping directly to (2, 4, 6, 16) assigns head stride 6 * 16 = 96, so head 0 reads offsets 0..95 (all 4 heads of token 0 plus the first 2 heads of token 1!). Reshaping first to (2, 6, 4, 16) assigns head stride 16 within each token, and transpose(0, 2, 1, 3) swaps the token stride (64) and head stride (16) so each head steps by 64 across tokens.
Follow-upWhat are the exact element strides of q after q_flat.reshape(2, 6, 4, 16).transpose(0, 2, 1, 3)? Before transpose, strides of (2, 6, 4, 16) are (384, 64, 16, 1); swapping axes 1 and 2 gives strides (384, 16, 64, 1).
How do you read an einsum string like "bhid,bhjd->bhij", and what is the rule for which indices get summed over?
Each distinct letter represents one axis of the input tensors: here b=batch, h=head, i=query sequence index, j=key sequence index, and d=head dimension. Any letter that appears on the left of -> in multiple inputs is multiplied elementwise, and any letter that does NOT appear on the right of -> is summed over (contracted). Because d is absent from bhij, d is summed out, leaving a 4D output ordered as (b, h, i, j).
Follow-upWrite the einsum string that computes the trace of each (S, S) attention matrix inside a 4D score tensor of shape (B, H, S, S), returning shape (B, H). "bhii->bh": repeating i on the last two axes selects the diagonal, and omitting i from the right side sums over that diagonal.
Derive the FLOP counts for factored LoRA (x @ A) @ B versus unfactored LoRA x @ (A @ B) for x of shape (B, S, d), A of shape (d, r), and B of shape (r, d).
Treat x as (B*S, d). In factored order, u = x @ A multiplies (B*S, d) @ (d, r) in 2*B*S*d*r FLOPs, and u @ B multiplies (B*S, r) @ (r, d) in another 2*B*S*r*d FLOPs, totaling 4*B*S*d*r FLOPs (24,576 in the kata). In unfactored order, W_delta = A @ B multiplies (d, r) @ (r, d) in 2*d^2*r FLOPs (65,536), and x @ W_delta multiplies (B*S, d) @ (d, d) in 2*B*S*d^2 FLOPs (98,304), totaling 163,840 FLOPs.
Follow-upWhen IS it faster to compute A @ B explicitly? Only when the adapter is static across all requests and you pre-merge W_merged = W_base + A @ B once at model load time, paying 2*d^2*r FLOPs once offline and 0 extra LoRA FLOPs at inference.
In a SwiGLU MLP block, why does the intermediate activation have shape (B, S, d_ff) = (2, 6, 172), and how many matmuls does the full SwiGLU block execute?
SwiGLU replaces a single up-projection with two parallel projections from d_model=64 to d_ff=172: a gate projection x @ W_gate and an up projection x @ W_up, both of shape (2, 6, 172). They are combined via elementwise multiplication silu(x @ W_gate) * (x @ W_up) (retaining shape (2, 6, 172)), and then contracted back to (2, 6, 64) by a third matmul with W_down of shape (172, 64).
At what sequence length S does multi-head attention matmul compute (QK^T and PV) exceed a single linear projection x @ W of shape (d_model, d_model)?
Across all H heads, QK^T takes 2 * B * H * S^2 * d_head = 2 * B * S^2 * d_model FLOPs, and PV takes another 2 * B * S^2 * d_model FLOPs, for a total of 4 * B * S^2 * d_model FLOPs. A single (B, S, d_model) @ (d_model, d_model) projection takes 2 * B * S * d_model^2 FLOPs. Setting 4 * B * S^2 * d_model > 2 * B * S * d_model^2 simplifies to 2 * S > d_model (or S > d_model / 2; compared against all four Q, K, V, O linear projections totaling 8 * B * S * d_model^2, attention matmuls overtake when S > 2 * d_model).
Why does slicing x_norm[:, -1:, :] with a slice -1: instead of an integer index -1 before multiplying by W_lm simplify downstream code?
Using the slice -1: preserves the 3D tensor rank (B, 1, d_model) = (2, 1, 64) so multiplying by W_lm of shape (64, 1000) yields (2, 1, 1000), matching the 3D rank expected by unified prefill/decode loss or sampling wrappers before indexing [:, 0, :] to get (2, 1000). Either way, slicing before the matmul cuts compute by a factor of S = 6 (256,000 FLOPs instead of 1,536,000 FLOPs).
How do you express batched matrix multiplication of two 3D tensors A of shape (B, M, K) and B of shape (B, K, N) versus broadcasting a 2D weight matrix W of shape (K, N) across A using einsum?
For two 3D tensors sharing batch axis b, write einsum("bmk,bkn->bmn", A, B). For a 3D activation tensor A of shape (B, S, K) and a 2D weight matrix W of shape (K, N), write einsum("bsk,kn->bsn", A, W); omitting b and s from the second operand tells einsum to broadcast W across both leading axes while contracting k.

Mixed review

Three questions from earlier topics. Nobody tells you the topic in an interview.

A08: Why do transformer attention scores divide the dot product q . k by sqrt(d_head) before applying softmax?
If q and k have independent components with mean 0 and variance 1, their dot product over d_head dimensions has mean 0 and variance d_head (standard deviation sqrt(d_head)). Dividing by sqrt(d_head) restores unit variance so large dot products do not push softmax into flat saturation regions with vanishing gradients.
K04: During autoregressive decoding of one new token at sequence position S, what changes in the Q, K, and V tensor shapes compared to the prefill pass?
During prefill, Q, K, and V all have sequence length S (shape (B, H, S, d_head)), making QK^T an (S, S) matrix-matrix multiply. During decode of one token, Q has sequence length 1 (shape (B, H, 1, d_head)) while K and V are read from the KV cache with length S (shape (B, H, S, d_head)), turning attention into a memory-bandwidth-bound matrix-vector multiply producing scores of shape (B, H, 1, S).
A08: What is the difference between the L2 norm and cosine similarity of two embedding vectors, and when does dot product equal cosine similarity?
The L2 norm ||x||_2 = sqrt(sum(x_i^2)) measures a single vector's Euclidean magnitude, whereas cosine similarity (x . y) / (||x||_2 ||y||_2) measures the angle between two vectors invariant to scale. Dot product equals cosine similarity when both vectors are L2-normalized to unit length (||x||_2 = ||y||_2 = 1).

Short notes

Quick-memorization cheat sheet covering every subtopic on this page and the key facts to remember cold.

All subtopics on this page

  • Matrices & batched matmul: Contracts the last axis of the left operand with the second-to-last axis of the right operand (..., M, K) @ (..., K, N) -> (..., M, N) in 2*M*K*N FLOPs per batch item while broadcasting leading batch axes.
  • Tensor shapes & physical strides: A tensor is a 1D memory buffer plus shape and strides; splitting (B, S, d_model) into heads requires reshape(B, S, H, d_head).transpose(0, 2, 1, 3) because direct reshape(B, H, S, d_head) slices tokens across heads (max_abs_diff = 36.2399).
  • Broadcasting & keepdims: Shapes align on the right and prepend 1s on the left; size-1 axes stretch with stride 0, so (2,4,6,6) + (1,1,6,6) + (2,1,1,6) -> (2,4,6,6), whereas (2,) * (2,1) silently creates a (2,2) outer product (mean 0.750 vs 0.800).
  • Einsum grammar: In "bhid,bhjd->bhij", letters omitted after -> (d) are summed over, letters shared on both sides (b, h) act as batch dimensions, and the RHS order sets the output permutation without separate transpose calls.
  • Contraction order & slicing: Factored LoRA (x @ A) @ B costs 4*B*S*d*r = 24,576 FLOPs vs 163,840 FLOPs for unfactored x @ (A @ B) (6.67x penalty), and slicing x[:, -1:, :] @ W_lm outputs (2, 1000) logits at 1/S the cost.
Important things to remember
  • Memory hook (R-T-E-B-F): Right-align broadcasts, Transpose before/after head reshape, Einsum sums indices absent from RHS, Batched matmul contracts (..., M, K) @ (..., K, N), Factor low-rank chains as (x @ A) @ B.
  • Core FLOP formulas: Linear projection = 2*B*S*d_in*d_out; Multi-head attention (QK^T + PV) = 4*B*S^2*d_model; Factored LoRA = 4*B*S*d_model*r.
  • Three silent bugs to check first in debugging: (1) reshape(B, H, S, d_head) without transpose, (2) (B,) * (B, 1) -> (B, B) outer product in loss computation, (3) missing .contiguous() before .view() after transpose.
