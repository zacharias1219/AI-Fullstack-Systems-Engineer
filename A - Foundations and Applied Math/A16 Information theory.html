Information theory

How do entropy, cross-entropy, KL divergence, and perplexity turn probability distributions into LLM training losses, RLHF penalties, and evaluation metrics? This page covers the five-step information ladder used in pretraining and alignment; parameter estimation lives in A14 and sampling mechanics in D11.

Before you read

Guess first. A wrong guess now makes the right answer stick later.

An overconfident model assigns 0.95 to the top token (true probability 0.70) and starves the other three tokens to 0.03, 0.015, and 0.005. Is forward KL(P||Q) equal to reverse KL(Q||P)?
No. KL divergence is asymmetric. In our kata run, forward KL(P||Q) is 0.4722 bits while reverse KL(Q||P) is 0.2902 bits (1.63x smaller). Forward KL weights errors by true P, so starving the 0.20 and 0.08 tail tokens incurs a steep penalty; reverse KL weights by Q, which places 0.95 mass where P and Q are close.
If you compute a language model's cross-entropy in natural logs (0.5119 nats) instead of base-2 logs (0.7386 bits), does its perplexity change?
No. Perplexity is base-invariant as long as you exponentiate with the matching base: 2^0.7386 = 1.6685 and e^0.5119 = 1.6685. Changing log base rescales cross-entropy by ln(2) = 0.6931, which cancels out upon exponentiation.
An unsmoothed bigram model scores a 7-transition test sentence where 6 bigrams are common and just 1 bigram was never seen in training. What happens to the sentence's perplexity?
It explodes to infinity. A single zero-probability event has surprisal -log(0) = infinity, which makes the average cross-entropy infinite and perplexity infinite regardless of how well the model predicted the other 6 tokens.

The core idea

Information theory measures uncertainty and mismatch in a single currency: the average number of bits needed to encode outcomes from a probability distribution. A rare event carries high surprisal because seeing it rules out many alternatives; a certain event carries zero surprisal because you already knew it would happen.

Every LLM training objective and evaluation metric sits on one five-rung ladder built from that single idea. Average surprisal under the true distribution P gives the irreducible floor, entropy H(P). Encoding outcomes from P using your model's predicted distribution Q costs cross-entropy H(P, Q). The extra bits you waste by using Q instead of P is KL divergence D_KL(P||Q). Exponentiating cross-entropy turns average bits back into perplexity, the effective number of equally likely tokens the model is choosing between at each step.

Memory hook

Walk the five rungs as S-E-C-K-P: Single event (-log p), Expected under P (H(P) floor), Coded with wrong Q (H(P,Q) loss), KL is the gap (H(P,Q) - H(P)), Perplexity un-logs it back to a count (b^H).

How it works

Surprisal and Shannon entropy H(P)

Why must information content use a logarithm? Two independent events x and y occur together with probability p(x)p(y), yet their information must add: I(x, y) = I(x) + I(y). The only continuous function that turns products into sums is the logarithm, with a minus sign so lower probability means higher surprise: I(x) = -log p(x). Base-2 logs measure bits (yes/no questions); natural logs measure nats, where 1 nat = 1 / ln(2) = 1.4427 bits.

Shannon entropy H(P) is the expected surprisal of a draw from P. For a vocabulary of size V, entropy is minimized at 0 when one token has probability 1, and maximized at log2(V) when all V tokens are uniform. That uniform bound is why a 50,257-token vocabulary has maximum entropy log2(50257) = 15.62 bits.

I(x) = -log_b p(x)
H(P) = -sum_x P(x) log_b P(x)   with 0 * log(0) = 0

Cross-entropy H(P, Q) and why LLMs minimize it

In machine learning, you never know the exact data distribution P; you only observe samples drawn from P and train a model Q to predict them. Cross-entropy H(P, Q) measures the average code length when true events come from P but you assign probabilities using Q. When the training label for the next token is a one-hot vector (probability 1 on the true token y*, 0 on all others), the sum collapses to a single term: -log Q(y*).

That single-term collapse is why PyTorch's nn.CrossEntropyLoss is identical to negative log-likelihood (NLL) over the softmax outputs. Minimizing average cross-entropy across a corpus is mathematically equivalent to maximum likelihood estimation (covered in A14).

H(P, Q) = -sum_x P(x) log_b Q(x)
One-hot target y*:  H(P, Q) = -log Q(y*)
Check: Why does a one-hot training label turn cross-entropy into negative log-likelihood?
Because P(y*) = 1 and P(x) = 0 for every other token, so every term in -sum P(x) log Q(x) vanishes except -log Q(y*), which is the negative log-likelihood of the observed token.

KL divergence: the excess-bits tax

Subtracting entropy H(P) from cross-entropy H(P, Q) yields the Kullback-Leibler (KL) divergence D_KL(P||Q). Algebraically, H(P, Q) - H(P) = sum P(x) log(P(x) / Q(x)). By Gibbs' inequality (which follows from Jensen's inequality on the concave log function), D_KL(P||Q) is always greater than or equal to 0, and equals 0 if and only if P and Q are identical everywhere P has mass.

Notice what this implies for gradient descent: H(P) depends only on the true data distribution, not on model weights. Its gradient with respect to model parameters is zero. Therefore, minimizing cross-entropy H(P, Q) during LLM pretraining produces the exact same gradients as minimizing forward KL divergence D_KL(P||Q).

H(P, Q) = H(P) + D_KL(P || Q)
D_KL(P || Q) = sum_x P(x) log_b (P(x) / Q(x)) >= 0

Forward KL (mean-seeking) vs Reverse KL (mode-seeking)

Because the expectation weights by the first argument, swapping P and Q changes which errors are catastrophic. In forward KL, D_KL(P||Q), the weight is P(x). Whenever true data exists (P(x) > 0) and the model assigns near-zero probability (Q(x) -> 0), the ratio P(x)/Q(x) explodes to infinity. To avoid infinite loss, Q stretches across every mode of P, producing mean-seeking (mass-covering) behavior. Pretraining and supervised distillation use forward KL.

In reverse KL, D_KL(Q||P), the weight is Q(x). If Q puts zero mass on a mode of P, that term contributes 0 * log(0) = 0 with zero penalty. Instead, Q is heavily penalized if it puts mass where P is near zero. As a result, reverse KL pushes Q to lock onto a single high-probability mode (mode-seeking / zero-forcing). RLHF (PPO in E07, DPO in E09) penalizes reverse KL from the learned policy back to the reference model to prevent reward hacking without forcing the policy to hedge across low-reward modes.

Check: If you train a model with forward KL on a bimodal target distribution, why can it generate invalid "in-between" outputs?
Forward KL penalizes Q=0 wherever P>0, forcing a capacity-limited Q to stretch across both modes and place probability mass in the low-density valley between them.

Perplexity: effective branching factor and tokenizer traps

Perplexity (PPL) turns average cross-entropy back into an intuitive count by exponentiating with the log's base: PPL = 2^(H_bits) = e^(H_nats). Expanding the average reveals it is the geometric mean of the inverse token probabilities across a sequence of length N. A perplexity of 4.0 means the model is, on average, as uncertain as rolling a fair 4-sided die at every token.

Perplexity has one notorious interview and production trap: it is only comparable between models that share the exact same vocabulary and tokenizer. A 128k-token model packs more characters into each token than a 32k-token model, so each token prediction is harder and per-token PPL looks higher even if the model compresses text better. To compare across tokenizers, normalize total negative log-likelihood in bits by raw UTF-8 byte length: bits-per-byte (BPB) = total_bits / total_bytes.

PPL = 2^(H_bits) = exp(H_nats) = (prod_{i=1..N} 1 / Q(x_i))^(1/N)
BPB = (sum_{i=1..N} -log2 Q(x_i)) / num_utf8_bytes

Smoothing, zero probabilities, and calibration

In count-based n-gram models, any bigram absent from the training corpus gets MLE probability 0. One unseen bigram sends -log(0) to infinity and crashes evaluation perplexity. Add-k smoothing adds k pseudocounts to every vocabulary token: P_k(w2 | w1) = (count(w1, w2) + k) / (count(w1) + kV). Choosing k is a sharp bias-variance tradeoff: too small leaves rare events noisy; too large (like add-1 Laplace smoothing on a small corpus) steals massive probability mass from frequent bigrams and inflates in-domain perplexity.

Neural LLMs avoid exact zeros because softmax outputs are strictly positive (exp(z) > 0), yet floating-point underflow or overconfident logits still cause exploding cross-entropy on outliers. Techniques like label smoothing (replacing 1.0 with 1 - eps) and temperature scaling calibrate Q so tail events are not starved.

Check: Why does bits-per-byte (BPB) solve the cross-tokenizer perplexity comparison problem?
Because the denominator is raw UTF-8 bytes of the text, which is identical regardless of how each tokenizer slices the text into tokens, making total compression cost directly comparable.

Kata: Perplexity of a tiny bigram model by hand

Computes entropy, cross-entropy, forward vs reverse KL divergence on a 4-token distribution, then builds a bigram language model from scratch to measure per-token surprisal, base-invariance, and add-k smoothing.

kata.py

import math
from collections import Counter

# --- Break-it flags ---
UNSEEN_TEST = False   # 1) Set True to score unseen bigrams with k=0 -> inf perplexity
ADD_K = 0.1           # 2) Try 0.0, 0.1, 1.0, 5.0 to see smoothing vs sharpness
SWAP_PQ = False       # 3) Set True to swap P and Q in KL divergence

def entropy_bits(p):
    return -sum(x * math.log2(x) for x in p if x > 0)

def cross_entropy_bits(p, q):
    return -sum(px * math.log2(qx) for px, qx in zip(p, q) if px > 0)

def kl_bits(p, q):
    return sum(px * math.log2(px / qx) for px, qx in zip(p, q) if px > 0)

# Part 1: Entropy, Cross-Entropy, and KL Asymmetry on a 4-token distribution
P = [0.70, 0.20, 0.08, 0.02]
models = {
    "Good Q":        [0.65, 0.22, 0.10, 0.03],
    "Overconf Q":    [0.95, 0.03, 0.015, 0.005],
    "Uniform Q":     [0.25, 0.25, 0.25, 0.25],
}

h_p = entropy_bits(P)
print(f"=== Part 1: Discrete Distribution (H(P) = {h_p:.4f} bits, PPL_min = {2**h_p:.2f}) ===")
print(f"{'Model':<14} {'H(P,Q) bits':>11} {'KL(P||Q)':>10} {'KL(Q||P)':>10} {'PPL':>8}")
for name, Q in models.items():
    a, b = (Q, P) if SWAP_PQ else (P, Q)
    ce = cross_entropy_bits(P, Q)
    fwd = kl_bits(a, b)
    rev = kl_bits(b, a)
    print(f"{name:<14} {ce:11.4f} {fwd:10.4f} {rev:10.4f} {2**ce:8.2f}")
print(f"Identity check (Good Q): H(P)+KL = {h_p + kl_bits(P, models['Good Q']):.4f} == H(P,Q) = {cross_entropy_bits(P, models['Good Q']):.4f}")

# Part 2: Tiny Bigram Language Model by Hand
corpus = (
    "<s> the cat sat on the mat </s> "
    "<s> the dog sat on the rug </s> "
    "<s> the cat chased the dog </s>"
).split()
vocab = sorted(set(corpus))
V = len(vocab)
unigrams = Counter(corpus)
bigrams = Counter(zip(corpus, corpus[1:]))

def eval_bigram(tokens, k):
    bits_list, nats_list = [], []
    for w1, w2 in zip(tokens, tokens[1:]):
        prob = (bigrams[(w1, w2)] + k) / (unigrams[w1] + k * V)
        if prob == 0.0:
            return float("inf"), float("inf"), float("inf"), []
        bits_list.append(-math.log2(prob) + 0.0)
        nats_list.append(-math.log(prob) + 0.0)
    h_b = sum(bits_list) / len(bits_list)
    h_n = sum(nats_list) / len(nats_list)
    return h_b, h_n, 2 ** h_b, list(zip(tokens, tokens[1:], bits_list))

seen_sent = "<s> the cat sat on the rug </s>".split()
unseen_sent = "<s> the dog chased the mat </s>".split()

print(f"\n=== Part 2: Tiny Bigram LM (V={V} tokens, N={len(seen_sent)-1} transitions) ===")
h_b0, h_n0, ppl0, details = eval_bigram(seen_sent, 0.0)
print("Per-bigram surprisal on seen test (k=0.0):")
for w1, w2, s in details:
    print(f"  P({w2:<4} | {w1:<4}) = {2**(-s):.4f}  surprisal = {s:.4f} bits")
print(f"Check: 2^H_bits = {2**h_b0:.4f} == e^H_nats = {math.exp(h_n0):.4f}")

print("\nSmoothing comparison:")
configs = [
    ("Seen (k=0.0)",   seen_sent,   0.0),
    (f"Seen (k={ADD_K})", seen_sent,   ADD_K),
    ("Seen (k=1.0)",   seen_sent,   1.0),
    (f"Unseen (k={ADD_K})", unseen_sent, ADD_K),
    ("Unseen (k=1.0)", unseen_sent, 1.0),
]
if UNSEEN_TEST:
    configs.insert(3, ("Unseen (k=0.0)", unseen_sent, 0.0))
for label, sent, k in configs:
    hb, hn, ppl, _ = eval_bigram(sent, k)
    print(f"  {label:<16} H={hb:6.4f} bits ({hn:6.4f} nats)  PPL={ppl:6.2f}")

Entropy sets the irreducible uncertainty floor of data, cross-entropy is the loss we minimize during training, KL divergence measures how far two distributions drift apart, and perplexity turns loss into an intuitive branching factor.

Traps

Each one sounds right. Say what is wrong with it before you open it.

"KL divergence is a distance metric between two probability distributions."
Wrong. A metric must be symmetric and obey the triangle inequality. KL fails both: D_KL(P||Q) != D_KL(Q||P). In our kata, Overconf Q had forward KL 0.4722 bits vs reverse KL 0.2902 bits.
"If Model A has perplexity 8 and Model B has perplexity 12 on the same text, Model A is strictly better."
Wrong unless both models use the exact same tokenizer and vocabulary. A coarser tokenizer predicts more bytes per token, so per-token perplexity can be higher even when its bits-per-byte compression is better.
"Minimizing cross-entropy loss during LLM pretraining is different from minimizing KL divergence to the data distribution."
Wrong. H(P, Q) = H(P) + D_KL(P||Q), and H(P) is constant with respect to model parameters. Their gradients with respect to weights are identical.
"Computing perplexity from natural-log loss (nats) gives a different value than computing it from base-2 loss (bits)."
Wrong. Perplexity is base-invariant when exponentiated with the matching base: 2^(H_bits) = e^(H_nats). In our kata, 2^0.7386 = e^0.5119 = 1.6685.

Question bank

Answer aloud, then open. Grade yourself honestly.

Derive H(P, Q) = H(P) + D_KL(P||Q) and explain why pretraining only needs H(P, Q).
Write D_KL(P||Q) = sum P log(P/Q) = sum P log P - sum P log Q = -H(P) + H(P, Q), so H(P, Q) = H(P) + D_KL(P||Q). Because H(P) is fixed by the data and has zero gradient with respect to Q's parameters, minimizing H(P, Q) minimizes D_KL(P||Q).
Follow-upCan cross-entropy ever be lower than H(P)? No, because Gibbs' inequality guarantees D_KL(P||Q) >= 0.
Why does forward KL cause mean-seeking behavior while reverse KL causes mode-seeking behavior?
Forward KL weights log(P/Q) by P, so Q -> 0 where P > 0 causes infinite loss, forcing Q to cover all modes. Reverse KL weights log(Q/P) by Q, so Q can set mass to 0 on extra modes for free and concentrate on one high-density mode.
Follow-upWhich direction is used in RLHF (PPO/DPO) to penalize drift from the reference model? Reverse KL, D_KL(policy || ref), so the policy stays inside the reference model's high-probability support.
What does a perplexity of 10 mean intuitively, and what is the perplexity of a uniform model over a 50,257-token vocabulary?
Perplexity of 10 means the model's average uncertainty per token equals choosing uniformly among 10 equally likely tokens. A uniform model over 50,257 tokens has entropy log2(50257) = 15.62 bits and perplexity 50,257.
Why does one zero probability on a test token send perplexity to infinity, and how do count models vs neural models prevent it?
One token with Q(x) = 0 gives surprisal -log(0) = infinity, making the mean cross-entropy and its exponential infinite. Count models use smoothing (add-k or Kneser-Ney); neural models use softmax (strictly positive) with fused log-sum-exp for numerical stability.
Follow-upWhy not just use add-1 (Laplace) smoothing everywhere? When k*V is large relative to small counts, it steals too much mass from seen tokens (in our kata, seen PPL jumped from 1.67 to 4.95).
Why can you not compare perplexity between a 32k-vocab model and a 128k-vocab model, and what metric replaces it?
Perplexity is normalized per token, and different tokenizers produce different token counts for the same text. Use bits-per-byte (BPB), which divides total surprisal in bits by the fixed UTF-8 byte count.
Follow-upHow do you convert a model's average nat loss L and token count T on a B-byte text into BPB? BPB = (L * T / ln(2)) / B.
How does PyTorch nn.CrossEntropyLoss relate to Shannon cross-entropy on next-token prediction?
It applies log-softmax to raw logits and takes the negative log probability of the true token ID. Because the target is one-hot (P = 1 on the true token, 0 elsewhere), this equals H(P, Q) = -log Q(y*) in nats.
In RLHF, what breaks if the KL penalty coefficient beta is too small vs too large?
If beta is too small, the policy exploits reward-model blind spots (reward hacking) and loses fluency. If beta is too large, the policy stays frozen near the SFT reference model and fails to improve on the reward.
Follow-upWhat metric should you graph alongside reward during RLHF training? Per-token KL(policy || ref) and output entropy to spot reward hacking or mode collapse early.
A language model has a validation cross-entropy loss of 2.0 nats. What is its loss in bits and its perplexity?
In bits: 2.0 / ln(2) = 2.0 * 1.4427 = 2.8854 bits. Perplexity: e^2.0 = 7.39 (which also equals 2^2.8854 = 7.39).
Why did add-1 smoothing raise seen-sentence perplexity from 1.67 to 4.95 in the kata while keeping unseen perplexity finite?
With V = 10, add-1 adds k*V = 10 to denominators that were only 1 to 6, flattening sharp seen bigrams toward uniform while giving unseen bigrams non-zero mass.
Why can a classifier have 90% accuracy yet terrible cross-entropy loss?
Accuracy only checks the argmax, whereas cross-entropy penalizes confidence logarithmically. Assigning 0.999 to the wrong class (0.001 to the true class) costs -log2(0.001) = 9.97 bits on a single mistake.

Mixed review

Three questions from earlier topics. Nobody tells you the topic in an interview.

D01: Why can a decoder-only LLM process all prompt tokens in parallel during prefill, but must generate output tokens sequentially during decode?
During prefill, all prompt tokens are known upfront, so causal attention runs as one batched matrix multiplication. During decode, token t+1 cannot be computed until token t is sampled, making generation strictly sequential.
D11: How does lowering softmax temperature T below 1.0 change the next-token probability distribution and its entropy?
Dividing logits by T < 1 magnifies logit gaps, concentrating probability mass on the top tokens and lowering the distribution's Shannon entropy (approaching greedy argmax as T -> 0).
A08: Why does the final LM head projection (B, T, d) x (d, V) become a major memory and compute bottleneck when vocabulary size V grows from 32k to 128k?
Both FLOPs (2 B T d V) and the materialized logits tensor (B * T * V elements) scale linearly with V, quadrupling peak logit memory during cross-entropy loss computation unless chunked.

Short notes

Quick-memorization cheat sheet covering every subtopic on this page and the key facts to remember cold.

All subtopics on this page

  • Surprisal I(x): -log_b p(x); turns products of independent probabilities into additive costs; p=1 gives 0 bits, p=0.5 gives 1 bit, p=0 gives infinity.
  • Shannon entropy H(P): Expected surprisal -sum P(x) log P(x); irreducible uncertainty floor; peaks at log2(V) bits for a uniform vocabulary of size V.
  • Cross-entropy H(P, Q): Expected bits using model Q for true outcomes P: -sum P(x) log Q(x); collapses to -log Q(y*) (NLL) for one-hot LLM labels.
  • KL divergence D_KL(P||Q): Excess bits wasted by Q: H(P, Q) - H(P) = sum P log(P/Q) >= 0; asymmetric (forward KL is mass-covering for pretraining, reverse KL is mode-seeking for RLHF).
  • Perplexity and BPB: PPL = 2^(H_bits) = e^(H_nats) (effective branching factor, uniform gives PPL = V); base-invariant, but use bits-per-byte (total_bits / bytes) across different tokenizers.
  • Smoothing and calibration: Any Q(x) = 0 on a true token yields infinite PPL; add-k smoothing (c+k)/(N+kV) prevents zeros at the cost of stealing mass from seen events, while neural models use softmax + label smoothing or temperature scaling.
Important things to remember
  • Core identity: H(P, Q) = H(P) + D_KL(P||Q); since H(P) is constant in model weights, minimizing cross-entropy equals minimizing forward KL.
  • Unit conversion: 1 nat = 1 / ln(2) = 1.4427 bits; perplexity is identical in both bases (2^H_bits == e^H_nats).
  • KL is not a metric: Asymmetric and fails triangle inequality; forward KL covers modes (pretraining), reverse KL locks onto one mode (RLHF/PPO/DPO).
  • Tokenizer rule: Never compare raw perplexity across different vocabularies; always convert to bits-per-byte (BPB).
  • Zero-prob rule: One unseen zero-probability token sends cross-entropy and perplexity to infinity.
